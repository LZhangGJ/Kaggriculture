# Fusion Champion V1

目标：以已通过官方 1.32.7 逐步一致性验收的本地完整 Agent 为对手池，开发一个规则为主、必要时由 LGBM 辅助分支选择的独立 Agent。

最终硬门不是平均胜率，而是：

```text
对冻结池中每一个 Agent 的双方换座得分率均 >= 90%
```

## 开发纪律

1. K320 是第一版基座，不把对手身份作为在线特征。
2. 只能使用比赛时可见的当前及历史公开状态进行条件判断。
3. 每项规则必须对应明确败局机制，并单独消融；无收益或伤害强对局时回滚。
4. 先做规则；只有可解释规则在独立事件库确认进入平台期后，才允许加入 LGBM。
5. LGBM 只能选择长期路线或局部计划修改，不能绕过合法动作执行器。
6. 调参集、验证集和最终验收集使用互不重叠的事件种子，并且全部双方换座。
7. 旧的 530001--530050 事件只作为历史基线，不再用于新规则选择。
8. 最终候选必须经过官方 Python 1.32.7 复验、JAX 一致性验收和线上 CPU 性能验收。

## 评测漏斗

```text
16 个事件种子方向筛选
-> 64 个独立种子规则消融
-> 256 个独立种子逐对手验证
-> 512 个最终冻结种子全池验收
-> 官方 Python 双座位抽样复验
```

任何阶段都同时报告：逐对手得分率、最低得分率、平均分差、双方座位结果、硬错误和吞吐。总体平均成绩不能掩盖单个弱点。

## 允许的融合方式

- 提取其他 Agent 的可迁移能力，例如投资规模、市场事务顺序、销售时机、现金缓冲和终局清算。
- 根据公开盘面识别经营压力和市场状态，再选择能力或局部修改。
- 禁止按作者名、Replay ID、隐藏库存或未来动作识别对手。
- 冻结专用 Agent 继续留在对手池，不允许被正式 Agent 直接 import 或调用。
