# Fusion Champion 开发经过与当前进度

日期：2026-08-21
目标：规则为主；只有规则无法继续提升时才用无未来泄漏的 LGBM；最终对冻结 28-Agent 池中的每个对手都达到至少 90%。

## 1. 起点：28-Agent 严格 Arena

Arena 使用 28 个已通过官方 1.32.7/JAX 一致性验收的完整 Agent。378 组各打 100 局，共 37,800 局。K320 排名第一、总得分率 86.7%，但逐对手 90% 门只通过 14/27，最严重短板是 Rank14（24%）。

这证明“选一个现成最强 Agent”不够；即使允许事后从现有路线中神谕选择，Rank14、PRT、Rank12 等对手仍需要新能力。

## 2. FC1：解决 Rank14 重羊压力

### 失败尝试

看到对手重羊后只把 K320 的牛羊数量改成 6 牛 8 羊，Rank14 得分率反而从 34.4% 降到 27.3%。原因是动物数量必须和现金、人员、作物、出售节奏一起变化，单改表面参数会破坏完整经营链。

### 有效能力

公开盘面在 step 24--95 出现“羊不少、牛少、现金已投入”的形态时，完整切换到 X562 的经营和市场能力。64 个新种子、双方换座中，Rank14 从 25.8% 提升到 81.3%，并同步改善 Soil/Flex/G02/Deniz/Kaito V27。该能力随后继续演化为带 PRT 后缀的压力分支。

## 3. FC2：K320 反镜像能力

通过对 K320 镜像败局的逐步对比，加入仅在公开农场高度接近时启用的提前出售能力。冻结参数为：

```text
horizon=4, clone_distance<=6, quantity_cap=32,
products=STRAWBERRY/MILK/WOOL, start_step=120
```

结果：对 K320 从 50% 提升到 89.84%；对其余 14 个关键对手的 1,792 局只改变 1 局，而且是增加 1 胜。四个独立 K320 事件块合计 403/448 = 89.955%，非常接近但不能冒充通过 90%。

进一步把“近镜像”收紧为公开农场完全相同、异构局使用较宽的四步 hedge，形成 FC2B 的 clone-aware 版本。

## 4. 当前最强关键六对手面板

FC2B（Rank14 压力分支 + K320 clone-aware preempt）在固定 seed `544501..544564`、每个对手 128 局的结果：

| 对手 | 胜-负 | 得分率 |
|---|---:|---:|
| Rank14 | 116-12 | 90.625% |
| G04 Soil Rain | 115-13 | 89.844% |
| Flex V59 | 115-13 | 89.844% |

结论：当前候选已经消除了最初 24% 的最大短板，但仍没有达到最终逐对手 90% 门。主要困难已转为 PRT、Rank12、近镜像 K320，以及 G04/Flex 各差一胜。

## 5. 已经反证并回滚的方向

| 方向 | 证据 | 结论 |
|---|---|---|
| 只改牛羊数量 | FC1A、animal substitution | 破坏完整经营链，退化 |
| 终局清仓顺序 | FC3A | 未改变胜负 |
| 针对 PRT 重羊路线提前卖奶/毛 | FC3J | 107/128 不变，只有极小分差变化 |
| 减羊或羊转牛 | FC3K | 没有稳定改善 |
| 把杂草修复后的动作延迟到下一个空闲槽 | FC3M/FC3N | Rank12 111→108，PRT 107→106，退化 |
| 整条路线在中途切换 | 多组 suffix/override | 事后 Oracle 高，但多数分支单独明显更差，在线选择不稳 |
| 小样本 LGBM 路由 | FC2V/FC3G | 样本不足，不部署 |

这些失败代码和回执继续保留为隔离实验，不并入正式候选。

## 6. Rank12 大样本反事实与 LGBM

为了判断“不是没有好分支，而是在线不会选”，对 Rank12 在 step 120 固定同一真实局面，分别续跑 K320 和五条候选路线：

- 训练：1,024 独立事件种子 × 双座位 = 2,048 个局面；
- holdout A：256 种子 × 双座位 = 512；
- holdout B：256 种子 × 双座位 = 512；
- 训练、A、B 的事件种子完全独立。

结果：

| 数据 | K320 基线 | 保守事后 Oracle |
|---|---:|---:|
| Train | 84.33% | 92.72% |
| Holdout A | 84.77% | 95.70% |
| Holdout B | 84.96% | 95.51% |

因此候选路线确实包含能补救 Rank12 败局的能力，而且 Oracle 在独立事件库稳定超过 90%。

但只使用 step 120 当时可见的 209 个公开特征训练 LGBM，结果只有：

| 评测 | LGBM |
|---|---:|
| Group OOF | 86.57% |
| Holdout A | 86.91% |
| Holdout B | 85.94% |

改用“是否翻转胜负”的直接目标，结果几乎相同。两个模型都主要只学会偶尔切到同一条 two-yarn 分支。这说明问题不是损失函数写错，而是 step 120 的可见状态还不足以判断后续随机市场条件；因此 LGBM 没有进入正式 Agent。

## 7. FC2A CPU Public 卡死与修复

FC2A Public 提交 `55662157` 的低分被定位为确定性工程故障，而非一般策略退化：状态型 PRT 在 step 288 冷启动，漏掉新一天 HIRE，随后 431 帧全 PASS。

修复版 `55663355` 从 step 0 影子运行 PRT，直到真实切换前仍输出原主路线。官方 seed `545102` 双座位中，现金从 13,313 恢复到 70,382，最长全 PASS 从 431 降到 10。详见同目录 FC2A 技术说明。

## 8. 当前暂停点与下一步

用户要求打包时，正在开始下一阶段的市场归因，尚未产生新结论：

1. 对 PRT/Rank12 的胜局和败局逐步记录双方出售商品、数量、价格和先后关系；
2. 判断剩余短板是否来自可观测的抢卖/压价窗口，而不是继续猜动物比例；
3. 若存在稳定机制，只实现“提前 1--4 步、调整订单顺序、分批出售”等局部、可回滚修正；
4. 每个修正先做同种子消融，再用独立事件库和双方换座复验；
5. 通过后刷新困难对手面板，再运行完整 28-Agent 矩阵；
6. 最终还需要官方 Python 抽样逐步一致性和线上 CPU 延迟验收。
