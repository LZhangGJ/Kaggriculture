# W9C：多未来反事实、64 条覆盖与排序器门控

日期：2026-08-29（JST）
结论：**候选能力 PASS；离线反事实 PASS；当前线上排序器 FAIL。**

## 1. 为什么不用单一未来打标签

同一个冻结前缀分别续跑不同官方未来事件后，候选排序会变化。标签半分相关性实测：

| 每候选未来数 | 两半标签相关性 |
|---:|---:|
| 4 | 0.507 |
| 8 | 0.680 |
| 16 | 0.839 |
| 32 | 0.886 |

所以正式覆盖验收使用 32 个共同未来；每个候选在同一状态共享完全相同的未来库。精确第一名仍可能在近似等价候选间互换，因此同时报告 500/1,000 元内近最优覆盖。

## 2. 静止对手：最终稳定验收

16 个状态（8 个独立前缀 × 双座位），每状态 32 个未来：

| 指标 | 旧 64 条 | 最终 64 条 |
|---|---:|---:|
| 精确 oracle recall | 56.25% | **75.00%** |
| 500 元内覆盖 | 68.75% | **81.25%** |
| 1,000 元内覆盖 | 75.00% | **87.50%** |
| 平均 shortlist regret | 475.18 | **281.83** |
| 最大 regret | 2,065.97 | 2,065.97 |
| 完整池相对 KEEP 平均机会增益 | 7,523.86 | **7,800.98** |
| 有正增益状态 | 100% | 100% |
| 终局溢出 | 0 | 0 |

最终一共执行 175,136 个完整续跑，450.79 continuations/s。

凭证：`w9_candidate8_multifuture_passive_prefix2820001_n8x2_future32_day9_final_v2.json`。

## 3. 强对手池：候选有价值，但 64 条启发式排序不足

| 对手 | 状态 × 未来 | 完整池相对 KEEP 平均机会增益 | 64 条精确覆盖 | 1,000 元内覆盖 | 平均 regret | 硬错误 |
|---|---:|---:|---:|---:|---:|---:|
| G001 | 8 × 16 | +6,434.89 | 50% | 50% | 2,023.84 | 0 |
| G017 | 4 × 8 | +13,018.50 | 25% | 25% | 3,010.50 | 0 |
| G231 | 4 × 8 | +17,935.84 | 0% | 25% | 2,524.16 | 0 |

这不是“新增候选没用”。恰好相反：完整池在强对手前缀里有很大的正机会增益；问题是解析价值函数无法在 100–300 多条里稳定挑中正确的多产业组合。

G001 的 8 个 oracle 为 5 个多产业、1 个单边、2 个 KEEP；G231 的 4 个全部是多产业。漏选统计因此明确指向：

> 下一步应学习 `状态 + 对手公开产能 + CandidateDelta → 多未来相对价值`，而不是继续发明更多固定 if 或无限增大某类配额。

对应凭证：

- `w9_candidate8_multifuture_g001_prefix2824001_n4x2_future16_day9_final_v3.json`；
- `w9_candidate8_multifuture_g017_prefix2825001_n2x2_future8_day9_v1.json`；
- `w9_candidate8_multifuture_g231_prefix2825001_n2x2_future8_day9_v1.json`。

## 4. 配对 C++ 对照的正确解释

上述“机会增益”满足严格配对：同一冻结状态、同一座位、同一对手、同一未来事件库，唯一变化是候选。它证明扩充候选空间后存在原 R6/KEEP 没有表达的高价值改进。

但这是离线 oracle 上界，不是可提交 Agent 的实际增益。没有线上选择器时不能把 oracle 结果当成胜率，也不能用未来事件作弊。

当前反事实标签主指标仍是我方终局现金。对真正的竞争选择器，下一版数据必须同时输出并使用：

1. 胜率/平局率；
2. 终局分差；
3. 我方终局现金；
4. 硬失败风险。

在该标签升级前，强对手结果只能证明候选价值潜力，不能完成最终竞技策略验收。

## 5. 当前树排序器为什么不能上线

现有 512 树 ExtraTrees 在稳定 32-future 数据的留出 4 状态上：

- model64 精确 oracle recall：25%；
- 旧 heuristic64：25%；
- model64 平均 regret：1,803.98；
- 旧 heuristic64 平均 regret：783.11；
- 模型反而更差。

根因不是模型参数太小，而是稳定标签只有 16 个状态，且训练主要来自静止对手。状态数远不足以学习多产业组合随对手/市场变化的价值。

凭证：`w9_candidate8_ranker_multifuture_passive_prefix2820001_n8x2_future32_safe_v1.json`。该模型保留为负实验，不部署。

## 6. 速度

| 项目 | 实测 |
|---|---:|
| C++ 完整普通对局 | 469.93 局/s |
| 多未来完整续跑 | 435–545 continuations/s（按对手变化） |
| 877 原始候选生成 | 平均 0.95 ms，P95 1.04 ms |
| 64 条 ExtraTrees 暖推理 | 平均 49.77 ms，P95 57.40 ms |
| 生成 + 推理 P95 | 58.44 ms |

技术上满足单步 1 秒预算。但模型一次加载在本机 WSL/E 盘约 3.78 秒，而且价值门失败；因此“速度合格”不能转化为“允许提交”。

凭证：`w9_candidate8_online_budget_v1.json`。

## 7. 门控结论

- 八类候选生成：PASS；
- C++ 真实执行与硬安全：PASS；
- 多未来离线教师：PASS；
- 静止对手 64 条近最优覆盖：基本 PASS；
- 跨强对手 64 条覆盖：FAIL；
- 当前树排序器：FAIL；
- 进入宏观 Self-play：**暂不允许**。

下一步应先扩大“多对手 × 前中后期 × 32 future”的稳定状态数据，并升级为胜负/分差/现金/失败风险的竞争标签。只有留源对手上 model64 达到预设覆盖、top1 配对增益为正且负增益率受控，才进入宏观 Self-play。
