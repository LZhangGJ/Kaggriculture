# R2 P16：完整作业链与可执行排班校验

**2026-09-11 交接更新：** 本包是最新对比中的“旧版”，并非原始 P16。对团队最新两份真实提交的 25 种子测试为 74/100 胜；增加采购恢复的另一版为 69/100 胜。完整开发过程、相对 P16 的改动原理、不同面板的口径与交付入口见 [仓库 agent.md §12](../../agent.md#r2p16-route-agents)，证据见 [交付记录](../../evidence/r2p16_route_agents_20260911/README_ZH.md)。下文保留此前验证历史；其中工作区路径不属于本包独立运行依赖。

这是在上一版路线经济评估器上修复漏项的独立候选版本。经营方向、作物和动物选择、销售评估及配置参数沿用上一版；修改的是减员和补漏如何证明工作能做完。

## 为什么原来会漏做

旧版先预演一天，认为少雇一人仍可完成原有工作，就删除一条雇工订单。但是，它没有保存预演中找到的完整路线。采购结束后，实际执行器根据当时的市场行情重新给任务排序、重新排班。启发式排班对顺序敏感：有一份完整解，不代表换一种顺序还能找到完整解。于是出现“已减员，实际排班却丢任务”的断层。

之后的补漏又把单个动作当作独立任务。田地还空着时，浇水被判为当前不需要；种植却可以被塞到最后一步。喂食也没有连同需要的领料一起安排。因此，任务清单里记着要浇水、喂食，并不能保证真正执行。

## 改进后的算法

1. **保留找到的完整解。** 少雇人之前，从预演中提取真正执行器生成的路线，逐步模拟验证。检查工人行动顺序、原料、种子、作物状态、收获数量和当天截止时间。收益比较与原有交货、容量、资金检查仍然保留。没有固定路线可证明原有工作完整完成，就不采用减员。
2. **开工时再次核验。** 实际编排若漏掉已承诺的工作，就用真实工人位置、库存和田地状态重建并核验保存的路线。通过后整体恢复这份可行解，避免把排班启发式的一次失败误认为人手不足。
3. **作业链整体补漏。** 从现有任务生成器取出同一地块的完整动作顺序，把已经安排和漏掉的相关动作重新合并。将整组工作在不同工人、不同插入位置上尝试；必要时增加领料。只有整组做完、原有工作与收获量没有减少、时间和资源校验通过，才整体替换路线。放不下时不会只留下前半条链。

这属于带资源和前后依赖约束的局部调度修复，加上可行解保存与模拟校验。不是重新训练模型，也没有加入种子、对手名称或某个地块的比赛特判。

## 使用与复现

Linux / WSL，使用 `g++-13`：

```bash
python3 -B build.py --unit
```

默认生成 `build/revision2/route3.so`，`main.py` 已指向它。构建器拒绝覆盖已有二进制；需要重新构建时使用 `--out` 指定新的输出位置。`policy/config.json` 与原 P16 配置相同。`build/revision2/route3.BUILD.json` 保存编译参数、源文件哈希和测试输出。

主要实现位于 `policy/route_economics.hpp`；保存路线和校验结果的状态位于 `policy/triad.hpp`；新增审计计数由 `policy/search.hpp` 输出。测试包含原有 20 项机制检查和 58 个改变作物、方向、剩余时间、领料需求与市场报价的通用用例。

对战脚本和证据位于工作区 `experiments/r2p16_route_workflow_20260910`。对局继续使用此前已编译、已校准的 C++ 模拟器，加载原始公开对手程序进行实时反馈对战。不是照抄对手动作录像。

## 适用范围

可行性校验覆盖当前观察和当前日内固定路线能确定的工作。实际观察变化后会重新核验；未知的对手交易、未来商店、未来随机事件并不因此变得可知。局部插入搜索没有找到解，也不代表数学上不存在更好的全局排班。

“漏项”统计指已经承诺保留的工作，不包括经济规划器主动决定不做的所有潜在农活。修复漏项也不自动意味着最终现金或胜率提高，需单独看对战结果。

## 首次验证结果（5 个新种子）

原 6 局、12 项已承诺漏做全部补齐，问题日人手和工资相同。78 项机制与通用用例通过。新种子 220 局对照中，旧修改版 / 新版均为 65 胜 45 负、0 已承诺漏项、0 无效工作动作；平均雇工费相同，新版平均现金低 117.43（约 0.12%）。串行最慢轨迹复测峰值 1.104 秒，存在一次超过 1 秒的决策。

详细结果见 `VALIDATION_ZH.md` 和 `VALIDATION.json`。目前定位为完整性修复候选，尚无胜率或收益提升证据。

## 扩大验证结果（30 个新种子）

随后保持二进制固定，将种子扩展到整个 32 位正整数范围的分层抽样：30 个新种子、11 个原始公开对手、两个座位，两版合计 1,320 局；另跑新旧直接对战 60 局。全部使用此前编译并校准的 C++ 对局模拟器。

对手池两版均为 564 胜 96 负，660 组配对没有胜负翻转。新版平均最终现金少 79.57，平均雇工费少 13.22，两项差异按种子计算的 95% 区间都跨过 0。旧版在 8 局中遗漏的 12 项工作被新版补齐，问题日人手、工资和任务集合相同。直接对战新版 16 胜 16 负 28 平；其中一个种子的两个座位，两版都因采购现金不足各漏做 4 项工作，仍有待解决。

结论仍是完整性修复有效，尚未显示更强的胜率或稳定的净收益提升。详情见 `EXPANDED_VALIDATION_ZH.md` 和 `EXPANDED_VALIDATION.json`。
