# 前排强敌优先与完整拳法结构化搜索 V2

日期：2026-08-24  
状态：替代“逐玩家 Replay 播放器优先”的正式执行口径

## 1. 核心结论

公开方案和当前前40 Replay 共同说明：强 Agent 通常不是从 719 步原子动作空间随机搜索出来的，而是：

```text
获得一条完整高手路线或人工经济骨架
→ 保持生产、维护、物流和变现链完整
→ 修改少数可解释的经营参数或局部战术
→ 同 seed、双座位、换对手消融
→ 只保留稳定增益
```

因此，本项目不再把“逐个复刻40名玩家的整段 Replay”作为主路线。Replay 的正式用途改为：

1. 提供完整可执行拳法锚点；
2. 提供经营项目的动作与事务模板；
3. 提供商店、对手、市场和终局条件下的变体证据；
4. 产生多个可以击败 FC24B 的新强敌；
5. 为最终融合 Agent 提供真实败局压力。

## 2. 为什么旧方法不够

将当前状态映射到一条历史 Replay 的剩余 719 步，存在根本缺陷：

- 过去的动物、土地、人员、库存和位置前缀不同；
- 新商店出现后冷切完整程序，会造成资源承诺不兼容；
- 即使按相同首店选择，来源对手和市场成交也不同；
- 动作恢复逻辑可以让对局跑完，但不能恢复原路线的经济含义。

Hasegawa 当前161路线实验已经实证：路线覆盖扩大确有帮助，但对 Flex 留出只有约五五开，且每局仍产生大量不匹配恢复。因此它是有效教师，不是第一名策略的无损在线复刻。

## 3. 新的搜索对象

搜索对象分三层。

### 3.1 完整拳法锚点

来源包括：

- 当前前40 Replay 中的完整获胜路线；
- 已下载且通过官方/JAX一致性的公开方案；
- FC24B 及其历史最佳版本；
- 已验证的高收益人工路线。

每条锚点必须覆盖完整719步，并完成生产、维护、物流和出售。

### 3.2 成套语义项目参数

参数不能只是孤立动作数量。正确单位是一个完整项目包：

```text
动物项目 = 设施 + 买入 + 饲料 + CARE + 收获 + 回仓 + 入库 + 出售
作物项目 = 种子 + 地块 + 种植 + 浇水义务 + 成熟 + 收获 + 回仓 + 入库 + 出售
人员项目 = 雇用时间 + 负责区域 + 任务链 + 日末退出
```

第一批可搜索参数：

- 开局 HIRE 数量和补雇日；
- 牛、羊、鹅的目标规模及增量投产日；
- 小麦、草莓、西瓜等面积与补种批次；
- 土地购买数量和时间；
- 各产业分配的人员曲线；
- 首店及累计商店信号下的项目增减；
- 产品首次出售日、提前量、批量和优先级；
- 后期停止投产、停止维护、计划退出和清仓日。

### 3.3 局部战术覆盖层

在完整拳法不被破坏的前提下测试：

- 杂草 actor-local 修复；
- 近镜像提前出售与下一步偿还；
- 当前市场订单排序；
- 仓库容量保护；
- 饲料价值门；
- 最后可行收获和清仓；
- 只依据公开盘面的作物防撞或市场抢跑。

## 4. 不能犯的参数化错误

以下做法仍然是错误的：

- 只把 `BUY_COW 8` 改成 `BUY_COW 10`，但不增加牧场、饲料和照料；
- 只把草莓面积从30改成40，不补人员和浇水时序；
- 删除一个 HIRE 后仍假设原来的 actor 编号与吞吐不变；
- 在日中切到另一条 Replay 后缀；
- 只看对静止对手现金，不看强敌共享市场下的胜率；
- 用榜单分数代替本地双座位留出实验。

每个参数必须编译成一组成套动作变化，并记录对以下指标的影响：

- 完成率和不匹配动作数；
- 终局现金；
- 对局胜率和分差；
- 生产里程碑是否兑现；
- 最坏尾部损失；
- 非胜转胜与胜转非胜。

## 5. 强敌优先门控

本轮目标不是先做一个看起来像前排的 Agent，而是先找到多个真实强敌。

### 5.1 发现门

候选必须首先与冻结 FC24B 对战：

- 固定开发种子、双座位；
- 至少128局方向筛选；
- 再用完全独立种子至少256局确认；
- 全局完成，无卡死和 hard counter；
- 开发集胜率必须明显超过50%；
- 留出集仍超过50%，且置信区间和最坏家族不能显示只是偶然。

通过者进入 `frontier_opponent_pool`。未通过者只能作为路线教师或局部能力来源。

### 5.2 多强敌要求

优先寻找彼此不同的三类 FC24B 克星：

1. 高牛/高吞吐、利用奶价和商店需求的路线；
2. 重羊或鹅/混合作物、在 FC24B 默认产业外竞争的路线；
3. 近镜像但在销售时机、人员和终局兑现上更强的路线。

如果多个候选只是同一行为家族，只保留最强代表，不按名字重复计数。

## 6. 最终融合流程

```text
前40 Replay + 本地全部完整拳法
        ↓
按行为去重，选完整锚点
        ↓
成套语义参数扰动 + 局部战术消融
        ↓
GPU：候选 vs FC24B
        ↓
得到多个真实 FC24B 克星
        ↓
逐类复盘 FC24B 败局，提取可见状态触发条件
        ↓
将能力接入 FC24B 派生骨架
        ↓
新 Agent vs 新强敌池 + 旧完整池
        ↓
保留非胜转胜多、胜转非胜少的版本
```

最终目标仍是：新 Agent 对更新后的每个强敌和旧 Agent 都达到90%胜率。该值是工程目标，不预先假设一定可达；若存在互相克制或近镜像导致的理论冲突，必须用逐局证据报告，而不能通过删对手或重复家族粉饰结果。
