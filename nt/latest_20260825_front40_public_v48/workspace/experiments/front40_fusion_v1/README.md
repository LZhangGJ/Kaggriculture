# Front40 Fusion V1

目标：基于 2026-08-23 天梯前 40 名各自当前最高分 submission 的全部公开 Replay，构建可审计的前排策略代理池，并把能跨玩家、跨随机事件复用的能力融合进一个新的本地最强 Agent。

## 证据范围

- 官方环境：`kaggle-environments==1.32.7`。
- Replay 快照：`replay/top40_live_20260823`。
- 只使用比赛中公开可见的商店、市场、自家状态和对手盘面。
- Replay 只能用于发现经营结构、编译测试夹具和训练/筛选公开状态路由器；正式 Agent 不得读取玩家身份、Replay ID、随机种子、未来事件或固定 Replay 坐标。

## 研发顺序

1. 冻结前 40 数据与路线族，区分独立能力和重复路线。
2. 盘点本地 Agent，建立“已有能力 / 缺失能力 / 可复原程度”矩阵。
3. 优先复原前五名独立路线族；相似路线族只复原一个代表。
4. 每个代理必须经过：来源轨迹对齐、新随机事件自由滚动、双座位 Arena、官方/JAX 一致性。
5. 只迁移被对照实验验证有效的能力，不按对手身份选择策略。
6. 融合候选必须同时在固定库和独立留出库胜过 FC24B，且不能产生新的家族短板。

## 双层 Agent 池门槛

- **融合供体池**：在独立随机库、双座位对 FC24B 胜率严格超过 50% 的家族。它们可以向综合 Agent 提供主骨架、公开状态路由或恢复分支。
- **强制验收对手池**：对 FC24B 胜率严格超过 10% 的所有行为去重家族，不论其是否达到 50%。它们不一定参与融合，但必须保留为最终候选的弱点对手。
- FC24B 本体作为冻结基线单独保留，不因行为去重而从验收中删除。
- 最终综合 Agent 必须在新的独立随机库、双座位、完整719步条件下，对强制验收对手池中的**每一个**对手达到至少 90% 胜率；不得用总体平均值掩盖单个短板。


## 当前基线

- 冻结本地冠军：FC24B。
- FC24B 旧验收池：旧 28 个严格 JAX Agent + 2026-08-22 最新 6 个公开 Agent。
- 旧验收结果：34 个对手每个 256 局，最低胜率 90.23%。
- 重要边界：这个旧池没有覆盖 2026-08-23 前五名的独立路线族，因此旧的 90% 不能外推为对当前天梯前排的胜率。

## 前40路线复原状态

- Rank1–40 已完成逐家族筛选；Rank30 是 FC24B 本体，不重复计作外部家族。
- 独立终验超过50%的家族进入融合供体池；其中 Rank39 `lelelove1225` 最新冻结版本对 FC24B 为 `83.20%`。
- 对 FC24B 超过10%的去重家族进入最终验收对手池。
- 不再增加额外的总体胜率、低分段专门门槛或超大样本零败门；最终核心标准保持为：对验收池中每个 Agent 的独立双座位胜率均达到至少90%。

## 目录约定

- `docs/`：阶段分析和设计决定。
- `configs/`：冻结目标、评测池和融合参数。
- `src/`：通用前排代理、路由与融合策略。
- `tools/`：Replay 编译、验收和 Arena 工具。
- `artifacts/`：路线库、事件库和模型。
- `receipts/`：机器可读回执。
- `reports/`：每阶段验收报告。
