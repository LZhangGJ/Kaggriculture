# Hasegawa 当前 Replay 重建门控报告 V1

日期：2026-08-24  
状态：**路线教师通过；在线 Agent 精细复原不通过**

## 1. 本轮回答的问题

本轮不是验证“能否播放 Hasegawa 的原始 Replay”，而是验证：

> 只根据当前公开状态和商店类型选择一条 Hasegawa 历史经营程序，能否在新随机局面、新座位和不同对手下稳定自由运行。

只有后者通过，才能称为可用的 Hasegawa Agent。

## 3. 失败过的方法

### 3.1 每次新商店出现就重新选择整段程序

当前 161 路线相对旧 102 路线确有改善：

| Bank | Flex 双座位 | 胜场 | 胜率 | 说明 |
|---|---:|---:|---:|---|
| 旧 102 | 64 | 18 | 28.1% | 路线覆盖不足 |
| 新 161 | 64 | 25 | 39.1% | 有改善，但仍弱 |

根因不是路线数量，而是局中切换到另一条完整 719 步程序后，前缀资产、人员位置、库存和未来事务不兼容。

### 3.2 等两个商店后再锁定程序

- Flex：4/64；
- 现金约 37k；
- 产生超过 109k 次不匹配动作意图。

它证明“多观察一会再整段切换”并不能解决前缀不兼容。

### 3.3 等一个商店后锁定程序

- Flex：10/64；
- 现金约 81k；
- 不匹配明显下降，但竞争力仍不足。

结论：不能先播放一个通用前缀，再任意接入另一局 Replay 的后缀。

## 5. 独立留出结果

### 5.1 Flex，128 局

- 随机种子与训练完全隔离；
- 64 个随机局面 × 双座位；
- 胜场：65/128；
- 胜率：50.8%；
- 平均分差：+742；
- 平均每局不匹配动作意图：约 27.5。

它比旧版对 Flex 的 37.5% 有明显改善，但只达到接近五五开，而且执行仍大量依赖恢复逻辑。

### 5.2 旧 Exact5，320 局

| 对手 | 局数 | 胜率 | 平均分差 | 不匹配/局 |
|---|---:|---:|---:|---:|
| Boatlee V20 | 64 | 73.4% | +5,219 | 53.3 |
| Ray K320 | 64 | 73.4% | +4,978 | 53.3 |
| Tetsutani | 64 | 73.4% | +5,219 | 53.3 |
| Kaito V27 | 64 | 65.6% | +7,076 | 2.4 |
| Flex V59 | 64 | 48.4% | +1,192 | 2.3 |
| **合计** | **320** | **66.9%** | **+4,737** | **32.9** |

重要审计结论：Boatlee V20、Ray K320、Tetsutani 三组的我方现金和不匹配序列完全相同，对手现金也高度接近，说明旧 Exact5 中这三个名字实际代表高度相同的路线程序。66.9% 不能解释为覆盖五种独立天梯风格。

## 6. 最终门控

| 能力 | 结论 | 理由 |
|---|---|---|
| 原始 Replay 逐来源编译 | PASS | 161 条获胜路线可编译 |
| 专家事务顺序教师 | PASS | 保留真实市场订单、人员和生产动作 |
| 商店条件路线证据 | PASS | 路线结构与首店存在稳定关联 |
| 新局面自由运行 | PARTIAL | Flex 仅 50.8%，仍有大量恢复 |
| Hasegawa 在线策略精细复原 | **FAIL** | 不能从 Replay 推断完整状态条件和偏差恢复规则 |
| 直接作为最终融合骨架 | **FAIL** | 会把轨迹偶然性和状态不兼容带入正式 Agent |

## 7. 后续正确用法

保留这些资产，但改变用途：

1. 将路线按首店、商店计数、产业规模和终局模式分组；
2. 从 Replay 提取“状态条件 → 经营能力”，而不是“状态 → 余下整段动作”；
3. 重点复原可迁移能力：
   - 首店驱动的牛羊规模；
   - Farmers Market 下的作物切换；
   - 高牛路线的牧场、饲料、人员、收获与出售完整闭环；
   - 商店发生变化时只修改受影响项目；
   - 事务失败后的局部恢复；
4. 每项能力接入 FC24B/当前冠军骨架后，分别做固定种子、双座位和新随机库消融；
5. 只有独立留出显著提高且没有家族退化的能力，才进入融合版。
