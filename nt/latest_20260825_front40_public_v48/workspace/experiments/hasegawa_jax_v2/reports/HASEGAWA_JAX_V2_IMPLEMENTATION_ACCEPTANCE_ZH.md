# Hasegawa JAX V2 实现与验收报告

## 1. 结论

Hasegawa V2 已实现并通过第一阶段验收。

V2 不调用旧的连续任务 Kernel，也没有重新实现通用 Thin Kernel。它直接在官方 JAX
状态转移之上运行：从 102 局 Hasegawa 胜局中，为未知开局和 8 种首个商店各冻结一条
完整的 719 步原子动作程序。首个商店出现后只锁定一次完整程序，之后不再每日选择或
拼接 Replay。

当前版本能够：

- 完整保留 Hasegawa 的人员动作交错顺序和同回合市场事务顺序；
- 在执行每个原子操作前检查当前地块、物品、种子、动物和仓库条件；
- 遇到随机杂草时只插入 `DIG`，随后恢复被阻断动作；
- 人员位置偏离时向当前程序的预期位置局部恢复；
- 识别官方 `PLACE` 的两种语义：放置动物，以及在仓库入口把指定随身物品入库；
- 根据实际 shed 数量保护出售请求，并在终局追加清仓；
- 在 JAX/GPU 上整局批量执行。

它仍不是 Hasegawa 源代码的精确复刻，也不是已经完成的通用任务规划器。当前运行逻辑
是“完整高手原子程序 + 当前状态局部恢复”，而不是能够自主生成全新日内任务链的模型。

## 2. 与 V1 的关键差异

| 项目 | V1 | V2 |
|---|---|---|
| 经营骨架 | 每日重新找最近 Replay 日历 | 首个商店出现后锁定一条完整 719 步程序 |
| 跨日处理 | 日切会清空/重置一部分任务和账本 | 不存在日切路线重选或任务清账 |
| 动作表达 | `CROP_PRODUCTION` 等连续任务链 | 官方原子动作逐步表达 |
| 人员交错 | 通用调度器重新安排 | 保留高手原始的日内多人交错顺序 |
| 市场事务 | 日汇总后重新生成订单 | 保留同回合原始订单和顺序 |
| 偏差处理 | 换路线或重建日历 | 只修复当前受阻动作与位置 |
| 旧 Kernel | 依赖 | 运行时完全不导入 |

“没有硬错误”误读为“策略已经充分动态适应”。

## 6. 已发现并修复的实现漏洞

初版把 `PLACE` 错误理解为只能把动物放入牧场/鸡舍，因此把 Hasegawa 的：

```text
PLACE WOOL 5 -> SELL WOOL 5 -> BUY_LAND
```

误判为非法动作。官方规则实际还允许单位在 shed access 使用 `PLACE(item, quantity)`
把指定随身物品入库。修正后，来源 Replay 从 step 1 到 step 719 完全一致。

这次漏洞说明：局部安全检查必须逐项以官方模拟器为准，不能根据旧任务抽象推断动作含义。

- “已经复刻 Hasegawa 完整动态策略”：`NOT_CLAIMED`；
- “可以直接提交”：`NOT_YET`。

建议下一步优先分析 Flex V59 败局，并对全部大败局按首商店、首次现金偏移、首次无效
意图、市场价格和最终产业结构分组。Boatlee/Ray/Tetsutani 虽然胜率略过 50%，但负平均
分差同样需要定位长尾失败。只有出现稳定且可解释的共同失败模式后，才增加新的状态条件
或恢复策略。
