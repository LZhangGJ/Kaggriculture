# 采购异常后的日内恢复：实现与验证

已把采购成交异常后的日内恢复接入 R2 P16 的完整任务链候选版本，并编译为可加载的 C++ 动态库。功能是每步对账、异常时重排当天剩余工作；新增的是决策算法，没有重新训练模型。

程序入口：`Kaggriculture/nt/latest_20260910_r2p16_route_recovery/main.py`。
最终二进制：`build/revision3/route3.so`，SHA-256 为 `a540d2c14ee8cabc2905a0d858e70b5fc48359b8ccc28b358eae7391459be98e`。
旧版对照是完整任务链版本的 `build/revision2/route3.so`，不是更早的经济路线版本。

**增加的行为**

- 对照上一动作的预测，核对真实现金、种子、仓库、土地和已雇工人。采购或雇工未足额，以及现金减少到付不起后续订单，都会触发恢复。
- 立即撤下剩余旧订单，从当前工人位置、各自背包和剩余小时重新排班。已经完成的工作保留。
- 只用当前可支出现金决定补购与追加人手。需要卖货时先出售未被任务占用的仓库现货，下一步根据真实到账金额再买。
- 比较能够完成全套剩余工作的不同雇工数；验证完整播种/养殖动作链后才购买。资金或时间仍不足时，逐步延期未开工项目，保护已有资产的维护与收获。
- 保留原承诺中的未完成任务，另记延期，避免通过删除承诺让漏工统计变好看。

恢复复用了原有排班器、完整动作链修复和观察盘面模拟器。没有使用比赛 seed、对手名字或 replay 后缀作为决策输入。外层日常经营预测不递归运行新增的恢复搜索。

**完整验证范围**

97 项 C++ 检查通过：20 项原经济/容量检查、58 项完整任务链检查、19 项采购恢复检查。覆盖五类作物补购、真实到账前不购买、无现金延期、背包饲料、仓库满载、临近日终、新增雇工的实际工资档位、原承诺保留、现有多年生作物保护及预测中不递归触发。

32 局回归：16 组配对。14 组未触发采购恢复，新旧全部 719 步动作一致；2 组已知故障配对在实际异常后改变。旧版共漏 8 个原承诺动作，新版 0 个。该集合包含已知故障，不能当作随机胜率样本。

另跑 220 局预先选定的新种子测试：5 个 seed × 全部 11 个原始对手 × 两座位 × 两版本，每版 110 局。seed 为 `407296613、1042873761、2091660419、3150275837、4180732261`，选择前检查过往协议，没有重复；本轮没有按结果挑选或删去 seed。

该新种子集合触发恢复 0 次；110 组配对动作完全一致。它验证正常路径的兼容性，尚不能证明恢复机制在随机对局中普遍提升胜率。11 个对手中存在策略同质化，5 个 seed 也不等于大量独立策略样本。

最终两组实验共 252 局，全部通过既有编译版 C++ 裁判的逐步复核：每局 720 帧、719 次决策，双方共 362880 份完整观察均一致；重新计算了工资、雇工、移动、溢出、无效动作和任务完成记录。此前校准过的对局裁判库未被修改或重编。正常路径一致性额外通过 `CAUSAL_AUDIT.json` 检查。开发阶段的 revision2 结果未混入最终统计，其保护条件影响普通规划的问题已在最终版本修正。

**计算开销与边界**

在全部并行测试结束后，对每个版本并行测试中最慢的一局，以及采购故障的一局，单独顺序回放。共 2876 次决策全部复现原动作。旧版单次最大 0.700 秒，恢复版 0.671 秒。完整逐步计时保存在 `SEQUENTIAL_TIMING.json`。这是本地测试，不是比赛沙箱时限认证。

恢复只在事件发生后进行；当天普通动作继续由原执行器逐步决策。筹资和采购步骤目前会暂停工人的路线。排班候选是有限搜索，只能说找到了通过验证的可行雇工数，不保证全局最少，也不保证每局工资下降。仓库溢出的历史问题也没有被这次采购功能整体消除，表中保留了真实溢出数量。

可用于本地对战的功能已完成。现有证据支持消除已复现的采购漏工，并保持本次普通对局行为；推广到更广泛异常局面的强度仍需更多自然触发样本。
