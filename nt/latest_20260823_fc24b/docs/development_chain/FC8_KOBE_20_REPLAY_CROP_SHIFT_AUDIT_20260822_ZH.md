# FC8：Kobe 20局作物转向与动物下降审计

日期：2026-08-22  
官方环境：`kaggle-environments 1.32.7`

## 1. 结论

Kobe 并不是在观察到牛羊下降之后，才临场决定转种胡萝卜。

20局时间顺序证据表明：

- 普通路线只在约第544–550步补种1、3或5块胡萝卜；
- 只有一局前三家商店均为 `PET_CAFE`，在第380步开始大规模胡萝卜项目；
- 该局累计发出94次 `PLANT CARROT`，而动物从第23天才开始下降；
- 胡萝卜项目明显早于动物下降，因此不能解释为“动物失败后的恢复”；
- 动物下降伴随大量无效 `FEED`，属于该分支的执行/物流缺陷，不是干净的项目退出。

因此，本局可借鉴的是：

> 根据重复需求商店启动大规模作物项目。

不能借鉴的是：

> 让动物因断粮逃跑，并把结果包装成主动退出。

## 2. 数据覆盖

冻结 Kobe 当前提交 `55668682` 的20局完整官方 Replay：

- 有效 Replay：20/20；
- 胜局：18；
- 败局：2；
- 前三店全为 `PET_CAFE`：1局；
- 大胡萝卜路线（审计分组：至少20次种植意图）：1局。

20局只能证明该 Agent 存在一个高度特异的商店分支，不能证明该分支对所有 triple-PET 事件都最优。

## 4. 动物下降的真实原因

20局中有10局出现动物数量下降：

- 9局只在第29天减少3只动物；
- 这9局没有无效喂养，符合终局停止维护/计划释放的表现；
- 1局在第23天开始失去全部14只动物，即 triple-PET 大胡萝卜局；
- 该局共有281次 `FEED` 意图，仅187次实际有效，94次为无效动作；
- 其中至少24次明确因为执行单位没有携带小麦，其余大量发生在动物已逃跑后的空设施上。

更强的反证是：动物消失后，Agent 仍继续向空设施发出 `FEED/CARE`。如果这是主动 `EXIT`，下游维护任务应当被取消，而不是继续执行。

## 5. 对融合 Agent 的能力缺口

当前严格验收的本地 Agent 池没有一条已证明可跨事件恢复、可动态执行的94动作级胡萝卜生产链。Kobe Replay 暴露的是一个真实缺口：

1. 根据同类需求商店的数量和到货节奏，决定是否启动大规模作物项目；
2. 从当前可用土地和人员状态生成种植、浇水、收获、回仓和出售任务；
3. 逐日检查项目兑现能力，而不是复制 Replay 坐标和日期；
4. 若决定缩减动物，必须同步取消购买、喂养、CARE和空设施任务；
5. 评分必须同时计算对手从市场价格外部性中获得的收益。

现有简单候选 `_pet_cafe_project_shift_v1` 只是把 FC2B 的部分小麦动作替换成胡萝卜，不能生成 Kobe 的生产规模和物流能力；它已在145个独立 triple-PET 事件上被否决，不能接入正式 Agent。

## 6. 下一验收门

先做潜力门控，不直接改正式 FC2B：

1. 固定64K事件库中筛出的145个 triple-PET 独立 seed；
2. 双方换座；
3. 对 K320、Rank12、PRT 分别验证 Kobe 大胡萝卜路线探针；
4. 同时报告胜率、现金、分差、无效动作、重同步和市场订单裁剪；
5. 只有跨对手显示稳定潜力，才开发状态驱动的胡萝卜项目执行器；
6. 新执行器必须做到无效动作归零，再与原 FC2B 做全局消融。

### 6.1 145个 triple-PET 事件的公平结果

使用完全相同的145个独立事件、双方换座，对比 FC2B 与 Kobe Replay 恢复探针：

| 对手 | FC2B | Kobe原始链 | Kobe恢复探针 | 原始链相对FC2B | FC2B平均现金 | 原始链平均现金 |
|---|---:|---:|---:|---:|---:|---:|
| K320 | 99.31% | 99.31% | 99.31% | 0.00pp | 40,340 | 77,807 |
| Rank12 | 62.41% | 58.97% | 59.31% | -3.44pp | 52,557 | 65,088 |
| PRT | 81.03% | 74.83% | 74.14% | -6.21pp | 52,350 | 66,931 |

原始完整动作链与恢复探针结论一致：两者都显著提高现金和平均分差，却没有提高得分率。恢复探针的配对变化为：

- Rank12：75个原败局被救回，但84个原胜局被破坏；
- PRT：39个原败局被救回，但59个原胜局被破坏；
- K320：救2局，同时破坏2局。

这再次证明比赛不能只优化平均现金或平均分差；高方差的大胜路线可能制造更多小败局。

但这组结果不能用来否定 Kobe 本体，因为恢复探针每局平均约有491个单位动作被本地恢复器替换，并有约256条市场订单被裁剪。它评价的是“粗糙 Replay 恢复器”，不是 Kobe 的真实条件策略。

原始动作链没有恢复器的上述替换，但仍是固定 Replay 时间表，无法在独立事件中根据真实状态重规划；它同样不是 Kobe 本体。原始链与恢复探针都弱于 FC2B，反而强化了同一个结论：真正有价值的是 Kobe 的条件控制和偏差恢复，不是把 episode `96045062` 的719步固定播放。

### 6.2 当前 Public 强度快照

用户于2026-08-22提供当前榜快照：

- Kobe：第10名；
- 评分：约2,880。

这是用户提供的实时榜单事实，尚未由本报告调用 Kaggle API 独立刷新。它说明 Kobe 整体 Agent 已具有很强的当前 Meta 适应性，因此下一优先级应是刷新其当前 Replay，并复现“状态条件 → 项目规模 → 日内任务链 → 事务顺序”，而不是继续修补粗糙轨迹恢复器。

### 6.3 与冻结路线库的结构相似性

将20局 Kobe 原始动作与冻结的87条 JAX 路线逐步比较，得到：

- 14局的最相似骨架是 V8/Rank1 的 `10C-4S-75L`；
- 6局的最相似骨架是 `6C-12S-100L`；
- 这6局全部在前两家商店中出现了 `YARN_STORE`；
- 其余14局前两家商店均没有 `YARN_STORE`；
- 20局与对应最相似骨架平均有331/719个完整步骤完全一致，范围241–392步；
- 20局最初26步均与 V8 共用开局，首次差异发生在第26步的杂草/恢复调度。

也就是说，在当前20局中，下面这条观察规则达到20/20一致：

> 前两家商店出现 YARN → 重羊 `6C-12S-100L`；否则 → `10C-4S-75L`。

这只证明路线选择与公开商店条件高度相关，不足以证明该阈值对所有独立事件最优。正式融合时仍需做反事实消融。

### 6.4 为什么不能直接把 Kobe 称为 V8

将每一步 Kobe 当时看到的完整观察重新输入公开 V8，并与 Kobe 记录动作做 teacher-forcing 比较：

- 平均完整动作一致：165.9/719步；
- 平均单位动作组一致：203.05/719步；
- 平均市场订单组一致：354.35/719步；
- 运行异常：0；
- 共同精确前缀仍为26步。

同盘面输出的一致度明显低于“固定动作骨架”的非连续重合，说明双方共享大量编舞，但运行时恢复、市场重排和中盘项目切换并不相同。因此当前最准确的结论是：

> Kobe 很可能以相同的高收益路线家族为经营底盘，并新增了自己的状态条件控制；不能宣称它等同于 V8，也不能把固定 Replay 当作 Kobe 本体。

另一个数据处理结论是：Kaggle Replay 的后座观察采用共享字段增量记录。teacher-forcing 必须先把后座 delta 覆盖到前座完整公共观察上，否则会缺失 `step` 并错误地反复执行第0步。本次工具已经加入后座观察重建，并在20局上做到0异常。

## 8. 真值边界

- Replay 关联只能证明 Kobe 在该公开状态下采取了某条路线，不能证明路线因果最优；
- 原始意图不等于实际成交或状态效果；
- 单一 triple-PET Replay 不足以冻结触发阈值；
- 路线恢复探针不是可提交 Agent；
- 正式规则必须经过独立事件、双方换座、全对手池和官方 Python 复验。
