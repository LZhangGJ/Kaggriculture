# Triad-DP T1：实现与边界

## 1. 本轮实现的内容

T1 从本地 2026-09-05 C3 重建包复用规则执行器、市场报价、动物维护等基础组件，重新实现经济项目生成、条件生产日历、持久项目承诺及日级候选试排。它不读取 J7 经营配方、不播放高手原子动作、不把某个对手的名字映射成路线。F3 的需求视图和有限路线子集 DP 思想用于参考；本轮没有拿到并重新编译完整的 9 月 6 日 F3，因此不把本轮基线称为“最新 F3”。

Justin Gao 文章提供的是职责划分，不是可直接移植的求解程序。以下代码是本轮实际实现，不是文章作者已经验证的能力。

## 2. 三层如何落地

### 经营层：每日生成可比较的投资方案

`policy/triad.hpp::Controller::plan` 从真实地块、当前库存、现金、已解锁商店及对手公开产能建立项目集合。它比较有限作物收获日期、作物类型、动物类型、维护方案和扩张，扣除资源、劳动及用地成本。共享市场收益是非线性的；每加入一个项目重新估价，不是把单项目利润直接相加。

这里的全农场组合仍是启发式逐项构造，不是 30 天全部动作空间的精确全局 DP。动物喂养/照料、连续作物维护等有限状态子问题使用 Bellman 递推。未来轮作收益递推也有实现，但在当前较优配置中，`rotation=0`、`repeat=0` 关闭了未来轮作/重复种植的估值项；这不禁止真实盘面中的收获后换种。不能宣传成“完整轮作 DP 已被证实有效”。

### 承诺与调度层：项目跨日，工人不跨日盲目绑定

`Commitment` 保存项目类型、出生时间、选择时间、后继作物及是否已投入。真实植物、动物、背包、仓库状态只从 observation 获取，不保存另一套假装已经成交的现实。

雇工每天被引擎重置，因此保留的是未完成项目，不是一个已不存在的 worker ID。已购买未放置的动物、已买种子的轮作后继可以次日继续；旧作物已经收掉后，后继承诺仍可从空地接续。库存预留按共享库存逐项扣除，不把一颗种子同时承诺给两块地。

每天重新组织工作路线，但有效的日内动作链与路线持续执行；失效动作、补给不足和可以安全交接的服务任务依据真实状态修复。`PLANT→WATER` 是同一地块任务链，不将种下但未浇水当成成功投产。任务默认继续，不采用“所有任务永不允许中断”的绝对规则。

`preview_bundle` 在采购之前试排当前工作。未投入且当天排不进去的新项目可以撤回，已存在的维护与已投入项目不能仅为了让预览好看而被丢掉。这是当天可行性检查，不是所有未来日期都可行的证明。

`triad_exact_tour` 对单个工人的 2–9 个既定地块任务求最短访问顺序；保留每个地块内部操作链。已与最多 8 个任务的全排列最优值对照。它不优化全队的全局分工，也不证明最短路等于最高经济收益。开发面板中启用它没有提高整体胜率，最终默认配置不启用；保留为可复现实验。

### 条件生产日历与公开信息前瞻

`crop`、`animal_path` 根据真实当前状态及声明的维护选择计算未来产出与消耗。若维护未兑现，次日从实际结果重新计算。已用可控引擎情景验证多个作物、出生日期、收获日期及动物案例；这不是所有随机状态的形式证明。

`SearchController::choose` 每日生成最多六种经营参数方向，由它们各自重新生成当前地块与采购计划，然后在 `PublicFlowScenario` 中执行至次日边界。执行仿真包括采购、雇工、移动、维护、收获、入库和销售，而不是只比较计划中的种植数量。以统一的公共情景和后续价值估计比较方案后，只安装今天的经营计划，实际动作继续由真实观察驱动。

候选方向包括原计划、较快资金回收、较少或较多动物、较弱或较强竞争惩罚。它们不是六条固定 719 步路线。候选按当天目标、订单、维护标志做粗签名合并；该签名不是完整的逐步行为等价证明，可能合并日内估值差别，这是搜索覆盖的限制。

公开情景是从 View 构造的合成世界，不是克隆实际比赛。它不接收真实 seed 或对手私仓。对手未来销售以公开产能的两个到货窗口近似，未知商店使用期望消费，杂草随机性未纳入该前瞻。场景里产生的合成商店抽样会被丢弃，不能变成候选特征。实际对战中的对手则每一步正常读取真实局面并响应。

## 3. 现金兑现的改动与未完成项

`settle_market` 在我方单位动作的条件投影后计算可卖数量，允许本步 DROP 的货同一步出售，同时保护已经预留的饲料、肥料和任务投入。市场结果仍以下一次真实观察为准；不能把条件投影当作并发订单必定成交。

默认策略及时变现剩余产品，不再让估值假设“已经卖掉”而执行端大量长期囤货。终局撤掉维护库存预留，保留原有终局回仓与销售截止规则。

这还不是完整的 `SELL_NOW/HOLD/融资/仓储/再投资` 联合 DP。一天内的动作投影和次日边界现金进入比较，但更远的价值仍采用近似产出与价格模型，实际对手的出售窗口也没有被精确求出。因此不能把本版描述成投资—生产—竞争—销售全部层面的精确最优解。

## 4. 监督估值实验，不与默认版本混淆

本轮实际采集了 7,049 个反事实候选分支。先冻结 356 维公开/我方状态特征，再复制完整环境与对手状态获取离线终局标签；候选只干预当前日，之后恢复共同原生策略。KEEP 与不中断轨迹的终局资金完全一致，另有小面板正序/倒序分支隔离检查。

实际训练了回归估值器和排序估值器，并导出 C++ 数值树验证预测一致。回归分支偏向 KEEP，排序分支未在完整开发对战中超过公开情景前瞻，因此默认 `scenario=1` 不调用学习模型。`scenario=-1` 是实验入口，不是默认晋级配置。数据、训练程序、模型和失败结果均保留，不能把“有训练”写成“训练已经提高胜率”。

## 5. 验收含义

验收分别报告七个对手的胜率、等权总体胜率、相同 seed 的双座位结果、异常、耗时、日末溢出损失以及抽样动作效果。平局不计胜，异常计负；不删除弱对手、失败 seed 或失败座位。

官方逐步一致性检查验证的是冻结规则及 Python 导出入口。它不代表在全部状态上证明模拟器正确，也不等于本轮重新验证了所有对手 Python 与 C++ 移植的一切行为。对手使用的是随包冻结的实时 C++ 实现，不宣称它们是 Kaggle 当前最新版。

最终结论以 `REPORT_ZH.md` 和 `runs/release_holdout100` 为准。开发面板、反事实事后最佳和训练集数值不能替代独立整局胜率。
