# S4H：自主开局与后续饲料估值的交叉测试

## 为什么再测曾经失败的能力

S4G真实复盘：自主开局增加畜牧后，对G003的牛奶售量增加但回款减少，小麦产量下降、外购支出增加约4869元。不是工资造成主要退化，前12天销售甚至更高。

源码 `portfolio_values` 按 `own_feed_demand_weight` 决定是否记入已有动物未来每日喂养；当前为0。新选动物的负小麦流已经由 `project_calendar` 计入，不能再重复加。当前应检验的是“项目落地成为已有动物后，维护需求是否从估值里消失”与自主开局的组合，而非重新扫描饲料倍数。

S3J等历史试过饲料权重，未普遍晋级；必须保留这一事实。新的条件是自主开局与现金日历/资金工作集，不能用旧单项失败直接排除，也不能保证叠加就会有效。

## 固定2×2，不再调网格

分别在 `intraday_funded` 与 `all_intraday` 上下文执行：

|自主开局|已有动物饲料估值|目的|
|---|---|---|
|关|0|固定开局的日历/资金比较控制|
|关|1|仅记入已有动物按当前维护政策的每日1份小麦|
|开|0|逐局复现S4G自主日历组合|
|开|1|检验真实的组合效应|

八个配置均固定 `cashflow_value_mode=2`、`funded_bundle_mode=2`。不修改 `committed_feed_weight`，因为该模式已将新项目饲料写进流量日历；不重复加。不开“某对手专用”或指定牛羊数量。0→1是关闭/启用条件饲料量，不搜索0.3/0.7/1.5之类系数。

## 验证

- 不改C++源码，复用S4G已核对的构建；配置使用同一份明确哈希。
- 对新组合补4局官方G003双座位核对；八对手原生迁移/隔离仍指向相同构建的已通过收据。
- N=20262701–20262750、双座位、PASS＋八个实时对手，7200条配置对局，C++最多16线程。
- 八组做只读现金/产销复核；两个S4G控制1800条结果必须完全一致。
- 按seed聚类计算自主开局、饲料修正及交互效应；报告销售、实际小麦采购、工资、投入规模，不以预测分数升高验收。
- O/P未用。只有实际改善才考虑冻结到新seed；不按已知对手挑不同配置。

## 停止细调条件

本轮若仍不支持晋级，保留失败能力但不继续扫饲料倍数、收获日期或开局数量；下一步需要完整可执行投资组合的后果模型，而不再只对当前逐项排序添惩罚。任何未来规划只能用自身/公开状态和明示假设，不能以真实未来或对手私有信息恢复Candidate事后Oracle。
