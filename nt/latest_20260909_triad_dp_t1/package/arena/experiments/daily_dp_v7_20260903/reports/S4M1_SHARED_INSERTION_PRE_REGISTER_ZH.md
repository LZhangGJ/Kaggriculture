2026-09-04。目标保持八实时对手逐一胜率超过90%，不以省步数替代。

## 证据及可证伪改动

S4M v1在64场原样实时对局没有发现可直接追加的遗漏任务，不放宽全量门槛。v2发现旧调度只把共享服务追加在路线尾部；v3加上交货和跨工人施肥/浇水先后约束后，仍有64/64局出现沿途插入机会，每局约50–78个检查点。检查点重叠，不能相加为全季节省，更不能等同收入。

`shared_service_insertions` 默认关闭。开启后，保留每位工人的材料动作相对顺序，对共享服务枚举工人和插入位置。只接受全工作集可在当日结束前完成且覆盖更多任务或降低峰值/总步数的方案。收获若原有入库承诺，转交后也必须保留入库；跨工人施肥必须先于浇水。检查不能通过就保留原安排。无新身份、数量、日期或种类特调；不推进模拟器，不窥视未来。

这是对已有任务的调度表达扩展，不是完整经济最优编排，也没有解除所有资源动作的单人归属。是否提高长链收益由下面实时对战检验。

## 冻结矩阵

四个背景各关/开插入，共8配置：

1. no_intraday：已有共享调度、逐步修复等，但关闭当天追加生产/采购。
2. all_intraday：原保留组合，包含当天追加生产/采购。
3. auto_portfolio：自主组合投资及统一作物日历。
4. auto_portfolio_procure：上述再加维护缺料恢复/采购。

全部保留已验证的增量PICKUP修复。第1与2构成调度×追加生产的2×2组合，避免单看省路；第3与4观察投资/维护组合下效果。后三个关开关背景应逐场复现S4L共2700场；第1背景不虚称已有逐场控制。
