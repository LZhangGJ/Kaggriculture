# S3U：排班与终局入库必须组合验证

2026-09-04。本轮开发实验完成，正式目标未完成；最终验收库未使用。

## 1. 结论

用户提出的“单项未必有用，组合可能有用”在这一轮得到了具体支持：**单独改排班降低收入，补上多人分批入库后，排班造成的大部分收入损失被追回。** 但不能把正交互说成组合已最强，更不能说已达到逐对手90%。

当前保留两个候选，不按对手身份切换：

- `terminal_only`：原排班＋终局入库波次，作为下一轮通用开发基线。
- `compile_terminal`：联合排班＋终局入库波次，保留为研究候选，部分对手更好、部分更差。

原版、单项失败配置、此前拆任务/雇工估计等所有开关和负结果继续保留，没有因单项退化而删除能力。

## 2. 本质问题与这次修改

S3T证明，排班退化不能仅归因于少雇工。只改变实际编排、保持旧雇工估计，依然退化；相同产量没有顺利变成现金。

官方完整复现发现：各工人都“来得及最后一步回仓”，但多个工人会同时争抢100仓容。市场出售发生在整个单位阶段之后，不能在两个工人的DROP之间清空仓库。后到的工人因防丢货保护而PASS，随后仓库卖空，游戏也结束了。单人路线正确，不代表多人联合物流可行。

新增独立开关 `terminal_deposit_schedule`，仅作用于最后一天的实际编排：

1. 保留现有编排作为基准候选。
2. 在同一批人员、同一任务集合上，生成不同完成提前量的贪心/插入编排候选。
3. 投影自己的携货、PICKUP、按单位顺序DROP、仓容和单位阶段之后的出售。
4. 超出终局的入库不能计算成现金；不够容量的整包DROP必须等待下一步。
5. 比较预计可兑现现金，只有严格增加才更换。允许少收一些低价值货，以保障高价值货及时卖出。

这是共享容量与截止时间的通用建模，不是固定某个seed、作者、商品数量或高手日历。官方规则、经营参数、雇工估计均未更改。

市场预测使用当前公开价格曲线及自己的预计销售影响，不读取隐藏对手库存、身份、真实seed或未来事件。它是条件估算，不是完美未来模拟。

## 3. 独立开关与组合

| 配置 | 实际联合排班 `regret_compile` | 终局波次 `terminal_deposit_schedule` |
|---|---|---|
| old | 关 | 关 |
| compile_only | 开 | 关 |
| terminal_only | 关 | 开 |
| compile_terminal | 开 | 开 |

四组的 `regret_hire_estimate`、旧兼容开关 `regret_schedule`、`split_service_jobs` 均为关。这样不会把实际编排与自动减少雇工混在一起。

后续同样遵守：先独立开关，再对有因果联系的模块做2×2组合；若单项失败，先检查下游依赖，不能直接判为无用。也不盲目枚举所有开关的指数级组合。每次保存关闭、单开、组合和新seed结果，区分“互补”“超过基准”“达到最终目标”三个结论。

## 6. 已知负结果与限制

预测收益提高不保证实际每局提高。A集：`terminal_only`对Boatlee有4/100局现金下降、G003有2/100、Fieldbook有4/100；组合相对compile_only对Fieldbook有6/100下降。这些不是删除的异常样本。

例如Boatlee/20261415/座位0：预计仅多赚2，实测少529；G003/20261413/座位0：预计多72，实测少294。当前价格近似、未知对手出售和任务实际执行会产生误差。这里只确定预测与实际不符，尚未逐一证明每例误差都由哪项造成；不凭个别败例加专用阈值。

本轮没有解决：

- 全局每一步重新分配全部工人。
- 普通生产日的完整共享仓容时序规划。
- 所有日内任务可任意拆分、交接、携料复用。
- 把新投资、采购、维护、运输、销售纳入同一套长程后果比较。
- 对手动态响应的准确预测。

终局编排比较使用近似可变现现金，不是把每套候选都用真实未来续跑到结束。它修复了一个有证据的约束缺口，不能代替完整经济规划。

## 7. 验收与成本

- 4,230项原生机制检查通过：包括仓容、单位顺序、出售顺序、永久占仓动物、PICKUP供给、超时、基准回退和候选现金不降低等。
- 本二进制共34局完整719步官方核对：六个新接入对手的官方/隔离检查24局，G001/G003两种新配置双座位8局，终局诊断2局。
- A/B四组7,200条配置对局，其中old和compile_only共3,600条逐局复现S3T历史端点，用于兼容检查，不算新独立样本。
- 新K四组3,600条，总计10,800条配置对局。另有A集3,600局重复现金/生产审计，不加进强度样本量。
- 冻结二进制后A、B、K各3,600条配置对局，完整脚本约11.43、11.33、11.64秒，C++热循环、最多16线程。属于本机这一组合的实测，不是每种任意策略都可达到的速度。
- 编译约22.07秒；A集重复账本审计约76.78秒。代表局原生单步调用最大抽样约4.4ms，不是完整Python线上1秒验收。最终Python提交版尚未同步。

源码、配置、官方规则冻结；最终PASS与八对手独立验收尚未运行。因此“开发集PASS超过18万”不等于完成目标。
