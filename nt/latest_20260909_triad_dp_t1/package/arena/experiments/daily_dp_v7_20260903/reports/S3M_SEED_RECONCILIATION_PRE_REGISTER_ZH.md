# S3M：采购后种子需求漂移，单机制预登记

2026-09-03。基线为 S3L 的 hire_base / L3_return，不启用失败的雇前插入编排和续种供给加权。不改变官方规则、对手、宏观选种/数量/布局与出售策略。

## 因果假设

原日初采购根据旧盘面生成；采购结算期间作物到期变为杂草，compile 从新盘面生成补种工作，却未重新采购种子。S3L 已有批量发生率及两个有钱但漏采购的真实见证。预计补上这处衔接可提高可兑现产量；不保证整局净收益或胜率增加。

## 机制边界

- 保存日初预计种子需求，采购队列完成后从当前真实状态重新计算需求。
- 只补“新增需求且库存不足”的部分；不顺便买回最初因资金不足放弃的全部大计划。
- 现金必须足够全部新增种子费用；不依赖对手私有物品/未来随机数。
- 使用现有联合编排器检查：多耗一个采购回合后，同一批资源就绪任务仍能完成。存在当前可见的当步腐坏收获时不延迟。
- 每天最多检查/修补一次，下回合依真实成交状态重新编排。不循环等待；失败则回到现有降级机制。
- 开关默认 false，试验配置 seed_reconcile 才开启。修复不能按日期、坐标、作者名触发。

## 验证顺序

1. 五种作物、多个日期和位置的因果夹具；现金/时窗/原已缺料/库存已足/重复执行/复位边界。
2. 全8原对手抽样719步官方状态与动作对照，六个迁移对手隔离测试。
3. ABC 150个已使用开发seed双座位：两配置 × PASS及8对手 = 5,400局。与前轮关闭开关逐局核对。
4. 现金/生产账本、修复发生与完成率、工资/种子成本、吞吐。报告所有对手，不挑最好对手或最好seed。
5. 只有ABC综合有价值才进行预先冻结D批20261701–20261750。所有用于选型的seed均为开发集；最终PASS/8对手验收库仍不使用。

本轮不自动宣布90%验收通过；不训练、不提交、不推送。无论保留或拒绝，都解释经济结果及下一轮共同能力缺口。
