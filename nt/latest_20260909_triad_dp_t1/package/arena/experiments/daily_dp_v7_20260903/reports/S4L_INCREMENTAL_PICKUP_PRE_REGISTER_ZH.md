# S4L：修正未执行领料的数量语义

2026-09-04，实战面板前冻结。目标不变：同一冻结实时Agent对八个指定对手分别超过90%。

## 已证实的问题

`s4k2_repeated_pickup_reproduction_v1`：持有1小麦，喂第一头牛，再领1小麦，再喂第二头牛。冻结规则原安排fed=2；重排后PICKUP从1变0，fed=1。代码把PICKUP数量误当“目标持仓”，官方实际定义是“新增领取数量”。实际动作下发后已通过plan.index推进，不能再凭当前持仓提前删除未来领料。

## 本轮唯一运行开关

`incremental_pickup_repair` 默认关，开启时：

- 未执行、数量有效、当前仓库有货的PICKUP，不因当前随身数量已达请求数量而删除；前面的任务可能先消耗它。
- 保留PICKUP后须标记后续可能携货，不能删掉它后面的DROP运输任务。
- 不改变宏观经营数量、日期、产业权重、市场报价、对手判断。
- 仍从真实库存执行并裁剪实际领取数量；不把未来订单或未收获产品当成已到手。没有声称解决一切未来跨单位供货/整队资源投影。

## 机制与组合验证

新机制覆盖：重复补料、当前有持仓仍可增量领取、领料后跨仓库格入库、数量合法性、真实部分领取、动作游标已执行不重复。小麦和肥料都检查；原27项与4490项回归保留。必须对照旧开关确实复现误删。

从S4K2冻结四背景：保留对照、保留对照+恢复采购、自主组合、自主组合+恢复采购。每种关闭/开启新开关，共8配置。这样同时验证独立修正和恢复采购的长链协同；本轮不重复未触发融资的等价配置，原融资实现和历史结果不删除。
