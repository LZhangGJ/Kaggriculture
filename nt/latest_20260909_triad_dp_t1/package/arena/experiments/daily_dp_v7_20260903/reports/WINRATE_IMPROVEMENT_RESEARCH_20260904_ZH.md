# 如何提高对战胜率：现有实测与代码联合复审

2026-09-04。用户要求研究提高对战胜率；本报告复用已经执行的对局与当前源码，未新增事后Oracle、未读取真实未来供策略选择、未固定高手日历。它是研究结论和后续实验顺序，不是声称已经解决或保证达到90%。

## 一句话结论

重点应从“再省几个工人动作”转向“高价值项目的投产、产销、现金再投资与对手市场竞争联动”。但不能简化成“只加抢卖”或“把收益函数换成双方利润差”：这两种单独改法已有失败/弱改善证据。

## 1. 当前差距不是全部由卖价或浪费造成

重新核算两个背景×八个对手的1,600条已执行完整局（各50开发seed×双座位），逐项核对：

`销售收入差 − 商品采购差 − 种子差 − 动物投资差 − 工资差 − 土地差 = 终盘现金差`。

这里对手账目是离线证据，不能作为运行输入；同seed双座位不是两份独立随机环境。

共享版的例子：

|对手|我方终盘差额|草莓售出：我方/对手|草莓均价：我方/对手|草莓收入差|工资支出差|
|---|---:|---:|---:|---:|---:|
|G001|-635|179.08 / 281.13|161.02 / 155.10|-14,768|-1,863|
|G003|-12,202|201.99 / 259.24|167.14 / 158.16|-7,242|-274|
|Kaito V58|-5,861|195.59 / 265.10|176.84 / 164.80|-9,100|-455|
|Six-Day|-11,206|187.23 / 258.98|154.33 / 144.23|-8,458|+156|

七个难对手下，我方草莓均价都高于对手，但销售量都更少。这是数量/产能结构不足的共同信号，不是“草莓都卖晚、只要抢卖即可”。羊毛、牛奶也有收入缺口，其他产品有抵消，不能把每个负项都当作可独立收回利润。

工资差多为数百，G001甚至我方少花1,863，仍未赢够。因此继续只优化移动和工资，不足以解释或解决全部万元级差距。调度仍会影响投产和收入，不能由此证明调度已经最优。

同一G003对局，day index 11我方/对手现金约255/17,357；这个时点双方累计草莓出售都为0。早期现金缺口不能归因草莓卖价，也不能单凭现金少判定投资错误，必须连同已形成资产、随后产出及融资义务一起核查。不能照抄该日现金或后续草莓数量作为硬目标。

完整数字、逐日兑现、各产品量价算术分解见：

- `receipts/s4v_winrate_research_v1/TABLES_ZH.md`
- `receipts/s4v_winrate_research_v1/summary.json`
- 可复算脚本 `tools/research_winrate_gaps.py`

## 2. 哪些方法已经试过，不能再次包装成新突破

### A. 加强经营估值不等于更会赢

S3O把新增项目对已有组合售价的影响计入后，PASS约18.18万→18.66万，但没有全面提升八对手胜率。部分情况下我方增收、对手增收更多。

### B. “我方收益减对手收益”也已试过

S3P同日历模式2→3，G001约43.7%→38.7%、Kaito22.7%→17.7%。因此不能只新增利润比/分差权重。方向并非错误，但错误或过粗的产出、出售时间预测会使新目标选择更差动作。当前证据不能唯一归因其中一个误差。

### C. 更多候选和更多开关不自动增收

S4I组合表达扩大后曾大幅增小麦、减草莓，并退步；后来日历口径与开关边界已经修过，不能把修过的问题当成当前新发现。

S4V最新10,800实时局：共享版新补喂39.5%平均对旧39.25%；完整自主组合33.375%对旧33%。有局部收益也有对Kaito倒退，不能晋级。全开更弱，说明新估值/执行联动还没有兑现价值，不是全部能力开关已经充分实现的证明。

历史依据：`S3O_PORTFOLIO_CASH_REVIEW_ZH.md`、`S3P_PAYOFF_MARGIN_REVIEW_ZH.md`、`S4I_JOINT_PORTFOLIO_REVIEW_ZH.md`及S4V配对结果。

## 3. 源码里仍存在的决策范围限制

|环节|当前真实能力/限制|对胜率的意义|
|---|---|---|
|项目选择|日初选目标，新增项目分配给空位；组合搜索主要改空闲地块上的产业数量|不能把当前项目“何时停止、何时回收、释放哪些人力”都作为同等候选|
|收获|`jobs()`对动物按储量上限/将溢出/终局触发；持续作物主要按4份/将溢出/到期触发|有货不等于生成收获任务。高价窗口、融资需要可能发生在阈值前|
|回仓|有防溢仓、部分中途搬运、终局调度，但存在开关/启动条件|不能把一条仓内SELL建议自动视作已经有完整的收获→入库→售卖机会|
|市场预测|`competition_sales()`用当前双方公开产能粗估短窗口供给；已有库存是我方库存|不是按对手真实出售历史/单位搬运到达时间校准的供给到市预测；不应说完全没有对手信息|
|任务取消|现有共享插入主要保留旧任务，再插新任务|人手排满时无法做“少CARE一次，完成更有价值工作”的真实取舍；S4W只在隔离验证这一小部分|
|联动估值|已有日内/下一日条件推演及长期资产估值|不是完整未来；对手PASS情景、后续补种/维护/到货假设均需要校准，不能称精准胜率|

代码入口：`native/policy.hpp`的`choose_impl`、`jobs`、`competition_sales`、`new_day`；`native/joint_portfolio.hpp`的`compare_portfolios`；`native/day_consequence.hpp`。

以上不是要求删除所有规则。前置条件、真实资源、官方合法性和事务顺序仍必须保留；应该扩展的是可比较的经营取舍，而不是放任非法动作。

## 4. 建议优先研究的三条完整因果链

### 第一优先：投产与现金循环

比较不同合法产业规模、启动/延期、采购、雇工和可实际执行的前几天生产；评分必须针对能够真实启动的项目。特别核对“预测第一次收入到账的时间”和“实际可完成收获、入库及出售的时间”。

先调查已执行项目的预测偏差，不直接写死多种草莓或少养牛。重新配置时要计入已投入资产、未来必要维护、同一工人的其他任务以及融资链，而不是只比较商品现价或利润率。

### 第二优先：将市场窗口与收获、物流一起选

比较三个通用候选：

1. 保持原收获/出售安排；
2. 提前收少量、交给可接手的工人回仓，只出售需要的部分；
3. 暂缓收/卖，保留人员去做更有价值的生产或维护。

只能使用当前成熟货物、真实位置/库存、公开产能与历史。比较预期销售增量，扣除新增移动、挤掉的工作和资金机会成本。不能仅向已有订单追加SELL，也不能每次提前都强制全卖。

“价格会上涨还是下跌”必须先在多seed实际轨迹中校准：预测未来4/8/24步供给与价格方向，再事后检查预测误差。实际后续只用于检验历史预测，不得拿它在当前局选动作；观测价格变化还包含我方实际订单，不能当成假设改动作后的反事实价格。

### 第三优先：有收益依据的工人重新分工与任务撤回

完成S4W原型的机制判断。允许撤回低价值工作，但必须同步取消其相关承诺、释放资源，再比较保留和替换的完整后果。先验证是“可行候选缺失”还是“估值选错”，否则反复调优先级没有意义。

这条是前两条的执行保障，不是寄希望于修好4个逃跑局就能把全池胜率提高到90%。

## 5. 如何验证，避免继续低效率小补丁

1. 从多个对手、多seed的失败中确认同一类机会，并包含胜局和未触发局作对照。
2. 做机制测试：候选存在、成交和资源回写正确、行为开关有效；不追求每个资产终局都清零。
3. 将相关环节分别设开关，并保留完整因果链组合：例如“提前收获×接力入库×部分出售”，不能因单独提前收获无效就否定组合。
4. 用便宜的小型全八对手开发面板先看行为和方向；出现可信改进再扩大，避免一处很少触发的补丁直接重复上万局重型调度。
5. 最终仍须同一冻结版本、全八对手、多seed双座位、未见seed回归、官方1.32.7与线上CPU时延。近似置信区间、最差对手和回归同时报告。不能用平均现金/平均胜率替代每个对手超过90%。

## 决策

不建议马上继续扫利润权重、不建议直接转纯RL，也不建议继续只省移动。优先证明高价值项目是否真正按预测时间变成现金，并把市场决策贯穿收获、物流、融资、再投资。当前证据支持这个优先级，但没有证据保证一轮改动达到90%。

本报告未替换运行策略、未启动新大规模强度面板。S4V 已完整关闭且不晋级；S4W 隔离机制仍未通过；没有修改或取消原Goal。

## 6. 补充实测：原出售预测是否足够准确

S4X 对两个已有背景、八个实时对手、两个已用开发 seed、双座位重复了 64 完整局，耗时约73.8秒。控制器未被修改，双方终盘现金逐局等于原面板。只读重建的出售预测与原函数一致。

在当前有未排收获产品或原出售建议的相关时点，单位报价预测平均绝对误差如下：

|背景|产品|原预测误差|假设现价不变的误差|
|---|---|---:|---:|
|共享版|草莓|9.68|9.10|
|完整自主版|草莓|17.98|13.89|
|完整自主版|牛奶|20.80|17.20|

不是每种产品都更差：共享版牛奶、两背景甜瓜等原预测优于该简单基准。因此不能直接删除全部预测，或推出所有市场判断没有价值。应按产品、持仓和计划到货时点校准，先确认偏差源于产出量、实际到市时间、需求，还是本方实际订单。

两个背景都在多种产品上出现成熟、但当前未生成/安排收获任务的观察。然而这可能是合理的集中收获，不是已确认亏损；同一份货物跨步重复观察不得累加成“损失”。仅有乐观距离下界，不证明工人有空或提前收值得。

预测与后来实价的比较只用于检查历史模型，不用真实未来在当前时点选动作。本方实际订单也影响后来价格；价格下降比例不能解释成“抢卖获利率”。这64局只含两个已用 seed，不足以判定新的策略泛化或提高胜率。

收据和明细：`receipts/s4x_cash_window_audit_v1/acceptance.json`、`receipts/s4x_cash_window_summary_v1/TABLES_ZH.md`。脚本：`tools/audit_cash_windows.py`、`tools/summarize_cash_windows.py`。

## 7. “利润比”如何使用

可以作为解释指标，但不应直接替代终盘胜负目标。高百分比、规模很小的项目，不一定比低百分比但能及时大量变现的项目更好。工人和土地共用，不能把每项都分摊一遍固定工资再比较，造成重复扣费。

建议在同一当前状态下比较**相对保持原计划的新增净现金、最早到账时间、占用的瓶颈资源和下游资金缺口**。新增工人费用按联合任务确实需要的人数计算；已经付出的不可回收成本不能在继续/放弃选择中再次扣除。对手压价按到货时间和不确定范围处理，不将可见产能直接等同下一步出售。

最终仍以多 seed、双座位实时对战的逐对手胜率验收，利润指标只解释为何选择，不保证加分。

## 8. 进一步核账后：主优先级应放在可兑现的生产规模

复用同样1600局的生产账，逐商品核对守恒，无需再模拟。对G003的共享版草莓均值：

|指标|我方|对手|
|---|---:|---:|
|累计种植（含补种）|27.94|36.08|
|前10天种植|12.45|19.48|
|实际产出|207.70|259.24|
|售出|201.99|259.24|
|损失+终局残余|5.71|0|
|实际产出/累计种植|7.43|7.19|

七个难对手的草莓累计种植量都比我方多。G003、Boatlee、Kaito、Lynn下，我方单次种植对应的实际产出比值并不低；因此当前共同差距更接近生产规模/产业配置与兑现机会，而非每棵草莓都不会照料或大量收获后卖不出去。不能由此证明底层最优：它仍可能限制能启动多少项目，田间储量上限导致的未生成产量也不记为已经损失的实物。

必须避免错误补丁：“将草莓固定增加8棵”。对手的产业结构、投入、融资、劳动和市场反馈不同，不能免费复制其多出来的量。正确问题是：**现有投资比较为什么在许多对手下少启动这类项目？是现金/人力真不足、替代产业被高估，还是预计到款/可执行规模错误？**

这组新增证据把下一轮优先级进一步收窄：先核查现有项目扩产比较的预测与实际兑现，市场窗口—收获物流作为配套及第二实验，不把“提前收少量成熟货”当作解决主要数量缺口的唯一手段。表格与完整奶/羊毛/瓜数据见 `receipts/s4x_production_gap_v2`；v1亦保留。

## 下一轮最小可证伪实验（以第8节新增证据为准）

首先在真实当前状态中比较少量**完整可执行**的投资调整：保留原计划、新增一个生产项目、延期一个尚未投入项目以释放现金/劳动。不强拆已投入资产，不读取后续真实对手动作。使用现有资源和短期排程接口核查启动所需现金、实际雇工、最早收入到账，再审查原估值是否高估替代项目或低估该项目。项目种类由当前市场与资源决定，不能固定只加草莓。

配套针对已有投入形成的成熟产品，比较 KEEP / 提前少量收回出售 / 继续持有三种可执行方案，避免先扩张完整搜索空间。分别测试市场时间预测、可转交的收获—物流、部分出售及融资联动；保留组合测试。选择只看当前公开信息与自身账本，绝不读取该局未来或固化已知赢局动作。

若只是换了工人、提前了动作，却没有改变实际到账或后续生产，就不视作能力提升。若联合链条确实改变现金/产能，再扩大多 seed 八对手实验；否则回到项目生成与投产成本偏差，不无限追加抢卖阈值。
