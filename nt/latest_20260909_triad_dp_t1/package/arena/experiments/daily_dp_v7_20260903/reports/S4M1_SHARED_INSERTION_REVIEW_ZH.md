# S4M1：沿途共享调度与生产链联合复盘

2026-09-04。机制、7200场实时面板、4500场重复账本、官方和时延检查均完成。本轮不晋级。目标仍为同一冻结Agent对八对手逐一超过90%，没有达成。

## 1. 从证据到改动

S4M v1在64场当前政策的原样重跑中，没有发现保留原计划后可以直接补做而漏掉的任务，因此没有加入“任意放宽全部任务必须可完成”规则。

旧重协调把免费共享任务全部加在工人路线末尾，忽略途中空位。v2有插入机会，但初版诊断只保留材料动作顺序，还不充分。v3进一步保护原有收获后的入库承诺，约束施肥先于浇水，包括跨工人的执行时序；仍有64/64局出现机会。原政策逐场现金一致。机会频率每局约50–78个检查点；检查点重叠，不能累加当实际省步或收益。

新增 `shared_service_insertions`，默认关闭。在真实状态上重建剩余路线，在各工人的材料任务之间插入HARVEST/COLLECT/CARE/WATER等无材料需求服务。材料任务仍由原工人按原顺序承担；共享作业必须唯一、完整且在日内预算内；原本承诺入库的产品不能因改派而失去DROP。若先后关系或预算不满足，保留原安排。

新方案相对当前保留安排，只有覆盖增加或峰值/总动作更小时才接受。没有查询未来、复制高手时间表、调用事后Oracle或按对手身份路由。但其选择标准仍不是完整经济后果模型，这是未解决项，不能称为完成全部工人规划能力。

## 3. 组合效应与不确定性

单独共享插入几乎不改变胜率；与日内生产组合后，Boatlee +15、Lynn +11、Kaito +5个百分点，但Six-Day -8、G001 -2、Three-Day -3。更复杂的自主投资组合也没有全面加分。不能把不同背景或不同对手的最好格子拼成一个Agent胜率。

按seed聚类的近似95%成对胜率变化区间：Boatlee +15pp [-1.86,+31.86]，Lynn +11pp [-3.89,+25.89]，G003 +2pp [-1.92,+5.92]，G001 -2pp [-17.58,+13.58]。这些都是反复用于开发的N集，不是独立确认；没有证明稳定泛化增益。

对G001，组合新增我方现金5912.96，但对方现金也增加5430.33，平均分差仅改善482.63；19局由输变赢，21局由赢变输。对Boatlee，28局由输变赢、13局由赢变输。既不能把现金增长直接说成胜率提升，也不能忽略分布与双方市场交互。

这些是完整政策变化的成对实账，不是可以逐项相加的独立因果收益。特别是：

- G001收获动作更少而销售更多，说明不能以收获动作次数直接替代收益；产业、每次收量与时机一起变了。
- Six-Day多做项目、多收获，反而销售减少、工资和采购增加。不能继续写“有空闲就追加”或“多做动作一定好”的奖励。
- 局部调度接受时峰值较低，不代表全季一定少走路；新生产和跨日反馈可使全季工作量增加。
- 同一共享算法在自主投资背景下增益消失或退化，不能脱离上层经营目标评价低层调度。

这支持继续研究编排与经济的联动，但并未证明一项孤立的最短路径修复已解决弱点。

## 5. 当前决定

不替换原保留基线；保存独立插入分支及所有四背景组合，不使用O/P，不推Git或提交Kaggle。Goal继续。能力是否有用要看完整产销和竞争结果，不是省移动就算成功。

下一步从这组已形成的正负差异中，检查哪些被提前/延后的任务改变了实际维护、收获、入库、再投资与对手市场。运行评分中 `schedule_metric` 在完成同一工作集时只累加同样的 `job_consequence`；其时间变量没有产生经过验证的融资/销售价值。共享插入又按峰值/总步数选方案。因此仍缺乏让两套合法编排按真实经济后果区分的能力。应先找多seed实际偏差验证这一缺项，不能直接加“提前一回合奖励”或照抄某局的最优顺序。
