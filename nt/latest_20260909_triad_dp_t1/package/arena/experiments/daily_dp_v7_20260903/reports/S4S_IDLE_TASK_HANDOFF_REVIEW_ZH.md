# S4S：就地接手补齐一部分协作能力，但胜率未提升

2026-09-04。本阶段完成，不晋级。原Goal仍为同一Agent对八原始实时对手逐一超过90%，未达到。

## 复盘证据与实现

旧策略128场完整原样实时复盘中，86场出现潜在就地接手机会，1103条重叠记录中825条收肥、121条收获、112条施肥、33条浇水、10条喂养、2条播种。9条需要同回合前置动作刚完成，分布于7场。机会不是独立样本，也不代表全部安全或赚钱；不能把罕见同回合播种浇水当主要败因。

新独立默认关 `idle_task_handoff` 只转交原本已安排的无材料服务：水、照料、收获、收肥。接手者当前PASS且就在目标格；使用原规则的当前单位阶段前缀验证实际效果。保留其他单位动作、同地块前置顺序、有限作物浇水增产、去重与既有手动回仓承诺。接手后删除原工人该次任务，后续仍滚动按真实状态修复。不新增项目，不改变种类数量阈值，不读取对手身份或实际未来。

这是有限的任务所有权解锁，不是任意物资传递、联合空间布局或完整跨阶段规划。默认关，不替换基线。

## 为什么提前做事却没多赚钱

额外128场重复真实对战（64对开关匹配，不算新强度样本）中，36对实际触发87次接手，分布于79个局—日；动作序列有305步不同。

- 79个有接手的日子，日末我方地块状态全部相同。
- 52个日子，日末双方农场、我方库存、市场、商店全部相同。
- 仅8对终局现金不同，胜负变化0。

说明本轮主要把本来日内就能完成的工作提前或换人，并没有增加日末生产能力。工资没有随单步空闲减少而自动退款；产品如果还是日末统一回收，也不一定提前变现。不能由此推导所有工人优化都无用，但应停止将“少PASS、多执行几个动作”当成足够的改善。

上述只是实际匹配轨迹观察，不是重放真实未来挑最优，更不能凭日末可见物理状态相同就声称对手隐藏策略记忆也相同。
