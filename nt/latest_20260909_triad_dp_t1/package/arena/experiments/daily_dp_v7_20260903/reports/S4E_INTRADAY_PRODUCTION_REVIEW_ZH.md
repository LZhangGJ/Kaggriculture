# S4E：日内追加项目与已有生产并行

2026-09-04。工程验证通过，强度不晋级；八对手分别超过90%的Goal继续，尚远未达标。

## 1. 这轮修了什么

S4D已证明仅省路会把MOVE变成PASS，而不是更多产销。因此本轮增加两个独立开关：

- `intraday_admission`：原工作继续执行；有空闲工人、可用地块和未预留材料时，允许当天追加项目，不再一律等第二天。
- `intraday_procurement`：允许为追加项目采购缺少的种子/材料。关闭时只用已有物资。

新增候选覆盖五种作物和三种动物。先预留原任务所需的人员、地块、随身材料、shed材料及全局种子；将已发出但尚未结算的当前动作计入预留。只用已到账现金，原买入/HIRE报价先占预算；不虚增未成交SELL收入。最多10条市场订单。

不改变原工人当前步动作；新采购记录为待执行项目，下一步重新检查实际库存、位置、地块及当日剩余时间，满足条件才下发。保护新增任务的后续PICKUP材料不被出售。以后维护回到统一日常任务，不永久绑定一个人。

这不是完整的最优规划器：新项目初次部署仍由一个空闲工人完成，暂不新增土地或日内HIRE，也未实现完整的未来工资/地块机会成本估值。不能将八类候选有定义，等同于八类都在实战被采用或都能提高胜率。

## 2. 验证口径

- 4,372项机制检查通过，包括八类可表达、资源唯一预留、订单槽位、未成交不能开工、其他工人生产不中断、跨日重置。
- 8对手各4局官方1.32.7完整对局抽样，合计32局；6个专用迁移对手另有状态隔离测试，全PASS。它们是有限抽样，不是所有状态的形式证明。
- N=20262701–20262750，50 seed × 双座位 = 每配置每对手100局；PASS加8个完整动态对手，9配置合计8,100局。C++最多16线程，不使用固定对手动作流代替实时响应。
- 8,100局只读产销审计重跑，双方现金及overflow逐局与主面板一致，719步商品/种子/现金账全部对平。重跑不增加独立样本量。
- 关闭新开关的old、all_guard、all_midroute_net共2,700局，与S4D逐局双方现金、胜负、分差、overflow完全相同。
- 全部审计中，我方已发出单位动作无效果计数0、观察到的动物逃跑0。这不代表遗漏意图为0，也不代表经济损失为0。
- O/P确认与最终验收seed仍未使用；不能将开发集选型当独立确认。

## 4. 实际增加了什么生产

仅使用已有库存的模式平均追加1.34–3.58项（随对手变化）；采购追加模式12.29–15.76项，主要是小麦和胡萝卜。全组合追加9.49–11.46项，也是这两种为主。样本中没有观察到实际库存不足却被当成成交成功的开工。

八类机械测试均可生成，但实战新增鹅为0，牛羊仅零星出现。现有规模、现金、工时、空间和近似价值共同筛选了它们；不能据此判定新养殖一定不赚钱。

差额还包括种子、动物和土地，完整资金等式已经核对；表中不是完整公式。减少采购确实发生，但有些处理同时改变了更赚钱的产业、后续日期及对手市场收益，不能把“少买小麦”或“空闲工人不PASS”当成优化目标。

例如单采购追加对G003平均小麦产量+57.9，但草莓产量-27.9、草莓收入-4,658；对Lynn平均小麦产量+50.9，草莓收入-3,163、牛奶收入-4,707。它们是整组策略变化后的实账描述，不能拆成互相独立的因果损失，也不能据此写“禁止小麦”的规则。

日内追加不是只在最后几天发生：funded对G003/Boatlee/Kaito/Lynn的首个追加项目均在day0，对G001均在day2（零起算）；随后多数集中在day6–12，后期又有少量追加。早期变化会影响很长的后续经营链。

## 5. 组合与性能

按预登记将S4D省路与新增项目叠加，两个成对组合的全部对手胜率都没有变化。它们不再完全是终局现金零变化，但每组对强对手的平均现金变化仍只有约-57至+30元；全组合范围约-57至+2元，不能算有用的强度提升。

同一次N50面板、G001、16线程：old约773局/s，库存追加536局/s，采购追加514局/s，采购追加+交换334局/s；复杂all_midroute_net约99局/s，all_intraday约104局/s，再加交换约89局/s。100局短批受开销和状态分布影响，99→104不是已证明的算法加速。它们是完整局/s，不是transitions/s；官方抽样时延也不代替最终线上CPU部署验收。

## 6. 决定与下一步

不替换保留基线、不晋级、不做身份路由，全部配置和源代码保留。局部组合有改善，但没有同一版本普遍超过90%，甚至还不到50%。

下一步先验证一个具体的通用估值缺项：日内`propose`虽然预留了尚未完成任务的材料/地块，但调用`values(o, existing(o), {})`时，未把“已排入但还没PLANT/PLACE”的项目产量及后续承诺纳入新投资评分。这不是偷看未来，而是自身已经下达的计划。是否在实际亏损/增益局面中频繁发生、是否改变新增项目排序，必须先以当前状态和待执行动作审计，不能直接宣称根因。

如有充分触发，再用独立开关将已承诺项目加入条件估值，保留KEEP及原候选，做stock/funded与多人组合的实时整局对照。不能将它变成固定日期/种类阈值，也不保证修完就能跨越强度差距。若缺项很少触发或不改变选择，不浪费整轮强度扫描。
