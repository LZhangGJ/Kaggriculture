# S4N1：未来用工成本接入日内生产——有微小信号，不晋级

2026-09-04。完成一轮实际改动、机制、官方回归、开发集及冻结后未见集复验。Goal继续active，没有达到八对手逐一>90%。

## 1. 为什么改、实际改了什么

S4N的64组成对逐步复盘中，62组第一次市场分歧是买种子而非卖货。共享调度改变空闲人员→日内项目选择不同→长期产销不同。源码的日内项目估值没有把新增维护工作与全农场未来工资一起算。

新增独立默认关开关`intraday_future_workforce`。对原局部选择器每个产业的最佳可执行单位/地块代表（最多8项）及KEEP，比较真实在田项目与已安排空地项目的条件未来人员成本。复用已有作物日历和日期任务pack，替换粗略的单项目动作费用，避免重复计费；当前已雇工不重复算工资，当前现金/预留/市场槽位/deadline不变。基础或新增预测不有限时回退原评分，不强制删除路线。启发式pack产生负边际工资时按0，不能凭追加任务获取虚假省薪信用。

没有改开局、模拟器、对手或任何固定seed路线。没有事后Oracle。也没有解决全部自由布局、未见未来资金短缺、不同收货时点或完整经营机会成本。此处未来日历仍是条件情景，不是实际未来。

## 4. 必须结合工人、生产、现金解释

N50共享组合里新增项目平均少约0.0–0.6个，工资通常少17–75，但总现金增益大多只有几十到几百；并不是省工资就必然多赚钱。例如G001工资少46.7但销售少222.5，现金反而少77.8；胜率仍多1场，因为胜负取决于双方资金分布，非我方平均现金单指标。

O50静止对手更能说明问题：

- 日内项目10.52→10.29个，全年工资5640.80→5653.13，并没有在实际闭环中保证省薪。
- 小麦额外采购支出+531.51，说明局部项目改变还影响后续饲料现金循环。
- 牛奶销售收入-2498.07，销量仅-2.4。逐场做精确算术拆分：按原成交均价计的数量部分-376.82，实际成交均价部分-2121.25。
- 草莓销量+3.99，销售额却-92.33：数量部分+996.97，成交均价部分-1089.30。羊毛多卖3.35、收入+814.02，抵消一部分亏损。

这些是逐场销售账目的算术分解，不是因果实验。成交均价部分同时含出售时机、自己供给变化、数量冲击等；不能就此硬写“牛奶提前卖”或“草莓晚卖”。但足以否定“主要只是工资估算不足”的单因素解释，也不能用更多产量、动作数或更少雇工当目标。

## 6. 下一步通用方向

不继续扫劳动价格或增加固定作物阈值。下一项应补真正的“同一工作集，不同执行/入库/销售安排的后果比较”：

1. 从真实日志定位当前已有产品、库存空间、待购资源与未完成任务的现金/物流瓶颈；优先筛选多seed重复出现的情况。
2. 比较保留安排、提前交付再继续、分批交付等合法多人安排，必须保留资源因果和材料归属，不把整段任务再次锁死给单人。
3. 评分按可核对的短期仓库/现金/融资状态变化，并把尚未兑现收益分开；不得直接加“早一回合奖励”。未知对手未来只做公开状态条件情景。
4. 特别不要重复S4C：现有中途卸货只在预计日末溢仓触发；其货值/额外步数评分并非投资融资与销售窗口比较。`schedule_metric`仍对同一已完成工作集给相同价值，不能用本轮新增用工估值宣称已解决第四项能力。

这是待验证的下一方向，不保证实现后能上分；若没有重复瓶颈证据，不能追加新运行规则。
