# S3L：采购成交与人员编排衔接，实验前记录

2026-09-03。先做只读诊断，不假设减人一定有利。当前new_day先用所有目标任务估算雇工，再通过funding/admit缩减买单；编排时才根据实际库存reserve。两者可能导致为未获资助项目雇人，也可能只是正常必要冗余。

增加编排开始时的离线探针：计划/可供料任务数、缺种子/饲料/肥料/动物、已买待放置动物、实际人数、在同一剩余时窗内用相同任务重新分配所需最少人数。最少人数来自现有greedy+insertion编排，不是数学全局最优。按官方雇工阶梯报价计算潜在节省上界，不直接当成实际收益。

探针复制控制器后调用jobs/reserve/pack，不修改运行中的控制器、环境、随机事件或对手。当前policy.hpp不变；原8对手完整策略不变。先对A开发集全部8对手和PASS各100局，并逐局核对旧面板现金/溢出。最终验收集不使用。

若主要是缺料导致计划被过滤，再测试“采购能力与人数共同决定”的通用改进；若缺料/人数差异很小，则排除该主因，不为它追加大量运行分支。不得按对手身份改变参数。最终目标仍是同一v7 PASS18万、八对手分别90%，该诊断本身不是交付验收。

## 初诊后、对战前的机制冻结

900局原配置审计通过，现金和溢出与旧面板逐局相同。每对手均约17–20天/局可用更少人数完成相同已供料任务，报价差约1,658–1,873/局。这个指标混合了任务筛减、实际市场准备时间变化和更强的插入编排，不能全算为某一个原因。

先单独检验其中已有代码的编排能力不一致：estimate原先只试顺序追加，compile在放不下任务时却会试insertion。在雇工报价阶段也尝试同一个insertion fallback；只有找到全部输入任务均可排入的解才允许降低估计人数。保持任务/优先级/开局/资源和市场策略不变，默认关闭，避免把“删任务省人工”当改进。

配置仅hire_base和hire_insertion，两项冻结后跑ABC每个配置对每个对手300局。如果呈现通用改善，再在预先确定的D（20261701–20261750双座位）确认；D一旦跑过即列开发，不能冒充最终验收。不继续扫描人数上限或逐对手阈值。
