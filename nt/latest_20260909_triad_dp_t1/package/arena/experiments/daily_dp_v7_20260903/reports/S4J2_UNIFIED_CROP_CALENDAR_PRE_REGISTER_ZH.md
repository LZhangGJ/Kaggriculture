# S4J2：新项目与已有作物使用同一份条件日历

## 证据与改动边界

S4I 的组合规划出现更多小麦、更少草莓、较大期末收入损失；S4J1 确认新项目预测多茬，而已有作物主要预测当前茬。前者是实战现象，后者是实现不一致；尚不能断言修复后必然上分。S3K 的续种总量加权已失败，不再扫描该权重。

新增独立开关 `portfolio_crop_calendar`，默认关闭，仅在组合规划器内使用。新种与已有作物均通过当前 `Controller::jobs` 的种植、施肥、浇水、收获、翻种语义，生成按日的产物交付、种子支出、肥料消耗和劳动日历。已有库存、产物和动物不得重复计入。只读取当前可见状态和冻结的当前报价；不读未来 RNG、对手订单、隐藏库存或身份。

这是充分供给、无未来杂草、维持同种作物的**条件预测**，不是模拟器真值或已拥有资产。资金在未来是否足够、真实物流拥堵及对手扩产仍有误差。已有项目续种成本被记录；比较不更改已有项目的新增方案时，基线共同成本相消，不可声称已完成未来现金可行性验收。

## 先完成的机制门

1. 五类作物、不同浇水/翻种/施肥开关：从合法采购后的官方 C++ 状态开始，按相同日内任务执行，与预测逐步比较作物状态、种子/肥料消耗、收获量和可入库日期。测试不使用事后挑选；关闭随机杂草的假设必须明示。
2. 合法的 PLANT→WATER 前后表示：尚未发生的产出及维护一致；已支付种子不能再次当作初始购买。 finite 初始 yield=1、ongoing=0，不能使用非法合成初值。
3. 终局不虚构下一天收入；已持有产量只计算一次；日内腐坏和当日来不及收集必须减少兑现量。
4. 旧开关关闭回归；S4J1 保留固定开局的边界测试继续通过。条件日历不向真实账本注入任何资源。

## 预先冻结的实时矩阵

每个执行背景 `intraday_funded`、`all_intraday` 各保留六格：原对照、自主开局对照、组合规划、组合规划+自主开局、组合规划+统一日历、组合规划+自主开局+统一日历。合计12格。

每格对 PASS 和全部8个真实对手，N50（20262701–20262750）、双座位，合计10,800局；最多16线程。N 已是开发集，不能作为未见验收集。O/P不动。报告每个对手的胜率、现金和按 seed 聚类的差值；重点比较统一日历开/关的同背景同开局，而不是只与最弱组比较。

先做耗时探针和官方迁移一致性，再进入矩阵。关闭组合规划的四格应与历史对照逐局一致。新日历四格重复做真实现金/产物流向审计，保留无收益及退化结果。耗时明显不合理时先进行不改变预测结果的复用优化，不通过删掉经营分支提速。

## 晋级

这轮仅为通用一致性修复验证；任何不足以提升全池的变体均不晋级。不把某个 seed 最优参数、路线或强对手身份写进策略。只有稳定候选才使用未见 O/P 复验；最终仍要求同一冻结 Agent 对8个对手逐个超过90%，并完成官方与线上时延验收。
