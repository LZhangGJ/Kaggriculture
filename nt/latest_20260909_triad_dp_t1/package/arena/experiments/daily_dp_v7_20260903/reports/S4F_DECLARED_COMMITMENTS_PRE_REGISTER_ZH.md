# S4F：已承诺未开工项目是否被日内投资估值漏算

2026-09-04，尚未实现或取得实验结果。承接S4E，不开启新的目标，不回到Candidate事后Oracle。

## 为什么检查

S4E新项目能够真实开工，单采购版平均每局12–16项，8,100局实账未观察到已发出动作无效果或动物逃跑；但没有普遍改善胜率。减少饲料外购可能伴随其他收入下降，不能再把“忙起来/省钱”当成功。

代码可以确认：`intraday::propose`统计未执行动作的资源和地块预留，但`values(o, existing(o), {})`只看到已落在真实农场上的项目，没有把仍在其他工人计划里的PLANT/PLACE作为已承诺产能。原日初生成器逐个选项目时反而使用了`selected`来抑制重复投资。

这是条件估值缺项，不是官方合法性错误。它是否在真实选择时显著发生，以及补上是否能提高胜率，现在UNKNOWN。不得事先叫它主要败因。

## 先进行的只读机制审计

在S4E冻结的stock、funded和all_intraday实时轨迹上，读取当时我方真实状态及尚未执行的计划，统计：

1. 新投资可选时，哪些工人已经承诺PLANT/PLACE，但地块尚未完成相应建立。
2. 当前步已经发出但尚未结算的动作也只计一次；已完成项目不能重复计算。同一地块及同一行动不能被两个账本重复记。
3. 仅将这些已排入的自身承诺转为条件产出、材料/饲料义务，比较原评分与补记后评分的排序变化。它们不是保证产出，更不能作已经到账的现金。
4. 审计前后实际发出的动作、完整局双方现金和overflow必须完全不变；不续跑额外终局分支，不生成事后赢家标签。

使用N50、多对手、双座位；抽取的是当前合法可见状态，不输入对手私有库存、身份、实际未来或Replay后缀。先观察触发数量，若罕见或不改变可选项，不直接跑大规模参数扫描。

## 有证据后才实施的独立开关

候选和可行性不变，仅用已有承诺校准新增项目的条件估值；不能因此永久禁止某产业或加入固定日期阈值。仍保留原评分/KEEP回退，实际成交按下一步真实状态处理。与库存追加、采购追加及多人组合分别对照，不能只测一个最有利seed。

所有比较仍用C++完整实时对手。先机制/官方抽样，再冻结配置做成组开发测试；任何选择所用seed属于开发集。O/P暂不用，直到出现真正值得确认的统一候选。胜负目标仍是同一Agent对8对手分别>90%，不是挑每个对手不同配置凑表。

## 不要夸大的边界

- 修补待执行承诺，不等于完成未来多年利润、工资、售卖时机或地块机会成本估值。
- 日内新建项目仍使用有限候选和原底层编排，不表示全局最优。
- 即使评分变化很多，也必须由实时整局收益和胜率决定是否保留。
- 不自动重试旧的S3J饲料权重扫描、S3L少雇工、S3W资金周转排名；那些已有多seed失败证据。必须提出新的机制差异。

## 只读证据之后、强度测试之前的冻结决定

`receipts/s4f0_declared_N50_v1`完成三配置×九对手×100局=2,700局，1,941,300步开关检查/关闭检查的动作完全相同，终局和overflow与S4E逐局相同。补记后确实改变同一可行候选集合的选择，但单采购版G001仅2/100局有变化，全组合对强对手约5–21/100局有变化；不能当作解释全部弱势的根因。

只增加`intraday_declared_value`一个独立开关，复用原有日初selected产能评分语义，不同时改饲料权重、预算、产业限制或日期。新计入的条件产能仍不进入实际cash/shed/seeds，实际成交保护不变。

进行一次有限的6配置N50实时对照：stock开/关、funded开/关、all_intraday开/关，共5,400局。没有新参数网格。因为第一处分歧只可能出现在只读观察到的改选局，这一单项本身不可能把本批G001直接升到90%；目的是判断它是否值得保留为后续大幅改善经营组合的基础，不能继续在这个小缺项上无限微调。
