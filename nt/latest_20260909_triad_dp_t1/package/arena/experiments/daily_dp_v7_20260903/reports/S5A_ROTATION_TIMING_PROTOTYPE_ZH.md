# S5A：转产时机与整场净收益——隔离原型验收

日期：2026-09-04。结论：机制原型通过；**未接生产版、未获得新的实战胜率，不能晋级**。原 Goal 继续 active。

## 用户补充与修正后的研究方向

高手存在换产业行为，不能因为 S4Z 的轮作试验退步就否定转产。必须把“选什么”和“何时做”分开比较：现在调整、延后调整、保留原经营、收完后不再投入。当前价格低并不自动意味着应该转产，也不应该把一次低价写成固定产业切换规则。

羊毛转草莓需要区分停止新增羊、将新增土地与人手投向草莓、减少部分维护、计划退出等不同含义。已有羊不能正常卖掉直接换成一棵草莓。**本原型仅解决成熟有限作物收获后的换种，不声称已实现动物退出和草莓投产的联合决策。**

## 问题证据

S4Z 的同10开发seed双座位实战中，完整自主轮作 PASS 现金163,072→185,757，但八对手平均胜率35%→17.5%。草莓收入增加同时伴随麦生产下降、商品采购增加、奶/羊毛收入下降。见 S4Z 报告，不能把各渠道差额当成独立因果效应。

旧 `rotate` 用单项目 `values()`，空地投资另有组合估值。这是具体的估值口径分离；修统一口径是否能提高胜率仍需实测。

## 已实现的隔离原型

文件：`native/rotation_portfolio_prototype.hpp`，没有被 `policy.hpp` 或生产模块 include。

1. 换种现金日历明确区分旧作物收获与新作物种子：旧小麦仍计为小麦，不能计成新草莓。
2. 替换已有地块的未来日历，不能同时保留旧产能又叠加新产能；重复地块直接报错。
3. 合并整座现有农场的产出、自产饲料、肥料需求、库存、种子和共享未来用工；现金可按销售、采购、种子、工资复核。
4. 已拥有的种子、小麦和已付当日雇工不重复收费；不重新扣已买动物/土地的历史成本。
5. `not_before` 明确投资开始日：先照常维护并收获旧作物，之后空置等待，再种新品种；不是把已种作物直接销毁。30表示本局不再新种，仍保留旧收获。
6. 继续保留当前公开市场、可见对手产能与城镇需求的条件预测；没有输入真实未来、对手私有库存、对手身份、录像或seed。

原型没有改成某日期必种草莓、羊毛低于某阈值必放弃羊。试验日期只存在于机制测试夹具。

## 实际验收

- v1：测试代码同一 `auto` 声明了不同类型，编译失败；日志与源快照保留。
- v2：修复测试声明；12,557项断言通过。
- v3：追加延期与停止投入语义；**12,562项断言通过**。编译约4.72秒，测试约0.0065秒。
- 包含1,080种同作物状态与原预测器回归、15种有限作物→五作物的原生单日收获/换种验证，以及资源守恒、唯一地块、饲料净额、共享工资、旧资产收获保留等检查。
- 确認一个明确时机例子：第19天种草莓仍能收到终局前产品，延至第20天则错过该收益；不是说实战应该固定第19天种。
- `receipts/s5a_rotation_mechanisms_v3/acceptance.json` 及源快照为本轮收据。生产源码哈希全部与 S4V 一致，生产二进制仍 `074c98bd83cf8aa47cd227f050033dbb05d4617dac6b137bb3dbb9c7ae40debd`。

**12,562是机制断言，不是12,562局官方实战。** 原生单日验证也不能替代新策略的官方完整局一致性和独立seed强度验证。

## 已知边界，不能夸大

- 这是“已知状态、维护成功”的条件预测，不是终局现金真值；未来新商店、杂草与对手实际交易未知。
- 当前只评估已在场资产，不包含全部准备中但尚未成交的投资；接入前须把实际采购投影和新项目承诺统一加入，不能估值一套资产却执行另一套。
- 当前日成本/工作量是日级估计；实际人员位置、领取材料、旧收获→新种植次序和当前资金可行性必须由真实准备/调度检查，不能只凭预测为正执行。
- 将来延后投资需要持久计划、真实成交回写、受影响项目重规划，当前原型没有把这一计划装入正式 Controller。
- `wages_on` 是现有共享未来用工估算，尚不是完整精确的跨日多工人调度。
- 动物退出、减少维护与新作物投产的联合时机仍未实现。

## 下一步

先在真实开发盘面只读检查 KEEP、立即换、延期换与停止新种的估值差异，拆出收益来源及首次到账时间。随后只接入通过当前资金/人员/旧收获保护验证的独立开关；在原八个实时对手、多seed双座位上做独立与组合实测，再用未见seed验证。

最终优化的是胜负及整局现金差，不是作物单品收入、利润率、动作数或某条事后最优路线。不得将原型预测排名称为实际胜率改善。
