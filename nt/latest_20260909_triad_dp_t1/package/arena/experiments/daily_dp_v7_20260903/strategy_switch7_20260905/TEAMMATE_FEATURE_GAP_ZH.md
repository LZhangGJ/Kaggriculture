# 队友147维与S9 146维特征审计

## 结论

不能声称完全复刻。S9逐位复用了队友147维中的前129维，删去了其固定动作路线未来24/48/72步的18维计划特征，加入17维动态控制器状态，得到146维。

## 已完全相同的129维

- 我方和对手公开农场：现金、hand、土地、当日雇工、杂草、空格、五作物/三动物/设施数量与产量、作物和动物压力，共54维。
- 我方私有且官方观察合法提供：shed12、种子5、单位携带12、shed/carry合计及余量3，共32维。
- 公开市场18、商店8、step/day/hour3，共29维。
- 我方与对手公开历史统计各7，共14维。

合计54+32+29+14=129。S9的`local_agent.py`直接调用同一个`route_switch_vector(..., route_actions=None)[:129]`，不是近似重写。

## 队友有而S9没有的18维

每个未来窗口24/48/72步各6维：预计支出、最大资金需求、现金余量、计划雇工、扩地、买动物。合计18维。

队友从固定路线动作带直接扫描这些市场动作。S9没有固定动作带；它只有每日经营recipe，工人和市场动作会按真实状态动态生成。因此直接传入某条固定动作带会产生错误语义，不能以“维数相同”冒充完全复刻。

## S9替换加入的17维

- 当前经营目标12：五作物、蛋/奶/毛/肥料、鹅/牛/羊。
- 控制器阶段、市场队列长度、计划土地、饲料库存目标、累计recipe缺失5。

这些说明控制器当前打算做什么，但没有显式量化未来三天资金是否足够，所以不是队友18维的等价物。

## 正确迁移办法

从当前动态计划和真实未完成义务编译未来1/2/3天的预计市场事务，再生成与队友语义对应的18维。不可读取真实未来商店、随机事件或对手私有库存；预测失败后按实际成交回写。

第一版应保留当前17维，形成164维，而不是删掉已有状态。必须单独消融：146维基线 vs 129+动态计划18=147维 vs 129+18+17=164维。模型、种子、候选和检查日相同；只有新holdout增益才能保留。

进一步的候选级可行性（例如每条后缀自己的资金需求）不是队友原147维；若加入，应视作新能力并与上述复刻消融分开，不能混报。
