目的：只判断当前失败是否主要因为漏掉队友最终节奏中的第7天。队友最终检查step `[144,168,216]` 对应0基第 `[6,7,9]` 天；S9已有6和9，缺7。

固定S9开局38、五后缀、146维合法可见特征和动态执行器。训练/开发仍用S9的TRAIN/SELECT，只补第7天真实前缀反事实；这是开发数据，不冒充新独立验证。第7天同时比较普通分类树和利用完整反事实收益的策略树，并与原第6、9天树组成首次切换锁定序列。

若开发配对增益下界不大于0，直接停止，不打开新holdout。若为正，先冻结规则，再用32个跨大范围随机新seed、双座位、七实时对手测试6/7/9，C++完整执行必须与反事实表逐局hash、现金、目标、切换日一致。不得根据holdout重选。

只有holdout增益下界为正且最弱对手不退化，才能作为增加第7天的证据。否则再考虑3/4/5/6/7/9；不能因为0–28事后Oracle更高就直接上线每天切换。
