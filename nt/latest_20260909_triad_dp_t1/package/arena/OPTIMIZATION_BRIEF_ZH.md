# 给GPT的综合优化任务与证据边界

目标：结合本包GPT两版、我们的经济规划/底层执行，以及七个强对手的可靠能力，改进自主动态规划Agent。不要仅把它改成G001专用克制器，也不要把某单seed的事后最优日历写成通用规则。先保留全部基线；分步修改、开关消融及组合消融，用多seed双座位七个实时对手复验。最终希望逐对手90%，但目前远未证明可达，不能编造达标。

## 三种方案到底是什么

- GPT V1：逐日经济估值；作物周期DP；局部小任务集合路线优化＋顺序分配工人；每步根据实际状态执行。没有读取对手农场；市场价格/商店是动态输入。
- GPT V2：现金/地块约束下的离散投资组合比较；作物与动物现金流预测；工人路线插入；容量分配。仍无对手公开农场的直接输入。不是V1所有能力的严格超集。
- 我们的运行核心：`native/policy.hpp`含上层投资与目标生成、布局/任务/人员编排、动态执行与恢复；独立头文件扩展融资、协作、轮作、实际效果等。存在历史兼容和很多开关，不能把“有字段”说成“已有效”。最新J7_03另外叠加29日语义配方，不是预录719步原子动作，但也是固定宏观计划，不是完全自主经济规划。可与ours_base、ours_autonomous对比。

## 已确认的问题，和仍需验证的假说

1. **V2存量作物估值遗漏实际yield_units。** 真实seed61010/seat0/step408草莓从yield2改到0，未来预测数组完全不变。见semantic_probes.json。执行HARVEST读真实产量，问题在上层估值，不是引擎凭空多收。
2. **V2融资现金投影过于乐观。** 用数量×当前价代替逐件出售压价后的总收入。合成测试羊毛库存10000、卖100：投影20,000，官方对PASS实际7,969。该例是机制探针，不声称自然败局恰好卖了100件。可能导致后续买入静默失败，须跟踪实际成交。
3. **V2部分计划按请求而非成交推进。** 土地请求后递减计划的代码，应核实失败后的重试/局部恢复；未证明所有实战败局因此发生。
4. 两GPT版本对手产能、上市时机缺少直接输入，这是代码事实。它们因市场改变而间接响应，但不能直接估计竞争者将增供多少。具体导致多少损失尚未做因果消融。
5. 更一般短板可能是经济决策与底层承载能力不一致：项目账面利润为正，但采购时序、人员到位、维护、产品兑现和再投资未共同兑现。请以首个可核查偏差及配对修复收益验证，不能因输钱就默认是低层问题。

## 希望怎么改

先跑通验收，复盘GPT两版和本地基座在相同seed/对手/座位的输局；区分估值错误、订单成交错误、人员产能不足、时序/物流损失与合理经济取舍。优先解决能用官方规则证明的硬错误。其余改变设计成开关，以3–5个可解释候选起步，同时测试单改与协作链叠加效果。

一个投资候选应同时得到可执行的人员/路径/资源安排，再比较预期净现金和风险；不把每个作物生命周期绑定一个固定工人，不强制下一步浇水，不把计划性放弃全部视为错误。维护时间以官方deadline和收益权衡为准。

禁止使用真实未来随机种子、对手私有库存、对手ID或离线终局标签作为线上特征。续跑可以用于离线比较，但不得把事后上限称为在线Agent胜率。不同随机seed本身通常不同当前局面，不冒充同一局面的多未来实验。

保留旧源与配置，修改副本；每次用新输出目录。61020–61029是公开给你的开发复现集；最终验证必须先冻结方案，再用未参与调参的新seed，逐对手报告胜率、现金差、异常、关键经济损失和本地耗时。如果改C++，必须重编译并核对官方。4核机器无需大扫参数，更不能伪造高速/胜率。
