# Candidate8 O1.6：45 场败局的上限缺口归因

日期：2026-08-31  
状态：**AUDIT COMPLETE / 不接入正式 Agent**

## 1. 一句话结论

O1.5 的 45 场败局中：

- **9 场（20.0%）**可以靠扩大候选枚举或搜索宽度救回；
- **0 场**发现已测量的硬执行错误；
- 剩余 **36 场（80.0%）**即使继续显著加宽搜索仍然输，但同一局面在冻结的 178 条完整路线中全部存在获胜路线。

因此，主要瓶颈不是模型“不会从现有候选中挑”，也不是 Beam 太窄或执行器卡死，而是：

> 当前 Candidate8 没有提出足够好的完整经营计划，或者软计划编译器无法把有潜力的高层计划高效兑现成一整局经营动作。

这两者还不能仅凭本轮数据完全拆开；下一步必须做“强制语义计划 → 当前编译器”的对照实验，而不是继续盲目加模型、加样本或加 Beam。

## 2. 冻结边界

本轮只使用 O1.5 在实验开始前已经冻结的 45 个三阶段非胜案例：

- 对手：冻结的 17 个强敌集合中产生败局的 15 个；
- seed：`10971001`、`10971002`；
- 双座位；
- 决策日：第 6、12、18 天；
- 基线：Beam 16、每节点最多 32 个候选；
- 目标：真实终局胜负优先，其次分差和自身现金；
- 真实未来只用于事后 Oracle 诊断，不是可部署推理方式。

没有修改正式 Agent、候选语义、执行器或 O1.5 数据，也没有训练和提交。

## 3. 归因方法

### 3.1 基线序列复放与硬执行检查

把 45 场 O1.5 选出的三阶段序列重新提交给 committed executor：

- 45/45 终局收益逐分完全一致；
- `end_overflow = 0`；
- `avoidable_crop_losses = 0`；
- `avoidable_animal_losses = 0`。

因此没有发现这三类明确硬伤。这里的“无硬伤”只表示没有溢仓和已定义的可避免作物/动物损失，**不等于经济编排已经最优**。

### 3.2 搜索宽度消融

在相同 45 场上，只改变候选臂数或 Beam：

| 配置 | Beam | 每节点候选上限 | 案例 | 救回胜局 | 相对基线平均分差改善 | 耗时 |
|---|---:|---:|---:|---:|---:|---:|
| arms64 | 16 | 64 | 45 | 5 | +2,667 | 169 秒 |
| beam64 | 64 | 32 | 45 | 2 | +1,030 | 252 秒 |
| combined32x64 | 32 | 64 | 45 | 7 | +3,497 | 329 秒 |
| arms128 | 16 | 128 | 45 | 8 | +4,728 | 299 秒 |
| arms256（只跑 arms128 未救回者） | 16 | 256 | 37 | 0 个新增 | +3,717 | 344 秒 |
| beam64+arms64（只跑联合未救回者） | 64 | 64 | 36 | 0 个新增 | +2,690 | 539 秒 |

`arms256` 的 111 个阶段候选池中只有 3 个仍触及 256 上限，说明它已经接近完整枚举当前候选语言；但没有再救回一场。`beam64+arms64` 也没有救回剩余 36 场。

所有宽度配置取逐局事后最好结果后：

| 指标 | 结果 |
|---|---:|
| 基线 45 场平均分差 | -13,771 |
| 宽度消融逐局事后最好平均分差 | -7,901 |
| 平均改善 | +5,870 |
| 最终救回 | 9/45（20.0%） |
| 仍失败 | 36/45（80.0%） |

说明候选截断确实存在，但不是 45 场败局的主要来源。单纯扩大 Beam 的独立贡献尤其小：Beam 64 救回的两场也能被其他宽候选配置救回。

### 3.3 178 条完整路线的事后参考上限

对每个败局，用同 seed、同座位、同对手，逐一运行冻结的 178 条完整路线：

| 指标 | 结果 |
|---|---:|
| 至少有一条路线获胜的案例 | 45/45（100%） |
| 每场最佳路线平均分差 | +37,196 |
| 最小最佳分差 | +12,457 |
| 最大最佳分差 | +110,292 |
| 宽度消融最好结果距完整路线参考上限 | 平均仍差 45,098 |

这证明这些局面并非不可赢，对手骨架也不是绝对压制。缺失的是把当前动态规划器带到这些高价值经营轨迹附近的能力。

完整路线池是事后、身份可知、真实未来诊断，不是可部署路由器；它只用于证明“同一局面存在强路线”。

## 4. 最终归因

| 归因 | 场数 | 占比 | 证据 |
|---|---:|---:|---|
| 候选枚举截断 | 2 | 4.4% | 增加候选臂即可救回，扩大 Beam 本身不需要 |
| 搜索宽度混合问题 | 7 | 15.6% | 多种候选/Beam 加宽配置可以救回 |
| 已测量硬执行失败 | 0 | 0% | 45/45 精确复放，无溢仓、可避免作物或动物损失 |
| 语义候选缺失或软编译兑现不足 | 36 | 80.0% | 近完整候选枚举和更宽 Beam 仍输，但完整路线池 36/36 可赢 |
| 参考路线池/基础骨架不足 | 0 | 0% | 178 条完整路线对全部 45 场都有获胜路线 |

按对手观察，9 场宽度可救回主要集中在 `G001`、`G005`、`G010`、`G038`、`G185`；`G002`、`G003`、`G004`、`G009`、`G031`、`G049`、`G092`、`G136`、`G194`、`G245` 的败局没有被本轮宽度消融救回。

## 5. 不能从本轮得出的结论

本轮不能宣称：

1. 当前低层执行器已经达到高手水平；
2. 只要新增一种 Candidate8 family 就能解决 36 场；
3. 178 条路线中的最佳路线能够在线被识别；
4. 更大的 LGBM、Transformer 或更多 O1.5 样本会自动补上表达缺口；
5. Beam 64 + arms 128 及任意更大组合绝不可能再救回案例。

本轮能确认的是：继续只加宽现有搜索，边际胜局已经明显饱和；它不值得成为下一项主工程。

## 6. 下一步唯一优先项

做 **O1.7：强制语义计划兑现测试**。

对剩余 36 场逐场取一条已知获胜完整路线，只抽取第 6、12、18 天可公开推导的高层语义里程碑，例如：

- 各产业目标规模和投产时间；
- 工人、土地和设施容量；
- 买入、融资、出售窗口；
- 需要延续或停止的项目；
- 当日关键事务顺序。

然后把这些里程碑强制交给当前计划编译器，不播放 719 步原始动作：

- 若编译器能够接近参考路线收益，缺口主要在候选生成；
- 若编译器仍明显掉分，缺口主要在计划兑现、多人调度或事务链；
- 若两者都有损失，再按“候选覆盖率 × 强制计划兑现率”量化拆分。

这是在增加新模型或继续 Self-play 前，最便宜且信息量最高的一步。
