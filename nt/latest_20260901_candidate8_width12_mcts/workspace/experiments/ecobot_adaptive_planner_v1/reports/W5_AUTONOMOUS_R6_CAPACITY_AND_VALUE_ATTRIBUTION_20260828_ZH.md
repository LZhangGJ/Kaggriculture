# W5 自主规划器 R6：产能搜索与价值归因验收

日期：2026-08-28  
结论：**部分通过。R6 保留为可回滚 Challenger；停止只靠参数微调继续搜索。**

## 1. 本阶段验证什么

本阶段没有使用 G001 经营日历，也没有按对手身份选择路线。Agent 只读取当前公开状态，由 C++ `NativeAdaptivePlanner` 自主决定经营结构并完成整局。

目标是回答两个问题：

1. R5/R6 的逐单位项目分配器是否还能通过参数搜索稳定跨过平均 `130,000`；
2. 若不能，瓶颈究竟是某个阈值，还是规划器缺少完整项目组合能力。

所有纳入结论的批量实验均使用：

- 队友 `fast_kaggriculture` C++ 1.32.7；
- `OMP_NUM_THREADS=16`、`OMP_DYNAMIC=FALSE`；
- 固定且互相隔离的事件种子；
- 双座位；
- 无非法动作、可避免作物损失、可避免动物损失和终局溢出作为安全诊断。

第一轮未完成的任务曾错误占用约24个 CPU 核心，已在产生收据前取消；下表所有正式数字均为固定16线程后重跑。

## 2. R6 基线

R6 在 R5 上只保留经过受控消融确认的产能调整：

- `max_cows: 15 → 16`；
- `max_total_animals: 23`；
- 其他失败实验不进入热路径。

独立 `2,048 seed × 双座位 = 4,096` 局：

| 方案 | 平均现金 | P10 | 最低 | 硬损失 | 溢出 |
|---|---:|---:|---:|---:|---:|
| R6 | 129,450.16 | 101,639 | 59,588 | 0 | 0 |

R6 比 R5 有小幅均值提升，但还没有稳定跨过 `130k`。

## 3. 4,096 候选局部搜索

搜索规模：

- 第一阶段：`4,096 × 16 seed × 双座位 = 131,072` 局；
- 第二阶段：`96 × 512 seed × 双座位 = 98,304` 局；
- 吞吐：约 `409–421 games/s`（16 CPU 核心）。

同一验证库结果：

| 方案 | 平均现金 | P10 | 最低 | 硬损失 | 溢出 |
|---|---:|---:|---:|---:|---:|
| R6 | 129,145.30 | 102,840 | 71,435 | 0 | 0 |
| 搜索第一名 | 129,433.81 | 103,590 | 68,778 | 0 | 0 |

搜索第一名只增加约 `289` 平均现金。它改善 P10，但最低值反而下降。这不是足以改变架构判断的提升。

## 4. 独立事件库复验

将搜索出的5个候选放到从未参与搜索的 `2,048 seed × 双座位` 事件库：

| 候选 | 平均现金 | P10 | 最低 | 硬损失 | 溢出 |
|---|---:|---:|---:|---:|---:|
| R6 基线 | 129,450.16 | 101,639 | 59,588 | 0 | 0 |
| 搜索 Rank3（均值最高） | 129,792.23 | 102,076 | 54,641 | 0 | 0 |
| 搜索 Rank1（较稳） | 129,648.43 | 102,176 | 59,803 | 0 | 0 |
| 搜索 Rank2 | 129,534.68 | 102,399 | 60,390 | 0 | 0 |
| 搜索 Rank6 | 129,347.68 | 102,723 | 58,912 | 0 | 1 |

结论：

- 最佳均值仍低于 `130k`；
- 参数微调的真实独立增益只有约 `200–350`；
- 均值最高候选牺牲了最差局面；
- Rank6 出现1次溢出，不能晋级；
- 因此不把任何搜索候选冒充成已通过的新 Champion。

## 5. 受控归因

已确认的小幅正向变化：

- 牛上限从15增加到16；
- 总动物上限保持23；
- 雇工上限保持12。

未通过或基本无效：

- 主动提前买地：收益大幅下降，并产生新硬错误；
- 重复作物生命周期估值：均值下降；
- 作物独立终局窗口：轻微下降；
- 更强的我方供给冲击：小值近似无效，大值变差；
- 实时承诺产量投影：单一事件库约 `+111`，但尾部变差；
- 雇工上限13/14：下降；
- 牛上限17/18：下降，且可能产生溢出。

失败的主动买地实现已经完全回退。当前 `native_adaptive.cpp` SHA256：

`38A34FAA8047DBFED7FE7593CEA5C9E62E239859F18BE37903436C0B493B3241`

## 6. 真正瓶颈

低收益 trace 表明，规划器会在不利商店前缀下过度集中于牛和草莓；高收益局面则能把相同骨架推到17万以上。

当前规划器每次只比较“再增加1头动物”或“再增加1格作物”，属于逐单位贪心。它缺少两项关键能力：

1. 同时比较完整组合，例如“减少4个未来羊承诺，换成一批草莓”；
2. 将买地和新增雇工这种固定成本分摊到整批项目，而不是全部压在触发门槛的第一个单位上。

因此，有些整体赚钱的组合会因为第一单位看起来不赚钱而永远进不了候选集；有些过度集中组合也无法被一次完整的 `SWITCH` 替换。

## 8. 下一步

下一步不是再扩大相同参数搜索，而是：

1. 在 C++ 中生成少量完整项目组合编辑：`KEEP / SCALE / DEFER / SWITCH / CANCEL`；
2. 支持多单位产业替换以及买地、雇工固定成本的整批摊销；
3. 用 common random numbers 对这些组合续跑，建立解析价值与真实终盘现金的配对校准集；
4. 只有 pairwise accuracy 达到75%、Oracle Top-K召回达到90%，价值器才有权执行路线切换；
5. 再恢复 `1k → 10k → 100k+` 自创拳法搜索。

这一步仍然是通用动态规划能力，不会加入作者名、Replay日期、固定坐标或对手身份特调。
