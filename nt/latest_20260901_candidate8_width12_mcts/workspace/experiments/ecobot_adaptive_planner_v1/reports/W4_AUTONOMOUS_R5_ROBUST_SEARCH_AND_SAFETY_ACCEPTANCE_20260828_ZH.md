# W4 自主规划器 R5 鲁棒搜索与安全验收报告

日期：2026-08-28  
规则与主力引擎：`fast_kaggriculture` C++ 1.32.7  
模式：无 backbone、无高手日历、静止对手、固定独立种子、双方换座位

## 1. 阶段结论

本阶段为**部分通过**：

- R5 相对 R3 的独立平均终盘现金提高 `1,816.65`，P10 提高 `717`；
- 两套各 `4,096` 局的验收中，作物损失、动物损失和日终溢出全部为 `0`；
- C++ 吞吐约 `586–587 局/秒`；
- 但真正留出的 seed 集平均现金只有 `129,052.79`，尚未达到设计书要求的 `130,000`。

因此：**R5 是当前最佳自主 Challenger，但不宣布自主收益门完成，也不替换可回滚的 R3。**

## 3. 本阶段实际修复

### 3.1 去除零权重实验功能的热路径成本

公开产量承诺投影在权重为零时，不再初始化约 5 KB 的缓存，也不进入地块扫描。相同规模探针吞吐从约 `474` 恢复到约 `656 局/秒`；加入末步精确安全检查后，正式吞吐仍约 `586–587 局/秒`。

### 3.2 容量安全改为“物流任务”，而不是禁止生产

错误方案曾把所有可收产品都计入立即容量风险，虽然溢出为零，但平均现金跌到 `109,808`。最终实现改为：

1. 只在真实 `shed + carried` 接近容量时触发回仓；
2. 为每个实际带货单位生成独立回仓 lane；
3. 单位尚在赶路时不提前占用 shed 容量；
4. 回仓优先级随日终临近逐步升高，但始终不超过缺水作物的 `980`；
5. 只在 hour 23 检查“这一项原子收获执行后是否真的溢出”。

这避免了“为了零溢出而少收产品”的伪优化。

### 3.3 修复同日种植后任务所有权丢失

极端 seed 中出现过：工人刚种下胡萝卜，下一步却把浇水任务交给远处工人，最终来不及浇水。现在同日 `PLANT → WATER` 义务若本地工人已站在目标格，会由该工人闭合；仍允许更高层规划自由选择种什么和种多少，但一旦落地投资，就不会因为全局重新匹配而无故丢失其硬义务。

## 4. 明确拒绝的方向

- **把所有地图产量当作马上回仓：** 平均现金约从 12.9 万跌到 11.0 万；
- **晚间全面禁止 HARVEST：** 会压制有效生产，并产生新的作物损失；
- **取消甜瓜上限后仅靠加强市场冲击惩罚：** 目标数量会变化，但收益、安全性都退化；
- **R4 单次搜索赢家：** 独立收益不稳且有溢出，属于小样本过拟合。

## 5. 当前能力边界

已经证明：

- 无高手日历可完整运行 719 个决策步；
- 跨日项目状态机与通用调度可稳定产生多种牛羊鹅、作物组合；
- 物流容量和同日浇水硬义务可以在不牺牲整体收益的前提下闭合。

尚未证明：

- 独立平均现金稳定超过 13 万；
- 至少三种**高收益且产业结构明显不同**的自主拳法；
- 面对动态强对手与不同市场状态有稳定非零竞争力；
- 完整本地 Arena 逐对手 90% 胜率；
- 官方 Python 1.32.7 最终候选复验。

因此下一步继续优化自主项目价值与兑现能力，先跨过独立 `130k` 门，再做产业多样性和动态对手门，不能提前回到高手日历选择器。
