# W12：G001计划、完整候选与跨阶段序列搜索隔离实验

日期：2026-08-29

## 1. 目的

W11 的胜负优先滚动 Oracle 在知道真实未来的情况下，对 G001 仍只有 2胜14负。本轮依次验证三个可能的瓶颈：

1. G001经营计划交给通用执行器后能否兑现；
2. 将原生G001完整计划作为第一类候选后，Oracle下限能否提高；
3. 允许候选跨2～3个阶段组合，能否发现单次贪心看不到的协同路线。

所有正式结果统一使用随机种子 `2842001..2842008`、双座位，共16个状态。

## 2. 实验1：G001语义计划交给当前执行器

输入是从 G001 官方 Replay 编译的完整30天语义日历，包含人员、土地、作物、动物、维护、产品、市场窗口和终局清仓等目标。它不保存原始动作坐标或逐帧动作。

通用自适应执行器负责把这些目标重新编译为人员任务、移动、市场事务和原子动作。

| 指标 | 结果 |
|---|---:|
| 胜-平-负 | 0-0-16 |
| 得分率 | 0% |
| 我方平均现金 | 61,279 |
| G001平均现金 | 88,393 |
| 平均分差 | -27,114 |
| 作物硬损失 | 0 |
| 动物硬损失 | 0 |
| 仓库溢出 | 0 |

### 结论

当前“语义计划 → 通用执行器”管线无法复现 G001 的竞技能力。没有非法动作或明显硬伤，但人员调度、布局、日内任务链、事务顺序和条件恢复造成了巨大的软效率损失。

严格来说，本实验测量的是“Replay语义压缩 + 通用执行器”的联合损失。语义日历没有保存G001全部条件分支和逐单位任务链，因此不能把全部差距都归因给调度器；但可以确认，现有语义计划管线不足以承载完整高手拳法。

## 3. 实验2：原生G001完整计划作为第一类候选

这一实验不再把G001压成日历，而是把完整原生G001策略当作一个从开局持续到终局的候选，与Candidate8 Oracle按“胜负 → 分差 → 我方现金”取优。

| 候选集合 | 胜-平-负 | 得分率 | 平均分差 |
|---|---:|---:|---:|
| 原生G001完整计划 | 2-12-2 | 50.0% | 0 |
| 原生G001 + W11滚动Candidate8 | 4-10-2 | 56.25% | +448 |
| 原生G001 + 滚动Candidate8 + 3阶段序列 | 6-8-2 | 62.5% | +1,171 |

两臂组合中，16个状态有14个选择原生G001，只有2个选择Candidate8滚动方案。这说明当前局部候选还不能取代完整拳法，但能在少数状态提供明确增益。

加入3阶段序列后，选择构成为：

- 原生G001：12个状态；
- W11滚动Candidate8：2个状态；
- Candidate8三阶段序列：2个状态。

### 结论

完整经营计划必须成为第一类、可持久执行的候选，而不能只保留成若干目标数字。它提供约50%的镜像安全下限，局部候选只应在反事实证据足够强时覆盖其部分计划。

## 4. 实验3：Candidate8跨阶段Beam Search

候选决策日为第3、6、9天。每个节点最多展开64条可行候选，Beam宽64；每个序列前缀都在真实未来上完整续跑到终局，以“胜负 → 分差 → 我方现金”评分。

| 搜索深度 | 胜-平-负 | 得分率 | 我方平均现金 | 平均分差 | 相对单阶段平均分差改善 |
|---|---:|---:|---:|---:|---:|
| 1阶段 | 2-0-14 | 12.5% | 89,042 | -17,403 | — |
| 2阶段 | 2-0-14 | 12.5% | 78,528 | -16,236 | +1,168 |
| 3阶段 | 4-0-12 | 25.0% | 84,250 | -7,488 | +9,915 |

3阶段相对单阶段在16个状态中的12个提高了分差，并新增随机种子 `2842007` 的双座位胜局：

`UNILATERAL → UNILATERAL → CONTINUOUS_SCALE`

这两局如果只看第3天的单次修改，分别落后23,521；完成三段组合后，变为领先4,833和6,727。

正式搜索共完成43,844次3阶段前缀终局续跑；1～3阶段全部实验总耗时129.54秒。

### 结论

跨阶段协同是真实瓶颈。某些早期动作单独看并不够好，必须与后续扩产/缩产组合才能翻盘。单步贪心会过早删除这些路线。

但三阶段确切未来Oracle仍只有25%胜率，因此跨阶段搜索不是唯一问题，也不能替代完整拳法与执行器修复。

## 5. 最终归因

按当前证据，瓶颈优先级为：

1. **完整计划承载与执行管线**：G001语义日历经通用执行器后0胜16负，是最大损失来源；其中语义压缩和调度执行的责任还需进一步拆分。
2. **完整拳法候选缺失**：加入原生G001候选后，组合得分率由Candidate8的12.5%提高到56.25%，证明只靠局部PlanDelta不能覆盖高手骨架。
3. **跨阶段组合搜索不足**：三阶段把Candidate8胜率从12.5%提高到25%，是明确有效的第二增益源。
4. **选择器不是当前首要矛盾**：以上实验均使用真实未来和Oracle标签；可选内容与兑现能力不足时，再强的RL/LGBM也无法凭空创造缺失路线。

## 6. 正确的下一版结构

建议把规划器改成：

```text
多个完整、持久、可恢复的经营骨架
        ↓
当前公开状态下生成局部PlanDelta
        ↓
2～3阶段Beam/反事实搜索评价组合
        ↓
只覆盖骨架中受影响的部分
        ↓
未被覆盖的任务继续由原骨架执行
```

RL或树模型之后学习的是“什么时候选择哪个完整骨架，以及何时采用哪组局部修改”，而不是重新学习全部719步原始动作。

## 7. 限制

- Oracle知道真实未来，不能直接上线；
- Beam宽64、每节点64臂，是近似搜索而非全序列穷举；
- 当前只验证8个种子和G001一个对手；
- 结果来自C++模拟器，尚未对新生成的序列逐条做官方Python 1.32.7复验；
- 实验1使用语义压缩后的G001日历，不能单独测出“执行器纯损失”。
