# Candidate8 跨阶段搜索 hard16 初筛验收

日期：2026-08-30

## 1. 结论

**跨阶段搜索方向有效，但当前三阶段 Candidate8 仍不足以解决 hard16。**

两批完全独立随机种子合并后：

| 方法 | 胜局/128 | 得分率 | 平均分差 |
|---|---:|---:|---:|
| 单阶段，第3天只修改一次 | 20/128 | 15.63% | -13,555 |
| 三阶段，第3/6/9天联合搜索 | 45/128 | 35.16% | -4,858 |
| 三阶段相对单阶段 | +25局 | **+19.53pp** | **+8,697** |

这证明“当前看似不好的早期修改，和后续修改组合后可能变好”。但三阶段知道真实未来，仍输掉83/128局，因此不能把剩余问题只交给RL选择器。

## 2. 实验设置

- 对手：Candidate8 Oracle 仍低于50%的16条固定C++路线；
- 两个独立实际种子库：`2900001..2900002`、`2901001..2901002`；
- 双座位；每个对手合计8局，每个深度合计128局；
- 决策日：第3、6、9天；
- 单节点候选上限：32；
- Beam宽度：32；
- 优化目标：真实未来胜负 → 分差 → 我方现金；
- 候选由当前 Candidate8 完整可行池生成，但每节点只取前32条；
- 对手未来固定路线和真实随机未来均已知，因此是不可上线能力探针。

第一批还测了两阶段：得分率从12.50%提高到17.19%；第二批为节省计算只复验深度1和3。

## 4. 计算成本

- 第一批：198.50秒；
- 第二批：166.80秒；
- 总计：365.30秒；
- 完成终局续跑：149,487次（含第一批的两阶段实验）；
- 约409次完整续跑/秒。

三阶段每个真实状态平均需要约1,007次终局续跑。该成本适合离线生产标签，不适合线上1秒推理。

## 5. 验收判定

判定：**方向性通过，竞技上限不通过。**

通过理由：

- 两个独立种子库都显示三阶段优于单阶段；
- 合并后胜率提高19.53个百分点；
- 平均分差改善8,697；
- 多个对手出现只有连续修改才能翻盘的证据。

未通过理由：

- 使用真实未来后仍只有35.16%；
- 16个对手中没有任何一个在合并8局上达到90%；
- G038、G049稳定0胜，G136仍接近0；
- 当前只是32臂、32宽Beam，不是完整组合穷举，但结果已证明不能仅训练单步选择器解决全部问题。

## 6. 后续用途

跨阶段 Beam 应保留为离线教师：

1. 生成 `状态 → 多步候选序列 → 终局胜负/分差` 标签；
2. 训练宏观Q模型预测序列或第一项PlanDelta的长期价值；
3. 线上只运行轻量模型，不运行千次终局续跑；
4. 对G038、G049、G136优先扩候选和完整经营结构，再重复本验收。
