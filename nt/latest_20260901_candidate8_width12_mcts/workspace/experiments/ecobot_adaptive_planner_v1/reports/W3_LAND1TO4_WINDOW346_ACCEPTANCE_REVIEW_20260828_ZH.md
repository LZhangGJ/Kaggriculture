# W3：1–4 块地与 2/4/8 天兑现窗口复审

日期：2026-08-28  
结论：**工程语义通过，排序门未通过，禁止接入运行时独立决定路线切换。**

## 1. 本轮改动

本轮没有把一、二、三、四块地训练成四个互不相通的模型，而是：

1. 在 C++ `score_plan_candidate` 中为基准计划和候选计划各增加 15 个通用兑现特征；
2. 分别采集 `max_quadrants=1/2/3/4` 四档训练状态；
3. 将四档数据合并，训练一个共享的 pairwise LGBM 排序器；
4. 另外按早期（0–10 日）、中期（11–19 日）、晚期（20–30 日）训练专家模型，验证是否值得分阶段；
5. 保留第二套独立随机种子作为冻结测试集，未打开最终 blind 库。

新增特征只依赖官方规则与当前公开/自身状态，包括：

- 新承诺第一次可能回款的天数；
- 当日新增动作需求、可用动作容量和 deadline 余量；
- 2/4/8 天动作需求与动作容量；
- 2/4/8 天预计净现金；
- 峰值人员利用率与最小窗口余量。

没有使用作者名、Replay ID 或对手身份分支。

## 2. 发现并修复的真实数据错误

346 维 schema 初次扩展后，`KEEP_PLAN` 是从第一条 SWITCH 候选复制生成的。旧复制逻辑只覆盖原有价值字段，没有覆盖新增的 15 个候选兑现窗口字段，导致 KEEP 样本可能携带另一候选的窗口成本。

已完成两处修复：

- `calibrate_portfolio_expected_value.py::keep_features` 复制全部新增窗口字段；
- 历史 346 维数据用 `repair_window_first_cash_lag.py` 修补首次回款和 KEEP 窗口字段。

同一局面、同一随机种子重新生成后，修补数据与新 C++/Python 管线在以下全部内容上逐项完全一致：

- 29 行 × 346 维特征；
- 候选 rank；
- 期望收益差；
- 未来收益样本；
- 座位与 prefix seed。

结果：`ALL_EXACT=True`。因此当前差距不是这项数据错误继续造成的。

## 4. 独立测试结果

### 4.1 共享模型

| 指标 | 仅 4 块地训练 | 1–4 块地共享训练 |
|---|---:|---:|
| 全部 pair accuracy | 62.77% | **63.60%** |
| 价差 ≥ 2,000 pair accuracy | 72.85% | **74.71%** |
| Raw Top-4 oracle recall | 未晋级 | 68.49% |
| Raw Top-5 oracle recall | 未晋级 | 80.14% |
| 安全策略平均候选增益 | +577 | **+757** |
| 安全策略负选择率 | 6.16% | **5.48%** |

结论：把土地容量作为数据分层是有效的，但增益不足以通过 W3。

### 4.2 分阶段模型

| 阶段 | pair accuracy | 价差 ≥2,000 | Raw Top-5 | 安全选择平均增益 |
|---|---:|---:|---:|---:|
| 早期 | 64.14% | 72.46% | 70.59% | +884 |
| 中期 | 67.92% | 78.89% | 86.05% | +1,895 |
| 晚期 | 59.42% | 76.19%（仅 63 对） | 69.23% | -44 |

分阶段并非普遍有效：中期清楚受益；早期和晚期仍弱，晚期安全策略甚至为负。因此不能简单部署三个阶段模型。

## 5. 误差定位

共享模型的主要独立集弱桶：

| 桶 | 全部 pair | 价差 ≥2,000 |
|---|---:|---:|
| 第 4 天 | 54.47% | 62.67% |
| 同目的产业、不同编辑 | 55.04% | 63.49% |
| 胡萝卜 vs 胡萝卜 | 41.23% | 34.72% |
| KEEP vs 作物 | 59.81% | 67.76% |
| 作物 vs 作物 | 61.40% | 72.22% |

相对容易的桶：

| 桶 | 全部 pair | 价差 ≥2,000 |
|---|---:|---:|
| 作物 vs 动物 | 74.15% | 80.80% |
| 动物 vs 动物 | 72.05% | 81.74% |
| KEEP vs 动物 | 75.00% | 84.91% |

这说明模型已经能判断“产业大方向”，但仍不能可靠判断同一产业中：

- 应扩多少规模；
- 释放哪一笔旧承诺；
- 当前人员位置和任务 backlog 是否允许新规模及时兑现；
- 两条表面相似的作物编辑中哪条实际物流更便宜。

## 6. 模型容量消融

将 LGBM 从默认 4 组结构扩大到 12 组结构、加入更深树、更多树、行列采样和更强正则后，校准集仍选择原来的 variant 3；独立测试结果与共享基线完全相同。

因此当前瓶颈**不是简单增加树参数**。

30 个新窗口特征消融显示：

- 新特征对全部 pair 有小幅正增益；
- 对大额 pair 和 Top-K 没有稳定全面增益；
- 中期有效，早晚期不足。

所以新特征保留为研究字段，但当前不能凭它们通过 W3。

## 7. W3 门控判定

计划书要求：

- 独立 pairwise accuracy ≥75%；
- Oracle 最优候选进入解析 Top-K ≥90%。

当前最好共享结果：

- 全部 pair：63.60%；
- 价差 ≥2,000：74.71%；
- Raw Top-5：80.14%。

判定：**FAIL**。

依照计划书，当前价值器只能裁掉明显不可行候选，不能独立决定路线切换；最终 blind 库继续封存。

## 8. 下一步

不再继续扩大树模型，也不再按土地数拆成独立模型。下一步补足真正缺失的执行状态：

1. 候选新增任务与现有人员位置之间的最小联合分配成本；
2. HARD 浇水、喂养、收获、回仓与新增项目之间的 deadline 冲突量；
3. 同目的产业不同规模的边际回款、边际人员占用和边际物流距离；
4. 对同产业候选使用成对边际特征，而不是只比较两份总量摘要；
5. 在新字段通过行为效果测试后，重新采集小规模探针，再决定是否扩大训练集。

这条路线符合“学习服务于搜索”：C++ 搜索产生完整、可执行候选和反事实收益；模型只学习筛选与排序，不输出原子动作，也不替代事务顺序和联合调度。

## 9. 市场预测与同产业边际特征合并消融

讨论帖指出：确定性环境应优先搜索与规划，学习只服务于候选筛选；联合动作、订单顺序和长期信用不能交给扁平策略头。为验证这一判断，没有增加模型深度，也没有改官方规则，而是将原来互斥的两组在线可见特征合并：

- 当前公开状态推导的对手产能、市场压力与 2/4/8 天短期预测；
- 同产业扩缩规模的边际回款、边际成本、人员负荷、setup turn 和单位收益。

新增特征模式为 `shop_bits_scale_forecast_marginal_catfix`，原始 346 维输入经无泄漏派生后为 509 维。它不读取未来事件、Replay 身份、作者名或未来动作；未来续跑仅用于离线标签。

独立测试对比：

| 指标 | 共享基线 v192 | 合并边际 v205 |
|---|---:|---:|
| 全部 pair accuracy | **63.60%** | 63.44% |
| 价差 ≥2,000 pair accuracy | 74.71% | **74.99%** |
| Raw Top-4 oracle recall | 68.49% | **72.60%** |
| Raw Top-5 oracle recall | 80.14% | **80.82%** |
| Raw 平均候选增益 | +762 | **+924** |
| Raw 负选择率 | 10.96% | **10.27%** |
| 安全门控平均候选增益 | +757 | **+836** |
| 安全门控负选择率 | **5.48%** | 7.53% |

结论：合并特征没有解决全部成对排序，但明显改善了搜索短名单质量和平均反事实收益。这支持把模型定位为“搜索候选筛选器”，不支持让它独立接管经营。由于全部 pair 和 Top-5 仍低于 W3 的 75%/90% 门槛，W3 继续判定 **FAIL**，最终 blind 继续封存。

对应收据：

- 训练：`w6_window346_forecast_marginal_pairwise_train80_cal5_v205.json`；
- 独立安全评测：`w6_window346_forecast_marginal_v205_raw_cal5b_v206.json`；
- 独立分桶：`w6_window346_forecast_marginal_v205_pairwise_buckets_cal5b_v207.json`；
- 独立无门控短名单：`w6_window346_forecast_marginal_v205_raw0_cal5b_v208.json`。

## 10. 386 维联合调度与投产排程消融

### 10.1 新增的通用能力

在不读取路线作者、对手 ID、未来事件或 Replay 后续动作的前提下，为基线和候选各增加 20 项通用执行投影：

- 当前统一任务队列的任务数、HARD 任务数和实际可分配任务数；
- 当前联合分配的移动距离、总动作步数、最小 deadline slack；
- 无法及时完成的任务数、未分配 HARD 任务数及延迟损失；
- 新项目尚未购入资源的 pickup/build/place/feed/care/dig/plant/water 投产工单；
- 投产总工时、多单位 makespan、首次回款 slack、不可达工单；
- 新增服务路线距离、路线跨度及单位新增规模所需投产步数。

新增字段只在需要完整价值拆分的基线和候选上调用真实 `build_tasks + assign_tasks`；没有把昂贵调度重复放进 224 个解析候选的热循环。

同时修复了一个对照错误：旧实现评估 KEEP 时，`hand_target` 尚未填入，而 SWITCH 已经过日历归一化，导致同样需要 5 名 hand 的计划被错误估成 `154` 对 `31` 步 makespan。现统一从完整项目工作量推导人员数，修复后同一计划两侧均为 `31` 步。

行为效果探针覆盖 2 条路线、4/10/19/24 日共 277 行。投产工单、总步数、makespan、回款 slack、服务距离和单位投产工时均随状态或候选改变，证明字段不是死字段。

### 10.2 新语料

- 训练：3,580 个独立局面、26,477 条候选、每候选 16 条共同未来续跑；
- 训练有效无序候选对：49,310 对（冻结模型选择 `Z>=1.96`）；
- 校准：1,240 条候选，每候选 64 条共同未来；
- 独立测试：1,241 条候选，每候选 64 条共同未来；
- 原始维度 386，派生维度 549，成对输入维度 1,647；
- 训练、校准、测试前缀种子和未来事件种子使用互不重叠的新区间；
- 1/2/3/4 块地均单独生成再合并，所有 640 个训练生成任务状态为 `PASS`。

候选续跑中的 `end_overflow` 保留为反事实失败信号，不能从训练集删除；删除会让模型看不到扩产过度造成的真实失败。控制器基线硬错误验收与“搜索候选允许失败并获得差标签”必须区分。

### 10.3 严格同数据消融

为避免把“新特征”和“新随机语料”混为一谈，新增 `project_portfolio_feature_schema.py`，将同一 386 维训练、校准和测试语料严格投影回冻结 346 维：标签、行顺序、未来续跑和分组完全不变，只删除新增 40 字段。

| 指标 | 同数据 346 维 | 同数据 386 维 |
|---|---:|---:|
| 全部 pair accuracy | **67.10%** | 66.75% |
| 价差 ≥2,000 pair accuracy | **77.70%** | 77.08% |
| Raw Top-4 oracle recall | **73.79%** | 71.03% |
| Raw Top-5 oracle recall | **81.38%** | 79.31% |
| Raw 平均候选增益 | +427 | **+528** |
| Raw 最坏候选增益 | -9,208 | **-4,415** |

结论：新增执行投影包含有用的风险信息，改善了平均选择价值和最坏损失，但没有提高完整排序与短名单召回。不能把“实际平均收益改善”误报成 W3 通过，也不应继续通过堆叠相似字段期待从 67% 跳到 75%。

## 11. 列表排序对照与方向收敛

为了验证失败是否只是“成对分类目标与 Top-K 门不一致”，新增列表排序器，让模型直接学习同一局面内 KEEP/SWITCH 整组候选顺序。模型和超参数只在训练/校准集选择，独立测试不参与选择。

同一 346 维语料的最佳 LambdaRank 对照：

| 指标 | 成对模型 | 列表模型 |
|---|---:|---:|
| 全部 pair accuracy | **67.10%** | 66.41% |
| 价差 ≥2,000 | **77.70%** | 77.18% |
| Top-4 | 73.79% | **74.48%** |
| Top-5 | 81.38% | **83.45%** |

列表目标只带来约 1–2 个百分点的短名单改善，仍远低于 90%，且没有解决全部 pair。因此瓶颈不是单一树参数或损失函数，而是：

1. 16 条训练未来不足以稳定标注大量近似候选；
2. 同产业规模的真实价值取决于未来完整调度和局部重规划，解析摘要仍有信息损失；
3. 当前局部编辑候选器可能根本没有生成真正更强的新拳法。

W3 继续判定 **FAIL**，最终 `v64` blind 继续封存。

后续停止小特征微调，改为两级规划：

```text
通用候选生成
→ 学习模型做高召回筛选
→ C++ 对短名单做多情景真实续跑
→ 以完整调度、最终现金和失败风险重排
→ 只执行胜过 KEEP 且优势稳定的局部编辑
```

这不是放弃自主规划，也不是退回 G001 日历；模型仍负责泛化筛选，C++ 搜索负责确定性环境中最可靠的完整价值判断。只有两级系统在预先冻结的独立集同时达到 `pairwise >=75%` 与 `Top-K >=90%`，才重新开放最终 blind。

列表对照证据：

- `train_switch_listwise_ranker.py`；
- `w6_joint386_projected346_listwise_train80_cal5_v234.json`。
