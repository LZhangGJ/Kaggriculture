# M3.8 路线卡验收报告 v1

日期：2026-08-19  
官方规则：Kaggriculture 1.32.7  
结论：**通过，可作为 M3.7 控制器的可选加速/增益分支。**

## 1. 本次到底增加了什么

路线卡不是新的原始动作，也不是 Replay 脚本。它是在现有任务层与原子执行器之间增加的一层固定长度计划：一个工人先锁定一组停靠点，然后逐项执行，只有观察到官方/JAX 状态中的真实效果后才推进到下一项。

当前每个单位最多保存 12 个停靠点，首版实现两类路线：

1. `FEED_TOUR`
   - 一次从 shed 精确领取本路线所需的小麦；
   - 按路线连续喂多个动物；
   - 在同一动物格上顺便收取已经达到阈值的牛奶/羊毛/蛋；
   - 执行需要的 CARE；
   - 只有 `COLLECT_WHEN_VISITING_AND_SELL` 或 `ACTIVE_COLLECT_AND_SELL` 才把收肥并入路线；`RESERVE_FOR_CROPS` 继续交给全局经济/调度器判断；
   - 生存喂养优先于产出奖励和 CARE，防止为了走近路而让远处动物逃逸。
2. `CROP_HARVEST_TOUR`
   - 连续收获多块成熟作物；
   - 对一次性作物可在种子与时间允许时原地补种并浇水；
   - 最后只回仓一次，或使用官方日终自动入仓。

原来的 primitive executor、合法动作检查和官方/JAX 状态转移没有改写。路线卡只产生已有的单步任务，不能绕过合法性和效果验收。

## 2. 实现中发现并修复的问题

| 版本 | 问题 | 修复 |
|---|---|---|
| 初始接入 | `[batch, unit]` 清理掩码不能广播到 12 个停靠点 | 按每个状态叶子的维度自动扩展掩码，并增加批量 JIT 回归 |
| V1 整局 | 8 次超期、2 只动物逃逸，现金仅 57,915 | 最后一回合留给官方日终结算；不再把它误算成可执行维护动作 |
| V1 整局 | 路线预留动物格，却没有同步收产品；动物收获从 106 次降到 40 次 | 把动物产品收获加入同格链，并置于可选收肥之前 |
| V1 整局 | 收肥从 53 次膨胀到 248 次 | `RESERVE_FOR_CROPS` 不再无条件并入路线，交回全局经济调度 |
| V2 整局 | 仍有 1 次硬超期和 1 只动物逃逸 | 路线排序改为生存任务绝对优先；对应的远处动物回归用例已加入 |

最终 V3 清零了全部硬错误。

## 3. 验收结果

### 3.1 固定种子 719 步 GPU 整局

种子 `1905263333`，座位 1，NullOpponent，使用与此前 V17 相同的 KAWASHIGI 日历来源。

| 指标 | 旧 V17 | 路线卡 V3 | 变化 |
|---|---:|---:|---:|
| 最终现金 | 82,488 | **98,857** | **+16,369 / +19.84%** |
| 硬错误 | 0 | **0** | 持平 |
| 非法动作 | 0 | **0** | 持平 |
| 未计划超期 | 0 | **0** | 持平 |
| 非计划动物逃逸 | 0 | **0** | 持平 |

本条轨迹实际创建了 49 张喂养路线卡、共 176 个停靠点。作物收获路线已经通过独立执行测试，但在这个固定日历/种子中没有自然触发，因此不能把该轨迹当作作物路线的实战证据。

### 3.2 官方 Python 1.32.7 逐步复验

- 比较初始状态在内共 720 帧；
- `exact_full_state_stepwise_parity = true`；
- 官方最终现金 = 98,857；
- JAX 最终现金 = 98,857；
- 差值 = 0；
- 双方状态均为 `DONE`。

因此，98,857 不是 JAX 语义偏差制造出来的虚假收益。

### 3.3 2,048 个独立事件流公平对照

两组都使用事件种子 `1000000..1002047`、相同日历、M3.7 解锁、719 步和 RTX 3090。

| 指标 | 关闭路线卡 | 开启路线卡 | 变化 |
|---|---:|---:|---:|
| 最佳热运行吞吐 | 85,867 trans/s | **86,395 trans/s** | +0.62%，视为无可测损失 |
| 终局现金中位数 | 58,801 | **71,012** | **+12,211 / +20.77%** |
| 终局现金均值 | 59,584 | **73,820** | **+23.89%** |
| 终局现金 P90 | 80,471 | **99,546** | +19,075 |
| 终局现金最大值 | 89,782 | **112,352** | +22,570 |
| 硬错误总数 | 1 | **0** | 改善 |

路线图的首次 `light_chunk_24` 编译为 101.65 秒，关闭路线卡为 91.72 秒，首编成本约增加 10.8%；这是一次性编译成本，不是每季执行成本。

### 3.4 跨局污染与测试

- 1,000 次连续 episode reset；
- batch = 8；
- 共 5,752,000 个控制步；
- reset mismatch = 0；
- cross-episode contamination = 0；
- full-episode snapshot mismatch = 0。

拆分执行的相关回归共 50 项通过、0 项失败。既有 CPU 全季 JIT 用例因重复进行重型编译而被停止，没有伪报通过；其覆盖由更强的 `2048 × 719` GPU 整局验收和官方 720 帧逐步复验承担。

## 4. 验收边界

本次可以确认：路线卡能表达并稳定执行“一个工人连续完成多个相关任务”，不会污染下一局；在当前 NullOpponent 经营基准上显著提高现金，同时没有降低热运行吞吐。

本次不能确认：

- 对真实强对手的胜率；
- 路线卡已经覆盖所有高手 multi-task 形式；
- 作物收获路线已在固定种子整局中实际触发；
- 当前 12 停靠点、最近邻加优先级就是全局最优路径；
- 98,857 可直接等同于 Public 分数。

## 5. 决定

**M3.8 路线卡 v1 验收通过。** 保留 `enable_route_cards` 开关，后续搜索和对战可做开/关消融。下一轮如果继续扩展，应优先用金牌 Replay 证据增加“动物产品专门巡回、浇水巡回、放置/建设链”，而不是一次把所有动作都塞进路线。
