# M3.9 种植与混合路线卡验收报告 v1

日期：2026-08-19  
官方环境：`kaggle-environments==1.32.7`  
结论：**路线卡工程能力通过；V20 高收益路线复现未通过。**

## 1. 最重要的结论

本阶段已经实现并验收：

- 作物连续种植、同日浇水、日常浇水、成熟收获、原地补种、施肥、回仓和日终入库；
- 动物喂养、照料、产品收集、肥料收集与作物任务的联合候选；
- 同一工人跨动物与作物区域执行混合路线；
- 活跃任务、路线卡、种子、肥料、饲料、格子和截止时间的共享预留；
- 未来目标因杂草等状态变化失效时，取消旧路线并重新规划；
- JAX 静态形状、JIT、GPU2048 批量执行与官方 Python 1.32.7 逐步一致性。

但这不等于已经复现金牌或 17 万经营路线。使用我们自己的 V20 最高收益 Replay 验证后：

| 执行方式 | 终盘现金 | 是否精确通过官方规则 |
|---|---:|---|
| V20 官方 Replay | 155,450 | 官方事实 |
| V20 原始双方动作直接送入 JAX | 155,450 | 是，里程碑和终盘精确一致 |
| V20 日历 → 当前混合路线卡 | 106,333 | 是，JAX/官方 720 帧一致 |
| V20 日历 → 种植与养殖分离路线卡 | 105,100 | 是，JAX/官方 720 帧一致 |

当前高层控制器对这局 V20 的最佳复现率只有 **68.4%**，少 **49,117**。因此：

> 当前路线卡已经会合法、稳定、高速地执行完整经营链，但当前 `Replay → 30天日历` 表达和作物项目生成仍不足以保留 V20 的高收益执行节奏。

## 3. 实现内容

### 3.1 种植路线卡

`CROP_FIELD_TOUR` 支持：

1. 空地 `PLANT + same-day WATER`；
2. 未浇水作物 `WATER`；
3. 成熟但未浇水作物 `WATER → HARVEST`；
4. 成熟作物 `HARVEST → REPLANT → WATER`；
5. 有肥料且策略允许时 `FERTILIZE → WATER`；
6. 有收获物时回仓放下，或使用官方日终自动入库；
7. 种子和肥料按路线前缀精确裁剪，不能借用未来资源；
8. 格子变成杂草或目标失效后，旧卡不会继续发出不可能动作。

### 3.2 混合路线卡

`MIXED_FARM_TOUR` 将当前可执行的动物和作物候选放入同一有序路线，重新计算：

- 工人当前位置；
- 动物生存/维护优先级；
- 作物浇水、收获和补种优先级；
- 剩余日内动作预算；
- 饲料、种子和肥料的前缀余额；
- 目标格子和资源预留；
- 回仓或日终入库方式。

直接的“动物收肥 → 同一工人给作物施肥 → 浇水”已通过定向执行测试。最终实现会只收取真正被施肥消费的额外肥料；动物策略本身要求的收肥不会被删除。

需要如实说明：选定的 V20 完整赛季虽然实际创建了 8 张混合卡，但这些自然触发的卡没有包含施肥动作；跨域肥料链的证据来自定向状态执行测试，而不是该局 V20。

## 6. 为什么混合模式看起来变低

它不是所有意义上的上限都降低：

- 2048 局观测最大值：混合 125,641，分离 125,097，混合高 544；
- 中位数：混合低 788.5；
- 平均值：混合低 318.1；
- 固定前 64 个种子：混合 25 胜、39 负，平均差 -5,164.9；
- V20 单局：混合 106,333，比分离 105,100 高 1,233。

正确结论是：

> 当前混合模式能改善部分布局，但总体典型收益略低于分离模式；它不是稳定升级，也不是最大值上限下降。

原因主要有两层：

1. 混合卡会改变两个独立路线的执行顺序和工人分工，某些局面更省路，某些局面会推迟作物补种或动物维护；
2. 更大的共同瓶颈是高层日历只保存每日峰值规模，没有完整保存“今天必须新增多少、哪批今天成熟、哪批必须补种、何时出售”的义务链。两种路线模式都会因此落后 V20。

当前建议：

- 默认搜索和训练使用 `SEPARATE_CROP_ANIMAL`；
- 保留 `MIXED_WITH_FALLBACK` 作为可搜索的候选路线族；
- 不把混合模式整体替换成默认模式。

## 8. 是否能复现 17 万

当前不能。

本次能够严谨证明的是：

- JAX 能精确重放 V20 的 155,450 原始动作；
- 当前高层控制器只能重新规划出 106,333；
- 本次选择的 V20 Replay 本身不是 17 万；
- 没有把一条真实 17 万 Replay 编译成当前高层日历并通过官方复验。

因此“路线卡可以复现 17 万”目前没有证据。要验证这件事，需要先取得真实 17 万 Replay，然后执行同样的三层对照：

1. 原始双方动作 JAX 精确重放；
2. 高层日历 + 分离路线卡；
3. 高层日历 + 混合路线卡；
4. 官方 Python 逐步复验。

## 9. 下一阶段建议

下一阶段应定义为“高收益作物义务日历”，而不是继续扩大单张路线卡：

- 增加每日每作物的新增种植量；
- 增加必须浇水、预计成熟、必须收获和必须补种的数量与截止时间；
- 保存种子采购和出售的数量/时机，而不只保存一个市场模板类型；
- 同一时刻允许多个工人各自持有作物路线卡；
- 用 V20 Episode `94084095` 设第一道能力门：先达到至少 90%（139,905），再讨论 17 万路线；
- 所有改动继续要求 JAX/官方逐步一致、GPU2048 零硬错误，并单独报告吞吐。
