# F3 RL 候选价值审计

目的：检查当前日级单项目候选有没有可兑现价值，以及模型是否把概率给了较差选项。不是重启Candidate8宏观找拳，不训练、不改策略/奖励/KEEP先验。

## 冻结抽样

- 训练轨迹4组：run0/run1的第1与第20训练批各取第一个seed，7实时对手×双座位，共56场来源对局；使用产生该批数据的step000或step019模型与原动作采样种子。
- 新轨迹2组：两个run的step020模型，各2个新seed（67000000–67000003，分别分配），共56场。它们不参与训练。
- 每场从8个日期区间各抽1个节点：0–2、3–6、7–10、11–14、15–18、19–22、23–26、27–28。抽样随机数固定，**不看输赢或候选价值**。总896个节点，遍及0–28天；不是全部局面穷举。
- 每节点检查全部当前可行选项，包含KEEP。无法选择的候选不当作失败样本。

## 对照续跑

重建完整相同前缀、对手状态和环境随机状态。在指定节点只强制一次选择，之后分别：

1. 原生F3自行经营，RL一直KEEP；测单次编辑后接安全基座的价值。
2. 同一个冻结MLP继续随机决策；测当前策略后续行为下的候选价值。

两类都由七个对手实时响应，不能播放固定对手动作。强制选择时仍消耗正常策略本应消耗的一次采样，确保各分支未来随机数对齐；不能让batch顺序改变同一前缀的策略随机数。

只读已冻结1.32.7 C++引擎与修复后的F3，新建审计接口。先验证未干预/强制原选择均与原接口完整动作一致、1/16线程一致，再批量运行。

## 输出与边界

- 每候选相对KEEP：胜负变化、终盘现金差/分差变化、原终局奖励变化。
- 区分有利/中性/有害；另报1000资金差门槛作为经济幅度诊断，不是游戏规则。
- 分早中晚期、对手、产业、训练/新seed统计；不只给事后最佳数值。
- 对比模型概率与实际候选价值，区分“没有更好候选”与“有候选却没选中”。
- 同seed不同节点高度相关，多个可救回节点不能累计成多场胜利。单节点事后最优、每场任选一个节点的事后最优，都不是可部署Agent胜率，更不代表在线能识别正确选项。
- 同状态比较使用同一未来随机实现，属于离线诊断；跨seed在不同真实状态重测。没有声称对同一状态穷举了未来随机分布。
- 工程通过后运行预定面板，无结果驱动扩大/删改样本。候选价值为特定续接方式下的值，不是全经营策略空间上限。
