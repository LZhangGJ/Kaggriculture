# 从R2到P16：做了什么，证据支持到哪里

## 1. 审计先行

原R2在11个本轮公开对手上为1501/2200胜。699败局＋55胜局对照的754场审计没有发现普遍的非法动作/莫名不执行；现金采购拒绝只有少量实例。短期计划预测与实走的整日单位动作约97.07%一致，我方24步现金MAE约111，对手约1114。这否定了“主要因为我方动作一团乱”的笼统解释，但不证明调度已经最优。

损失更集中在投入、上市和竞争后果：一些局面卖得更多却收到更少钱；甜瓜上市明显晚于对手；动物线还带来小麦采购负担。不能直接把这些相关性当因果，所以用独立开关、同seed双座位、实时对手做消融。

依据：[基线验收](development/reports/BASELINE_ACCEPTANCE_ZH.md)、[754局复盘](development/audits/baseline_audit/REPORT_ZH.md)、[现金成本](development/audits/baseline_audit/CASH_COSTS_ZH.md)、[短期现金预测审计](development/audits/cash_projection_audit/SUMMARY_ZH.md)。原始记录按原名保留；大JSON无损gzip，不补造缺失文件。

## 2. 迭代链，不等于越多功能越强

| 阶段 | 核心尝试 | 主要结果及处理 |
|---|---|---|
| 早期P1–P8 | 融资、供给压力、统一延迟、公开账本、开局偏置、报价积分、公开销售时刻 | 多数不能稳定提升；P8开发73.45%，新32降至70.60%，不晋升 |
| 前瞻期限 | 把一天条件前瞻扩成两天，或关闭前瞻 | 两天开发67.50%，未改善；无前瞻组合后来63.14%，不采用 |
| P9 | 已有产品在短窗口内分批卖，保持饲料、融资、终局约束 | 模式1开发75.73%；新32点估计改善但区间仍跨0 |
| P10 | 有限作物施肥的精确成长/消耗与执行承诺 | 单测11712场景、50688查询通过；不能把局部数学准确直接等同胜率 |
| P11 | 从对手公开作物移除/收获历史估计有限作物上市时钟 | 开发79.27%，确认集并非始终更好 |
| P12 | P9＋P10＋P11组合 | 开发78.32%；后续不同新seed块波动较大 |
| P13/P14 | 全组合估值用真实收获日、同收获日免肥等 | 小筛均127/176，对照P12为149/176，淘汰 |
| P16半量 | 首日假想对手新增供给按半量加入 | 小筛147/176，未采用此档 |
| **P16全量** | P12＋初始对手投资供给先验，MPC中保持有效 | 小筛158/176；开发1790/2200；共同64新seed1115/1408 |

功能源码已包含在P16完整policy里，具体启用项由冻结编译宏和config决定。不能把旧实验目录中的 `agent.so` 或build receipt当成P16。保留 [原消融汇总](development/reports/ABLATION_RESULTS_ZH.md) 和各 [candidate审计材料](development/candidates/)，但旧汇总的最后阶段可能落后于COMMON64。

## 3. P16工程验收

- P16关闭先验版与P12二进制相同；22局/15818个联合动作完全一致。
- 首日先验只能在step0使用；对手已有真实生产资产时不启动这个初始代理。
- 更改己方私有库存不改变对手先验；没有读取对手私有库存、身份、seed或未来动作。
- 下一日清除先验；MPC复制/重新配置仍保留应保留的公开时钟与先验，候选估值实际改变，避免dead field。
- 8组P12/P16代表局用官方规则按原动作逐步复验保存帧与双方现金账。包括救回、丢旧胜、仍输、仍赢，而非只看成功例。
- 交接中源码重编译与冻结P16库哈希相同；搬迁入口对11对手3seed双座位66局与既有记录完全一致。

## 4. 尚未解决什么

1. 共同新seed平均79.19%，离90%仍有差距；不能保证不丢任何原胜局。
2. 假想对手投资只是先验，实际对手可能采用12甜瓜等完全不同开局；并非精确预测器。
3. P16比P12在共同64seed多赢，但平均己方现金反而较低，分差也略低。以胜负为目标，不能仅按收入给版本排名。
4. 首次差异是放置次序/布局，随后随机过程和长期选择连锁变化；无法把收益归为一个纯净的局部交易效应。
5. 新seed两批差异很大；仍需要更多**冻结版本的独立**验证，而不是重新调整这一批seed。
6. 本地可运行不等于官方提交安全：Linux动态库兼容性、线上资源限制还需单独验收，本次不提交。

## 5. 继续开发的边界

先读 [README](README_ZH.md) 和 [COMMON64](evidence/new32_block2/COMMON64_ZH.md)，再用 `run.py` 验证搬迁正确。若研究修改，在新目录/新binary里开展；保留P16、P12、原版，不覆盖哈希。

历史 `development/scripts/*.py` 记录准确的本地生成、审计和评测方法，但路径依赖原workspace，**没有声称全部能在这个精简包里直接运行**。可直接运行的入口只有根目录 `run.py/build.py/verify_package.py/main.py`。完整对手、官方裁判已随包，可自行扩展这几个入口；不必下载新的Notebook或改官方引擎。
