## 4. 修了什么

### 4.1 保留预测时使用的当日维护选择

原 T2 为已有动物生成投入产出日历后，又在组合价格更新后重新求一次喂养/照料动作。由此可能出现估值中假设继续养、执行却改变维护的脱节，或者相反。

`animal_path()` 新增可选的 `first_action` 输出，记录该日历所使用的首日喂养/照料选择。`forecast_service[pos]` 保存它。`set_service()` 在修复开关开启时使用这一已记录选择，不再用另一份价格表覆盖。现实状态仍由 observation 读取；任务可执行性仍由原执行器检查。

### 4.2 用完整组合目标比较已有动物的生命周期替代方案

`reconcile_service()` 为已有动物重新生成一条条件生命周期方案：从组合扣除该动物旧投入产出流，再加新流，并使用与投资组合相同的 `model.value()` 比较。仅当条件模型分数严格改善时，才同时更新项目流与当日维护动作。

因此不是孤立地“今天少买一份饲料”，而是在同一模型内比较其后续投入、产出、人工和竞争后果。模式 2 使用当前条件价格来生成一个替代方案，不穷举所有联合维护计划，也没有真实未来保证。

### 4.3 在采购/排程之前对齐，撤回不可执行新项目后再对齐

主要修改在每日规划中、`core.prepare_orders()` 之前；若预览撤回当日无法启动的新项目，组合价格更新后再次协调维护方案。原新投资、作物周期、执行器与市场模块保留，未针对对手 ID、seed 或具体案例写分支。

完整源码差异见 `T2_to_R1.patch`，同时修改了 `triad.hpp`、`bridge.cpp`、`agent.py` 和配置。**参数 ABI 从 T2 的 33 个扩为 37 个；不能只换 .so 而沿用旧 Python 参数列表。必须成套使用本包 `policy/`，或使用补丁后重新编译。** `td_settings_count()` 可用于调用方核对数量。

保留前次 `animal_path` 的 GCC `noipa` / Clang `noinline` 修复。

## 6. 本地运行

Linux / WSL2，进入解压后的本目录。文件校验不编译、不跑比赛：

```bash
python3 verify_package.py
```

依赖和构建：

```bash
python3 -m pip install -r requirements.txt
python3 build_all.py --jobs 2 --cxx g++
```

该命令构建策略和七对手运行器；策略构建自动做上述 5 条轨迹回归，不自动运行 112/1400 局。只需要策略动态库时：`python3 build_policy.py --cxx g++`。

复跑本文 112 局：

```bash
python3 run.py --tag r1_local112 --start 2609096000 --count 8 --threads 4
```

同种子原 T2 对照：

```bash
python3 run.py --tag t2_local112 --baseline --start 2609096000 --count 8 --threads 4
```

`--baseline` 在本包明确是 `baselines/t2/policy/`，不是 T1。每个输出目录必须全新，避免覆盖。用 `--count 1` 即为七对手双座位 14 局。随包已编译面板扩展是本环境 Python ABI；Python 版本不同应从源码构建。
