# S4E：日内现金/工时重新进入经营决策

2026-09-04。保持八对手逐一>90%的完整目标；本轮不是Candidate事后Oracle。

## 证据与假设

S4D已实证省路变成PASS。旧S3L/S3J/S3Q也证明仅省工、增加饲料权重、缩小原投资包，并不足以提高全池强度。本轮不重复这些参数扫描。

代码中 `new_day → choose → prepare_orders` 只在跨日触发。日内收到新现金、有空闲工人或可用土地，不会产生新的经营项目。这是可确认的表达限制；尚不能认定它是主要败因。

## 实现

- 独立开关 `intraday_admission`：在原生产继续执行的同时，为当前空闲工人提出新增项目，覆盖五作物与三动物。只使用当前公开/自有状态和原有经济估值，不使用对手身份、真实未来或终局赢家标签。
- 独立开关 `intraday_procurement`：允许在当前已有市场订单后补购买缺少的材料/种子；关闭时只允许真正未被其他任务预留的已有物资。
- 现有任务的人员、地块、材料及全局种子先预留。新增项目不能抢占这些承诺。
- 只使用已到账现金；不把尚未执行的DROP/SELL或预期涨价当现金。已发出的买入/HIRE先扣报价预算，真实成交不足时按下一步实际库存重新判断。
- 购买后先记录待执行项目，下一步确认实际资源、地块和剩余时间才下发人员路线。市场部分成交不能当作全量成功；不能向空地发WATER、无小麦发FEED。
- 有材料时也从下一步执行，所有原人员当前动作不改动。每步最多接纳一项新项目，未来维护交回统一日常任务，不绑定一个工人长期维护。
- 项目必须能够在当日剩余时间完成准备/放置或种植/当日浇水，且第一批产出满足原期限规则；不是强迫填满空闲时间。新增土地、日内HIRE和全局最优编排不在本项里假称实现。
- 新项目消耗的资源不允许被同回合/后续市场模块卖掉；现有产品销售仍可继续。

2. 先少量官方完整局发现实现错误，再完成8对手各4局官方抽样与隔离；不能用低no-op代替强度。
3. N50=20262701–20262750，双座位、C++≤16线程、PASS加八实时对手。配置：old、仅库存追加、允许采购追加、all_guard、all_guard+追加采购、all_midroute_net、all_midroute_net+追加采购。先冻结源码/配置，再执行全部7组。
4. 统计实际新增项目/采购/因失败或期限取消、产出与资金差，做单项及组合对照。发生新增项目但现金不增应报告，而非事后删除不利seed。
5. O/P未用。只有有意义的跨对手候选冻结后才进入独立确认。无晋级则保留实现和全部失败证据，继续当前目标。
