# Kaggriculture 当前进展总结

更新时间：2026-08-18 09:08 JST

官方规则口径：`kaggle-environments==1.32.7`

## 1. 一句话结论

我们已经具备“官方规则裁判 + 精确 JAX 高速模拟 + 完整经营路线执行 + 强对手池 + Public 提交”的闭环；当前真正取得线上效果的仍是“预先规划完整拳法，再依据公开市场局部变招”的规则 Agent。EBA26v2 的当前 Public 分数为 **2378.4**。BC、Transformer、LGBM 路由和 PPO 都完成过实测，但尚未产生可以替代规则主线的晋级模型。

## 3. 模拟器和规则工程

### 3.1 已经完成

- 官方 1.32.7 的农场、市场、商店、随机事件、终局和双方状态已经进入 JAX 固定形状模拟。
- 已验收 canonical 完整赛季、100 个未见 seed、随机状态策略和故意非法动作。
- JAX 负责海量筛选，官方 Python 1.32.7 始终保留为最终裁判。
- 完成了可在 GPU 上批量运行的路线矩阵、动态任务账本、市场有序子动作和策略/PPO训练链。
- 通过固定事件库、持久编译缓存、批量矩阵化、STOP 快路径、重复计算清理等方式解决了早期反复 JIT 和动态市场循环带来的性能下降。

### 3.2 仍需注意的边界

- 86K 是 Dynamic Full-core V2 的阶段验收，不代表原先 100K/120K 动态决策目标已经完成。
- JAX 对规则的精确性已经通过冻结验收，但新增策略执行器或新对手迁移后仍需重新做逐步一致性和官方双座位复验。
- 37 个本地强对手尚未全部严格迁移到 JAX，所以当前大池测试仍有“精确对手、近似代理、官方 CPU 复验”三种证据层级。

## 4. 建模与训练实验的真实结论

### 4.1 PPO / self-play

我们完成了 scratch、BC-init、Current Self-play、Frozen-Best、弱 last-best、KL 锚定、双座位梯度和 tiny PPO 等排查。最关键的发现是：

- 早期退化并非单纯由 KL 或座位梯度抵消造成；事件多样性不足和相同模型闭环放大偏差是重要原因。
- 将独立事件数量从 128 扩展到 512 后，短程学习结果明显更稳定。
- Current Self-play 可以在小规模公平复现中提升，但长程稳定性和跨外部对手泛化尚未达到晋级要求。
- 目前没有 PPO checkpoint 通过“未见事件 + 双座位 + 外部强手”的完整晋级门。

结论：PPO 链路可运行，问题主要是学习目标和对手/路线保持机制，而不是 GPU 跑不动；当前不应继续用长程纯 self-play 盲目消耗时间。

### 4.2 BC / Transformer

- Replay 已能编译为参数化任务卡，并纳入对手公开状态和有序多动作。
- 50K MLP 对推理吞吐影响很小，但仅扩大模型没有解决自由滚动。
- LegalFormer / CandidateFormer 证明关系注意力和任务卡建模可以接入，但 1,000 batch BC 后自由对战仍发生严重分布偏移。
- 代表性结果：训练 CandidateFormer 对冻结 86K 基线仅 **10.55%** 胜率，因此 checkpoint 被明确拒绝晋级。

根因不是“Transformer 参数还不够”，而是高手 Replay 主要提供正样本；许多经营局面同时存在多条可行路线，单步模仿会把微小错误带入训练集从未覆盖的新状态。

### 4.3 LGBM 路由

- 已验证规则主干 + LGBM 辅助选拳、同局面反事实排序和动态路线选择。
- 树模型很适合条件分歧，但训练样本覆盖不足时，会在未见商店/市场组合上做脆弱切换。
- 当前没有 LGBM 版本稳定击败最强规则主干，因此没有替代 EBA 路线。

更合理的用途是：JAX 对同一局面续跑多条完整拳法，用真实胜负、分差和执行失败率生成反事实排序标签；LGBM 只决定是否切拳，不接管 719 步底层动作。

## 5. 路线、Replay 和规则 Agent 的进展

### 5.1 路线搜索

GPU 路线搜索已经证明能够快速筛选大量候选，但也确认了一个重要边界：对手不动时的高现金路线只证明“无竞争赚钱潜力”，不证明对强手有效。

正式 GPT 包中的 R6/R7 结果为：

- 共 16,000 个原始候选；
- 使用 4→16→32→128 seed 漏斗；
- 决赛候选经过 64 个未见 seed、双座位 JAX holdout；
- 再用官方 Python 1.32.7 逐局复验；
- 最终保留牛奶 3 条、羊毛 3 条；
- 结论严格限定为 `BEST_OBSERVED_WITHIN_FROZEN_DOMAIN`，对手是 NullAgent，不是强手胜率证明。

### 5.2 金牌元策略的新证据

8 月 18 日的前 20 Replay 显示，主流仍是牛、羊、麦子、草莓、肥料闭环，没有出现新的植物主线。变化主要是：

- 有羊毛需求时，高羊毛路线更普及；
- tetsuya 开始按商店与价格细调牛羊比例，而不是只在 10牛4羊 / 6牛12羊之间二选一；
- 值得新增的候选包括 11牛4羊、8牛6羊、6牛12羊、4牛10羊-75地、6牛5/6羊-75地；
- KAWASHIGI 在高羊毛对局中的优势既来自路线，也来自同一路线的执行细节；
- 暂无足够证据证明前 20 已普遍根据对手盘面实时大幅改线，当前变化更多由公开商店、价格和需求驱动。

### 5.3 EBA26v2

EBA26v2 采用“完整赛季主计划 + 少量公开状态变招”：

- 基于 EBA21v2 的 Route17 公共状态路由骨架；
- 第 168 步若公开商店包含 `YARN_STORE` 且不含 `ICE_CREAM_SHOP`，切换到 Route18（6牛12羊、100地）；
- 运行时只使用公开商店和公开局面，不读取对手身份、seed、未来事件、终局结果或对手私有状态；
- 保留杂草修复、按需求调整卖出槽顺序、近镜像高价商品提前出售、数量偿还和终局清仓。

官方 1.32.7 的 weak6 holdout：384 局、317 胜、82.55% 胜率、平均分差 +5,517，最弱单对手胜率 70.31%。其中对 public G02 为 96.88%，对 public G04 为 92.19%。

同一个较小的 full37 筛查面板（每个对手仅 4 seed、双座位）中，EBA26v2 为 262/296，胜率 88.51%，但最弱单对手仅 25%。因此它是当前线上最强候选之一，但“本地所有方案 90%”目标尚未完成。

## 6. 当前架构判断

最符合已经观察到的 Kaggriculture 结构的方案不是“每天从零决定一切”，而是：

```text
公开商店/价格/初期信息
  -> 选择一条完整经营计划
  -> 确定投资、牛羊比例、土地、雇工、生产和出售时间
  -> 确定性执行器完成底层动作
  -> 在少数关键点观察实际偏差和对手公开产能
  -> 只在反事实续跑证明更好时切换路线或调整出售顺序
  -> 官方 1.32.7 复验
```

这与当前 EBA/V20 的实践一致，也能避免 BC 和端到端 PPO 在 719 步自由滚动中迅速偏离正样本。

## 7. 尚未解决的核心短板

1. **路线覆盖仍不够。** 当前强路线集中在牛奶/羊毛及少数比例，植物、鸡蛋和更细的混合比例缺少同等强度的完整拳法。
2. **关键点切换标签不足。** 我们知道“何时可能该切”，但缺少大量同局面、多路线、相同随机未来的真实反事实排序标签。
3. **对手精确 JAX 覆盖未完成。** 37 个对手还有 10 个未迁移、17 个只是近似代理。
4. **局部强不等于全池稳。** EBA26v2 在 weak6 大样本很好，但 full37 小面板仍存在 25% 的最差对手结果。
5. **学习模型尚未晋级。** BC、Transformer、LGBM、PPO 都已得到有价值的失败结论，但还没有比规则主线更可靠的模型。
6. **MCTS 尚未正式落地。** 原子动作级 MCTS 分支太大；真正值得做的是路线/宏动作级的 GPU 反事实搜索。

## 8. 推荐的下一步

1. 保留 EBA26v2/V20 的“计划优先、局部纠偏”执行骨架，不重做底层模拟器。
2. 将最新金牌比例编译为可完整执行的候选拳法，先加入 11C4、8C6、6C12、4C10、6C5/6C6。
3. 在冻结关键局面上，用 JAX 对每条候选做相同未来事件、双座位、多强手的反事实续跑。
4. 标签优先级固定为：执行成功 > 胜负 > 分差 > 自身终盘现金；不要只预测单步动作。
5. 先用阈值表或 LGBM 学“是否切拳/切哪拳”，确定性执行器继续负责合法动作和人员协同。
6. 只把 JAX 筛出的前 3–5 条候选交给官方 Python 1.32.7 复验，再决定是否提交。
