# 统一 portfolio 边际价值实验

基线：`joint-portfolio-optimizer` 的 `f0b659f7aae1c990d644b57ed84729c6e403fab4`。
实现开关：`R1_CONFIG_OVERRIDES='{"marginal_value":1}'`；默认值为 0。
这是纯 R1 的候选生成实验，不修改 replay 路线、接管规则或默认部署参数。

## 实现的优化问题

沿用现有条件价值函数 `Planner::value`：将双方公开存量资产投影到未来产出，
结合已开放商店需求、未来商店期望与库存价格曲线，模拟逐日现金流。
目标包含折现后的本方收入、对手收入的竞争权重、劳动/工资和逐日累计现金缺口惩罚。
本次没有把对手未来种植行为或未开放商店当作已知事实，也没有修改原有需求/供给预测器。

旧候选 DP 的输入主要是交易后的市场报价；它并不等于一个项目对整个组合的增量价值。
新增 `policy/r1/marginal_value.hpp`，对 9 种商品的每个未来日期计算：

```text
mu[t,i] = (V(A + epsilon * e[t,i]) - V(A - epsilon * e[t,i])) / (2*epsilon)
epsilon = 2
```

这是有限幅度的中心差分，不声称在价格折点或现金约束处存在解析导数。
它包含同类商品对自有未来销售的挤压、对对手未来收入的影响，以及现金变化对之后各日缺口的影响。
利用按商品可分解的市场递推，只重算被扰动商品的未来后缀；现金缺口仍与组合总现金联合计算。
复杂度从逐次重算完整价值的 `O(9^2 H^2)` 降为 `O(9 H^2)`。

生命周期 DP 接收按其自身折现因子换算回日期 t 的信号，避免未来收益重复折现。
动物服务和多年生作物维护递推增加 continuation 折现，有限作物的施肥比较折现收获收入。
`prices` 继续表示市场报价；`generation_values` 专供候选路径生成。
完整路径仍通过原来的 `Planner::value` 比较与执行准入检查，不能用线性估值替代它们。
组合发生改变后刷新信号；已计入当前作物流的首日服务动作保留到执行端。

## 兼容与验证

- 默认开关为 0，旧配置不变；Python 包装接受上一版设置 ABI。旧二进制显式启用新功能会要求重编译。
- 新 C++ ABI 接受上一版设置数组前缀，新字段自动为 0。
- 2,808 个有限差分对拍：覆盖 9 商品、多个剩余期限、现金短缺、负商品流、竞争权重及两种 DP 折现。
  参考答案逐次调用完整 `Planner::value`；最大绝对误差约 `1.3e-11`。
- 额外检查单期真实增量收入、自有供给的价格挤压、关闭现金惩罚时无关商品的独立性、
  动物服务 DP 与穷举动作序列一致、组合信号刷新后已接受作物的首日服务保持一致。
- 官方引擎双座完整轨迹：新开关为 0 时，新旧二进制 1,438 帧动作完全相同。
- 七强收益实验：同 seed 双座，16 seeds，每臂 224 局。结果见下一节。

这次结果没有支持“将报价直接替换为条件目标的边际值即可提升胜率”。
数值实现成立，策略效果失败；不能据此断言所有未来价值建模方案无效，也不能把失败完全归因于
某一种预测误差。本轮尚未完成逐阶段因果消融。

## 复现

先在基线提交编译并保存 `policy/r1/agent.so` 为 `work/agent-before-marginal.so`，
再在本实验分支执行：

```bash
bash policy/r1/build.sh
g++ -std=c++20 -O2 experiments/test_r1_marginal_value.cpp \
  policy/r1/executor/vendor/simulator.cpp -o work/test-marginal
work/test-marginal
python experiments/test_r1_marginal_value.py \
  --baseline-binary work/agent-before-marginal.so
python experiments/run_strong_ab.py \
  --baseline policy/r1/agent.py --candidate policy/r1/agent.py \
  --candidate-r1-config '{"marginal_value":1}' \
  --seeds 16 --start 2610500100 --workers 8 \
  --output work/marginal-final-public7-16seed.json
```

测试使用仓库已有 `run_strong_ab.py` 的官方引擎和七强对手，不引入简化游戏规则。
新增计时字段 `wall_seconds` 与 `decision_seconds` 分别记录整局与本方决策累计墙钟时间；
多进程并发下只能作为粗略开销观察，不能解释为严格的单核延迟 benchmark。

## 仍然存在的模型边界

数值对拍只证明边际计算符合现有条件目标，不证明目标能够准确预测真实终局输赢。
未来商店是期望值，对手后续改种、销售时点和投入仍有预测误差；仓储、运输和劳动可行性
最终交由现有执行器处理，价值函数里的劳动成本并非完整路线优化。
生命周期子问题还使用固定劳动影子价格；固定成本与工资的现金紧张程度没有全部转化为同一组对偶价格。
现有组合选择仍是带准入检查的贪心/局部改进，不提供全局最优保证。

后续应先对真实败局做分阶段预测残差分析，分别校准对手供给、实际兑现时点、劳动与现金约束；
再比较报价路径与边际路径的候选并集、多个供需场景下的保守增量收益。
有稳定样本外收益后，才值得扩大组合搜索或进行冷/温接管验证。
