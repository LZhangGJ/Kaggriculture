# R1 系统的理论分析

配套 `ARCHITECTURE_AND_FINDINGS_ZH.md`（那份讲"是什么"，这份讲"为什么"）。
目的是从第一原理出发，指出**哪些设计在理论上站得住、哪些不成立**，以及由此推出的改进方向。

## 当前总判断（2026-09-22）

当前 R1 **不是“一个已经完善、只是没有求到足够精确解的数学模型”**，而是以下几种对象的串接：

`单轨迹对手供给预测 → 部分闭合的场景模拟 → 一日绝对现金 → 重新起钟的折现 tail → gain/cost^α 贪心 → preview/repair 执行`

各段都包含有价值的成熟部件，但它们没有共同定义同一个目标、状态转移和可行域。因此“把当前优化器
算得更精确”并不推出接近真实最优；它最多接近当前 surrogate 的最优，而当前 surrogate 与真实胜率
之间没有一致性保证。

一个“数学模型较完善，所以求解应接近最优”的论断至少需要四个前提：

1. 状态转移产生合法、守恒、时间索引一致的轨迹；
2. rollout 与 tail 是同一效用的 Bellman 分解；
3. optimizer 的可行集等于 executor 真正可执行的计划集合；
4. surrogate 对真实目标有可校准的统计关系，并报告其近似误差或 regret。

当前四项都尚未满足。已经由内部反例直接确认的不是“小精度问题”，而包括：对手供给与资产状态不闭合、
rollout/tail 折现重新起钟且会改变 winner、静态预算不代表现金路径、`gain/cost^α` 不求解声明的价值最大化、
proposal/joint 使用嵌套 argmax。故后续需要重建**数学语义链**，但不需要推倒工程：`Asset` 现金流表示、
官方价格曲线、精确成交 primitive、公开状态桥、执行器和 replay 前缀均可复用。

固定顺序为：合法状态转移与市场守恒 → 时间一致的 deterministic objective → 明确的逐时可行域 →
可测内部 regret 的优化器 → 多情景 margin 分布上的胜率/CVaR。任何端到端胜率只在这些层完成后作为
部署门槛，不能反向裁定已证明的不变量。

## 一、目标函数：我们优化错了统计量

**引擎的计分**：第 29 天各自的现金，`own > rival` 即胜。

**我们的规划器实际最大化的是** 单条确定性预测上的 `own − 2·rival`；它既不是严格的
`E[own-rival]`，也不是胜率。
**而目标是** 最大化 `P(own − rival > 0)`。

**这两者不同。** 在 margin 的分布上：

```
            输的局                赢的局
   ─────────┬───────────────────┬─────────
           0│                   │
       (尾部)│←── 胜负由这里决定 ──→│
```

- 提高 **均值**：向整条分布加一个常数 → 只有落在 0 附近的少数局翻转
- 提高 **左侧尾部**：把最差的那批局拉起来 → 直接翻转

**这解释了整个项目里反复出现的模式**：sale DP 把 margin 抬高 **+356**，胜率却净 **+0**；`animal_bias`、`discount` 这类改动同样"均值动、胜率不动"。**+356 相对于 margin 的段内标准差（约 3,000~4,000）只是 0.1σ，翻转不了几局。**

**定量标尺**：`max_animals` 20→40 在 2670 段上给出 **+2,211 margin → +6.2pp**。即在这个分布上，**约 350 margin ≈ 1pp**。要把 thomas 从 75% 推到 90% 需要 **约 +5,300 margin**，而 DP 的 +356 只有它的 1/15。

**理论结论 1**：目标是 `P(margin>0)`，不是期望或某个固定分位数；CVaR/分位数只能作为显式选择的
风险代理。现有单情景线性估值**在数学上无法表达“我要赢”这件事**。

## 二、经济结构：这是一个共享需求曲线的 Cournot 博弈

**生产端**：`种子 + 劳动 + 土地 → 作物`；`小麦 → 动物 → 畜产品`。
**需求端**：每个商品一条向下倾斜的价格曲线 `price_i(inventory)`，库存随双方总供给上升而价格下跌，下限为 1。

所以**单位收入 = price_i(市场库存)**，而市场库存由**双方合计**的供给决定。**这是一个标准的 Cournot 双头博弈**，区别在于：

- 生产有时滞（作物 3~12 天成熟），所以是**动态** Cournot
- 有资本积累（土地、动物），所以有**投资**维度
- 商品之间通过**劳动力和棚容**耦合（争夺同一批工人、同一个 100 单位棚子）

**Cournot 的标准结论**：双头各自的最优反应产量 > 联合最优产量 ⇒ **在均衡里双方都倾向于过度生产、把价格打下来**。

**而我们的目标函数是 `own − c × rival`**。其直接含义是：

| c 的取值 | 含义 |
|---|---|
| 0 | 只最大化自身终局现金 |
| 1 | **精确的线性 margin：`own-rival`** |
| >1 | 超额惩罚对手现金：宁可自己少赚，也可能选择让对手损失更多 |
| −1 | `own+rival`，这才是联合利润（合谋）目标 |

**而胜负正是比较双方现金** ⇒ 在**线性 margin** 下 `c = 1` 才是自洽的。
**但目标是胜率（阶跃函数）** ⇒ 伤害对手的边际价值**依赖于当前 margin 的位置**：在 0 附近极高，在大幅领先时为零（已经赢了，再压对手不加胜率）。

**这解释了那个反直觉的实测结果**（`competition` 从 2 降到 1 反而更差）：**c=2 是"在 margin 分布上取平均"的一个粗略代理** —— 我们大量的局处在 margin 不大不小的区间，那里伤害对手确实值得加倍权重。

**理论结论 2**：共享价格外部性不是 `competition` 的另一种权重，它已经通过“双方成交共同推进同一市场库存”进入状态转移。`competition` 只是在结果层决定如何计入对手现金：`1` 是 margin，当前 `2` 是经验性的超额对抗权重。若要优化胜率，不能再调一个全局 `c` 冒充尾部风险；必须在多情景 margin 分布上定义胜率或 CVaR。

## 三、控制问题：我们把它切成了四个子问题，其中一个是错的

**决策空间**（每步、每天）：
1. **组合**：100 块地 × 8 种项目 × 时机
2. **劳动力**：每个工人这一步做什么
3. **市场**：卖什么、卖多少、何时卖；买什么
4. **资本**：买地、买动物、雇工

**现在的切法**：

| 子问题 | 方法 | 理论上成立吗 |
|---|---|---|
| 组合 | 逐地块贪心，按"加进去后整个组合 `value()` 的增量"排序 | 会重算完整代理值，但不是该代理目标下的全局约束最优 |
| 劳动力 | 执行器把 `core.target` 展开成动作序列 + 各种修复 | 接近（组合已定，是个调度问题） |
| 市场 | 桶内贪心（本地规则），可选 DP | 局部成立 |
| 资本 | 折进组合的 `first_cost` 与 `rank` 分母 | **✗ 不成立** |

**更正**：我最初写的是"逐地块贪心在一个不可分的目标上做坐标上升 ⇒ 系统性超配"。**读过 `triad.hpp:443-451` 后这是错的**：

```cpp
auto next=portfolio;add(next,a);double val=model.value(o,next);   // 对整个组合求值
...
current=bestval;                                                   // 基线随接受而前移
```

每次候选评估都把**整块地加进去后对整个组合重新估值**，而 `value()` 里 `cash += trade(i, inv[i], a.f[d][i])` 用的是**组合当天的全部产出**并推进 `inv[i]` —— **自身的价格冲击是被定价、被惩罚的**。准确说法是：它正确计算了“把一个项目加入当前组合”在**既定代理目标**下的边际值；这不意味着代理目标等于真实胜率，也不意味着贪心求出了该代理目标的约束最优解。

**它真正的局限至少有四点**：
1. **地块的处理顺序**（`free` 按 `near(a)` 排序）会影响结果 —— 贪心的顺序依赖，非最优但不算错。
2. **一块地只能选一个项目、且不接后继**（`rotation=0`）—— **这是对可行集的硬性限制**，短周期作物因此无法被串起来。
3. 候选先算完整 `gain`，再用 `gain / cost^α` 排序，同时只扣一个静态 `budget`；这不是
   `max value(portfolio)` 的现金约束优化，可能用低 NPV/低成本项目挤掉高 NPV 项目。
4. 计划现金约束只看当前现金、0.85 倍 shed 清算值、reserve 和少量 feed cover；它不是逐日现金路径约束。
   `risk·liquidity` 又在现有轨迹中基本为零，最终可执行性依赖 preview/repair 事后删项目。

**为什么资本的折法不成立**：买地、买动物是**投资决策**（今天花钱，未来多产），它和"这块地种什么"是不同性质的决策，却被压进同一个 `rank` 的分母（`pow(cost, capital_power·(1−money/16000))`）。`max_animals` 20→40 值 +6.2pp 就是这个折法在泄漏价值：**当上限不是紧约束时，投资的最优规模由边际收益决定，而不是由一个人工上限决定。**

**理论结论 3**：**这里原有一个"应改成产出组合的凹优化"的结论，已撤回**（前提不成立，见上）。
留下的问题需要按内部 surrogate regret 与执行可行性分开测量，而不是直接重构：
- 贪心的**地块顺序依赖**（`free` 按 `near(a)` 空间排序）—— `portfolio_swaps=1/2` 已做过局部邻域实验，端到端为 0 或负；这不能证明贪心正确，只说明在旧估值和旧参数补偿下继续扩大局部搜索不能直接部署
- **`rotation=0` 的可行集限制** —— 但 `rotation=1` 实测显著更差，**在没想通它为什么更差之前，动它没有意义**
- **资本/现金约束求解错误** —— 应先在固定状态上报告“贪心解与声明目标下更优可行解”的内部 regret，
  再判断是优化器问题还是价值模型问题；不能用完整胜率直接裁定求解器是否数学正确

32 个独立 warm handoff 状态的内部审计已经确认这不是纯理论担忧：最终胜出 proposal 在 `9/32`
状态存在 ratio 选择与最大边际 `model.value` 选择的分歧，局部 value regret 最大约 `$249`，3 个状态的
局部 regret 和超过当时 top-2 gap。隔离地按边际 `model.value` 排序后，外层 proposal winner 在
`4/32` 状态换序，最高 score 的单状态变化为 `−236..+762`。负号不是 value 排序“理论上更差”的证据，
而是另一处目标不一致的直接反例：内层 `model.value` 与外层 rollout+tail score 不是同一个效用。
因此不能先对旧 surrogate 做昂贵 exact 搜索；必须先统一状态转移和 Bellman 目标，再测 solver regret。

进一步把 open-loop 对手供给、固定 Bellman 时钟和精确市场 primitive 同时启用后，反号仍未消失：
value-order 相对 ratio 的外层最高 score 在 32 个独立状态中 13 升、10 降、9 不变。这定位出比排序器
更上游的**控制时域错配**：`Controller::plan()` 按项目持续到终局的 portfolio 价值生成候选，
`SearchController::score()` 却只执行该候选一天，随后恢复 common base 并重新规划。也就是说，生成器
求长期承诺，评分器求一日干预；两者即使各自精确也不是同一个优化问题。下一步的 solver audit 必须直接
搜索首日可执行 bundle，并用统一外层 continuation score 评叶，不能再把长期 `model.value` 当作真目标。

直接外层邻域已经验证该错配具有高覆盖：32 个独立 handoff 状态、658 个可行单-slot 反事实中，25/32
状态存在优于默认 winner 的邻居；即使和既有 default/single-swap/double-swap 的最好结果相比，仍有
23/32 改善，最大 `+506`。更关键的是，25 个改善状态中有 15 个最佳邻居的长期 `predicted` 下降，
20 个最佳强制项目不是局部 `value_kind`。所以不能把长期 value 当成 outer search 的无偏启发式；它在
大多数可改善状态上方向都可能反。首日 bundle search 必须周期性用真实 continuation score 截断/重排
beam，而不能只在叶节点为长期 value 选出的少数候选补一次外层评分。

width-2 外层 beam 又在 17/32 状态超越一阶邻域，增量合计约 `+898`；相对所有既有模式，25/32 状态
仍有改善且 16 个最终解需要两个 slot 联动。width 4 在首批 8 状态把二阶叶近乎翻倍却没有新增最优解，
所以当前证据支持“小宽度、outer score 周期性重排”，不支持继续扩大枚举，也不支持独立地修单格。

固定 suffix 又把问题进一步定位到 continuation，而不是首日 transition。8 个真实 handoff 上，outer
候选预测的首日 `c2=own−2·rival` 差分合计 `+5,615`，实际下一日为 `+4,881`，符号 8/8 一致；但模型
隐含 continuation 仅为 `−4,696`，真实终局反推为 `−11,813`，非零状态方向只对 `3/6`。真实首日
margin 合计 `+4,691`，到终局却变成 `−2,800`。因此首日 outer search 找到的收益多数确实兑现，错误
主要是对动作后状态的后续重规划/尾值估计不足。下一步应逐日审计 continuation 的 Bellman 残差和状态
分叉，不应继续加 beam 宽度。该结果只有 8 状态，且两臂都绕过 joint-bundle 后层，只是内部定位证据。

逐日分解进一步表明，缺失状态是对手跨日库存与成交策略。8 个状态的终局差分中，我方现金合计 `+1,332`，
对手现金却 `+4,132`；对手公开资产计数 8/8 不变。Thomas seed100 在 day24 已能从公开账本得到 WOOL
库存区间 `[0,33]`，随后候选使市场库存/价格分叉到 `−51/+195`，对手多赚 `$5,659`。近三日成交小时
密度不能解决：它仍假定每天产出当天卖完，并在该反例上把错误 outer gain 从 `+89` 提高到 `+176`。

因此 continuation 的状态必须从 `public farm + market` 扩为 belief：

`Z_{t+1,i}=Z_{t,i}+H_{t,i}-S_{t,i}`，

其中 `Z` 是对手隐藏库存，公开地块变化和市场守恒给出区间/后验约束，`S` 的分布必须条件于价格、小时、
剩余天数和公开成交历史。候选会改变价格，所以 `S` 不是候选公共常数。正确的近似是对即时卖、持有和
终局清仓保留多个公开可生成情景，再比较 margin 分布或稳健下界；把 upper 乘固定权重后全部注入今天，
既不满足状态转移，也正是旧 pending-stock 实验失败的语义，不能据此否定库存状态的重要性。

但库存 belief 不是当前最上游的一处错误。用既有 sale DP 对同一 forecast flow 做跨日最优清仓，Thomas
seed100 的 WOOL 价值会对各相关候选共同下降约 `$6,994`，winner 却不变：库存时序的绝对误差很大，
候选差分在这个局部仍小。相反，保持同一对手点预测、只让控制器按真实语义逐日重规划到终局，6 个非零
outer 反事实的方向由一日静态 tail 的 `3/6` 提高到 `5/6`，聚合由错误的 `+919` 变为 `−2,053`，接近
真实 `−2,800`。所以当前优先关系是：

1. 先让 continuation 评价实际执行的闭环策略，而不是“长期静态 portfolio”；
2. 再把对手隐藏库存和条件成交响应作为闭环状态/情景补入；
3. 最后才在同一闭环目标下审计 solver regret、风险目标和经验参数。

1/3/5/10 日截断的候选方向并不单调，不能把一个较短 horizon 当成可靠近似。终局闭环本身也仍使用单条
open-loop 对手供给，所以它是对控制时域错误的隔离证据，不是完整的博弈解。任何 top-K 加速必须保持
候选集嵌套：扩展候选集后的最优值不能低于原集合；一次各自按短分截 top-4 的实验违反了这一不变量，
其 `−1,939` suffix 结果不得用来裁定 outer search。

修正为嵌套候选集后，闭环重排 normal 相对旧 normal 的真实 margin 合计提高 `+9,774`，证明第一步方向
有效；但额外 outer 相对闭环 normal 的预测为 `+7,970`、真实为 `−430`，非零方向只对 `2/4`。这不是
闭环定义又错了，而是典型的 **optimizer's curse**：候选集合扩大后，`argmax` 优先挑中单条对手预测的
正误差。故“闭环 Bellman 一致”是必要条件，不是充分条件；其后必须对对手响应保留非退化情景，并按
期望/下分位数选择，而不能对一个点预测继续扩大搜索。

## 四、估值函数 `value()`：逐项理论审查

```cpp
val = Σ_d [ cash_d − c·enemy_d ] / (1+r)^{d−day}  −  risk·liquidity
```

| 项 | 理论问题 |
|---|---|
| `cash_d += trade(i, inv, a.f[d][i])` | **假设当天产量在"盘中某一点"一次性卖出**。引擎实际在我们选的任意一步成交。日粒度 ⇒ 与执行器的 4 步节奏不匹配（已实测：日内分布对结果影响很小，所以这一项近似成立） |
| `enemy_d += trade(i, inv, supply·rival[d][i]·.5)` ×2 | `rival` 曾是结构性缺失的（4 个商品恒为 0，已修 `replant`）。**而且 `trade` 对数量是凹的** ⇒ `supply` 不是可分离的缩放，不能与 `competition` 互替 |
| `dem[d][i]` | 与引擎逐字对应，**这一项是对的** |
| `pow(1 + cfg.discount·max(0,1−money/20000), d−day)` | 钱过 2 万后**基数为 1 ⇒ 完全不贴现**。即：一旦有钱，规划器认为第 13 天的 1 块钱 = 第 29 天的 1 块钱。**这抹掉了资本的时间价值** —— 而正是它导致了 sale DP 的囤货倾向（囤货在模型里免费） |
| `risk·liquidity`，`liquidity = Σ max(0, −balance)` | 唯一的**风险项**。**实测：`risk` 从 0 扫到 10，四个臂逐位相同（Δ=0）—— 因为规划器投影的累计现金流从不为负 ⇒ `liquidity ≡ 0` ⇒ 这一项是惰性的。** 所以 `value()` 在实践中是**纯粹的风险中性期望最大化**，没有任何风险意识 |
| 报价 `quote(i, inv, q)` | 单位价格函数与引擎一致；批量平均报价并不等于官方逐单位成交，跨过 `$1` 地板时还会错误地推进全部库存或完全不推进。该项是已确认的模型不变量错误，不因孤立修正后的旧参数端到端 A/B 下降而变成“正确” |

**另外**：`val` 对 `a` 是**线性**的（`Asset` 的流量逐日相加、`value` 逐项求和），但 `trade` 对数量是**凹**的，而每次候选评估都传入**整个组合**的流量 —— 所以自身的价格冲击仍然被定价。这一项原被我当成"线性化丢掉了总产出依赖"，**是错的，已撤回**（见第三节的更正）。

## 五、执行层：一个被证实的高风险结构

**`settle_market` 的第一行**：
```cpp
if (s.delay_sale<0 || (preparing && s.feed_finance<=0)) return;
```
`preparing = core.phase==1`，而 `Controller::plan` 把 `core.phase` 置 1。**所以换天那一步（core 做当天主决策的一步）整个函数直接返回，卖出完全不过滤。**

这不是一个小 bug，而是**一个结构性的事实**：卖出决策实际发生在两个不同的地方，且它们在时间上交错：
- 换天步：`core.act` 自己决定（无过滤）
- 其余步：`settle_market` 过滤

**任何"卖出层"的改动都必须同时考虑这两条路径**，否则就会像本次会话里那样，出现"计划看起来在跑、结果完全不变"，或者更糟 —— 改动一条路径后另一条路径的行为突变（我曾因此让牲口饿死，−28,178/局）。

**另一个结构性事实**：`project_sales`（那个按值捕获 `local_sale` 的 lambda）**只在 `project()` 里被调用，而 `project()` 是预测用的模拟器**。线上真实的卖出路径是 `settle_market`。**这一点极易误判** —— 我最初以为 `project_sales` 是执行路径，浪费了大量时间。

## 六、由此推出的改进方向（按理论价值排序）

### A. 先保留不确定性，再谈“胜率目标”（最高价值）
现状并不是严格的 `E[margin]`：R1 把未来未知商店压成均值、把对手供给压成单条点预测，然后对这一个
确定性未来最大化 `own - 2*rival`。

仅把这个确定性分数套上 sigmoid、截断或“接近 0 加权”等单调非线性，**不会改变任何候选排序**：
若 `m(a) > m(b)`，则对任意单调 `g` 仍有 `g(m(a)) > g(m(b))`。因此旧建议中“无需新信息，给
`val` 加非线性即可变成胜率目标”在数学上不成立。

`P(margin>0)` / CVaR 只有在模型保留一组可能未来时才有定义。正确顺序是：

1. 对未来商店、对手成交时序或模型残差保留多个**公开信息可生成**的情景；
2. 对每个候选得到 margin 分布，而不是一个点值；
3. 再按胜率、下分位数或 CVaR 排序。

这不要求识别对手身份，但要求新增不确定性模型和多情景计算；在当前 R1 已很慢的前提下，不能把一个
单调变换伪装成低成本修复。现有 `risk·liquidity` 只惩罚模型内资金为负，也不是终局 margin 风险。

### B. ~~组合的凹优化~~ —— **前提已被证否，撤回**
我原先写的是"逐地块贪心在不可分目标上超配，应改成 9 维产出组合的凹优化"。
**读过代码后这条不成立**：贪心每次都对整个组合求值，自身价格冲击已被定价（见第三节的更正）。
所以这条不是缺陷，不需要修。
**不存在原先声称的“未计自身价格冲击”缺陷**，但 constrained solver 仍然是启发式：
- 贪心的**地块顺序依赖**（`free` 按空间顺序，非按价值）—— 局部交换已经实测为 0/负，只能说明旧整套系统下不能直接部署，不能证明求解器无 regret
- **一块地一个项目、不接后继**（`rotation=0`）—— 这是对**可行集**的限制，`rotation=1` 实测更差（−3,008），所以"放开限制"本身不是答案，需要先想通它为什么更差（见第七节）
- `gain/cost^α` 加静态 budget 不是声明代理目标的严格预算最优解；若要判断贡献，应在固定状态上求内部
  上界或受限 exact/beam 解并比较 surrogate regret，而不是先跑完整胜率

### C. 把资本决策独立出来
现状：买地/买动物折进 `rank` 的分母。
应为：`max_animals` 的经验（+6.2pp）已经证明这个通道很值钱。**把"该养多少动物、该开几块地"当成一个显式的投资问题**，其最优规模由边际收益决定。

### D. 先统一时间效用，再校准贴现
现状：`max(0, 1−money/20000)` 使现金过 2 万后不贴现；更根本的是 `score()` 把未贴现的一日绝对现金
与在边界重新起钟、重新按候选现金设折现率的 tail 相加，不满足同一目标的 Bellman 拼接。
应先二选一并保持全链一致：若目标代理是终局现金，就不应凭空贴现；若保留时间价值，就应从起点冻结
同一折现语义并正确折现 continuation。不能先根据端到端结果盲调 `discount`。

### E. 卖出层的两条路径统一
把换天步也纳入过滤（但要在**不触发那条融资分支**的前提下 —— 我试过，直接把 `settle_market` 全部启用会让采购断粮）。

## 八、完整计算图的一致性条件

真实问题是一个部分可观测随机博弈。令 `b_t` 为基于公开历史和己方私有库存形成的 belief，终局现金差为
`M_T`，理论目标是：

`J_t(b_t) = max_π E[1{M_T > 0} | b_t, π]`。

当前 R1 实际计算的是：

`Q_hat(a|o_t) = one_day_cash(a, r_hat, d_hat) + V_theta(o'_{t+1}, portfolio_tail)`，

其中 `r_hat` 是单条对手供给预测，`d_hat` 把未知商店压成均值，`V_theta` 是折现后的
`own_flow - competition*rival_sales`。这不是同一目标的数值近似，而是经过多次问题替换后的排序代理。

逐层必须满足以下条件：

| 层 | 必须满足的条件 | 当前状态 |
|---|---|---|
| 信息 | 线上只使用公开历史与己方私有状态，不使用对手身份/隐藏 seed | 满足；147 维只属于 replay 路线树，R1 本身读取完整公开观察与己方 private |
| 场景转移 | 注入市场的供给、对手现金和产生供给的资产状态必须属于同一条轨迹 | **违反**：聚合供给已成交，但对手资产未同步；tail 又从 stale board 重算 |
| 市场守恒 | 每单位成交按官方顺序报价；价格触底后成交仍给钱但不推进库存 | 正式 `R2_MARKET_INTEGRAL=0` **违反**；已有精确 primitive |
| 目标 | 候选生成、候选选择、sale 层与最终验收应对应同一效用，或明确记录代理关系 | **违反**：生成/选择主要用 `c=2` 点值，sale DP 用 `c=1`，验收是胜率 |
| 不确定性 | 若目标是胜率/CVaR，同一候选必须有非退化的 margin 分布 | **违反**：未知商店、成交时序和模型残差都被压成一个点 |
| 优化 | 在声明的代理目标与现金/资源约束下，求解器应返回可解释的近似最优解并报告 regret | **未建立**：空间顺序贪心 + `gain/cost^α` + 静态 budget，无内部上界 |
| 计划—执行 | 估值中的项目、现金流和劳动必须可由 executor 实现；修复不得静默改变目标 | 部分满足：preview 会删未 admission 项目，但仍依赖大量事后 repair，且 finance 只完整覆盖 feed |
| 联合选择 | 若 action 为 `(proposal, joint bundle)`，应优化联合可行集，而非先选 proposal 再只搜其 bundles | **违反**：当前是 `argmax_p` 后才搜索 `J(p*)`；现有 joint 触发少，影响量级仍待内部审计 |

### 哪些“缺项”在候选比较中会抵消

`enemy` 没有对手工资、种子和投资支出，因此不能解释为对手终局现金。但若假设对手未来策略和支出
完全不随我方候选变化，这些缺项是候选公共常数，会在 `argmax` 中抵消。真正影响排序的是：

- 我方候选通过共享价格改变对手销售收入；
- 对手会响应我方公开动作，使其数量或支出不再是常数；
- stale 场景使不同候选落在不同市场库存上，公共供给误差与候选供给产生交互。

因此不能仅凭“少算了对手成本很多钱”判断它贡献很大；必须写出候选差分后再估量级。

### 后续审计顺序

1. 先修复并验证场景状态闭合、逐单位市场守恒等规则级不变量；
2. 在固定 observation / fixed portfolio 上分解各项对候选差分的贡献；
3. 在同一代理目标内计算 greedy/预算求解的内部 regret；
4. 只有前三层一致后，才用多情景 margin 分布替代单点 `c=2`；
5. 最后重新校准补偿参数，并以完整 warm 链决定是否部署。

端到端下降可能是误差补偿被拆开，不能用于否定第 1 层的正确修复；端到端仍是第 5 层不可省略的部署门槛。
