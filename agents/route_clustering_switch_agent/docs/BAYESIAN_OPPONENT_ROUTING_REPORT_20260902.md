# 贝叶斯前缀对手识别与反制路线库方案（2026-09-02）

## 结论

可行，但不能把问题简化为“前 `n` 天硬聚类，然后每类固定选一条路线”。建议把系统
拆成两个相互独立、可分别验证的部分：

1. **贝叶斯对手信念**：根据已经发生的公开轨迹，持续维护对手属于各路线或路线类别
   的概率；信息不足时明确保持不确定，而不是强行分类。
2. **类别反制路线库**：使用 C++ 引擎、遗传搜索和对局矩阵，为一组需要相似反制的
   对手路线生成少量共享路线；每条候选以类别内的稳健覆盖衡量，而不是只看平均胜率。

贝叶斯方法解决“现在更可能面对谁、是否值得切换”，不负责凭空生成新路线。新路线仍
由 replay 初代、遗传变异、block/continuation 组合和 self-training 产生。

建议的最小闭环为：

```text
公开前缀轨迹
  -> 对手类别后验
  -> 共享反制路线库
  -> 后验期望收益与风险门控
  -> KEEP 或最多一次路线切换
```

## 1. 当前系统与缺口

当前生产 agent 已经证明“有限路线库 + 公共状态 selector”可以工作：

- 652 路线对手池总体原始胜率 95.51%，最低单对手 82.81%。
- 运行时从大规模实验候选压缩为 7 条活跃路线。
- selector 读取 147 维公开状态，检查 48/96 回合，在线最多切换一次。
- 未见状态回退共同开局 `NR295`，不使用对手 ID、seed 或未来信息。

这些结果见 [全池联合路线进化与 selector 实验](JOINT_ROUTE_EVOLUTION_SELECTOR_20260827.md)。

现有路线族的距离为：

```text
0.45 * 生产组成距离
+ 0.35 * 布局距离
+ 0.20 * 累计宏观动作时序距离
```

它适合做 replay 去重和行为族谱，但没有回答两个关键问题：

- 两条行为相似路线是否真的需要相同反制；
- 线上只观察到前几天时，当前证据能否区分这些路线。

当前 `fingerprint_distance` 也是一次性的加权状态距离，不是随时间更新的对手后验。
`route_evolution.py` 中已有的 `posterior` 只表示遗传算子的 Beta 平滑成功率，与对手
识别无关。

最近 block/tail 实验还说明：oracle 能在部分状态找到更好的 continuation，不代表盲目
拼接或一个未校准 selector 能稳定选中它。因此本方案必须同时包含候选安全性、后验
校准和 `KEEP` 门控，不能只替换聚类算法。

## 2. 两层类别，而不是一个 200+ 类标签

建议明确区分两种类别：

### 2.1 观察类别

表示前 `n` 天“看起来相似”的对手轨迹。它只用于构造似然和更新后验。200+ 个观察
类别本身不是问题，因为在线保存数百个概率的成本很低。

### 2.2 反制类别

表示面对我方候选路线时具有相似胜负响应的对手集合。它由对局矩阵决定，而不是仅由
布局相似度决定。多个观察类别可能共享同一个反制类别；前期无法区分、但后期需要不同
反制的路线则保留为一个混合后验，等待新证据。

因此线上不需要为 200+ 类复制三条路线。合理的结构是：

```text
数百个观察原型
  -> 数十个反制类别
  -> 一个共享候选路线库
  -> 每类只保存候选的权重或排名
```

## 3. 前缀表示

在第 `n` 天边界提取序列特征，首版检查点建议为第 2、4、6、8、12 天。具体维度由
数据契约固定，不在报告中预先写死。每个检查点保存以下信息的快照和增量：

- 对手公开资源与资产；
- 作物、动物、设施、土地和 farmer 数量；
- 布局的分区计数、坐标摘要和解锁状态；
- 新发生的买地、雇工、建造、放置动物、播种和出售等事件；
- 过去若干天的动作节奏和事件时点；
- 公开市场和商店环境；
- 我方公开开局行为。

用于“对手身份”的主特征只取对手公开轨迹。市场和我方开局作为条件变量进入似然，
因为同一计划可能因库存、价格或我方竞争而执行失败；它们不应被误解释为对手身份。
我方私有资源只用于判断我方路线是否可执行，不进入对手类别特征。

单个快照不足以描述路径，必须同时保留日增量和事件时间。例如“两条路线在第 4 天
都拥有一块新土地”，可能分别在第 2 天和第 4 天购买，后续资本压力并不相同。

## 4. 贝叶斯信念模型

令 `c` 为反制类别，`x_t` 为第 `t` 天新增的公开证据，`z_t` 为市场和我方开局等
上下文，则每天更新：

```text
P(c | x_1:t, z_1:t)
  ∝ P(x_t | c, x_1:t-1, z_1:t) * P(c | x_1:t-1, z_1:t-1)
```

### 4.1 v0 模型

首版不需要神经网络。建议在 log 空间实现以下模型之一，并以验证集选择：

- 收缩协方差的对角 Gaussian/Student-t 类条件密度；
- 对标准化前缀向量的 kNN/kernel likelihood。

先验来自训练窗口内的路线频率并做 Dirichlet 平滑，同时限制最大先验占比，避免每天
重复出现的同一提交压倒其他路线。模型输出完整后验、熵、最大后验和 OOD 分数。

### 4.2 贝叶斯不能解决的事情

如果两条路线在当前所有可观测量上完全相同，任何模型都无法提前区分。正确输出是
“二者仍然都有概率”，并选择对这个信念集合稳健的路线，而不是提高模型复杂度制造
虚假置信。

### 4.3 UNKNOWN/OOD

必须保留一个未知类别。当所有已知类别的最大似然低于训练分布阈值，或后验熵长期
过高时：

- 不执行类别专用切换；
- 继续全局稳健路线；
- 将该局轨迹加入离线困难样本池；
- 等新 replay 或 self-play 证据完成后再扩充类别和路线库。

## 5. 面向反制效果的聚类

对每条对手路线 `r`，使用固定候选面板 `a_1...a_m` 生成 payoff signature：

```text
u_r = [U(a_1,r), U(a_2,r), ..., U(a_m,r)]
```

`U` 至少包含跨 seed、双座位的原始胜率、margin 和不确定性。反制类别主要由
`u_r` 聚类；前缀距离只决定这些类别在第 `n` 天是否可辨认。

如需一个联合诊断距离，可使用：

```text
d(r_i,r_j)
  = alpha * d_prefix
  + beta  * d_continuation
  + gamma * d_payoff
```

但上线标签应优先服从 `d_payoff`：看起来不同但能被相同路线覆盖的对手可以合并；
看起来相同但需要不同反制的对手不能被硬分，只能暂时保留混合后验。

类别数不再由 silhouette 或 average-linkage 阈值单独决定，而由以下量共同选择：

- 类内反制 regret；
- 前缀可辨认程度；
- 每类所需最小路线数；
- 封闭验证集上的策略收益。

## 6. 每类少量路线如何生成

先使用现有 replay 路线、已入选遗传路线和 block/continuation 候选构造初始候选集，
再以类别内完整对手面板进行遗传搜索。候选不能只对 medoid 或一个代表路线评估。

对反制类别 `C` 和候选集合 `S`，最直接的覆盖目标是：

```text
max_{|S| <= K} min_{r in C} max_{a in S} U(a,r)
```

实际实现应使用胜率下界或平滑后的 mean/CVaR/min 组合，避免纯 `min` 被小样本噪声
控制。`K` 的 v0 默认上限为 3，但路线在类别之间共享。

遗传适应度继续沿用已经验证有效的原则：奖励“加入当前策略后的边际覆盖”，而不是
候选单独的平均胜率。任何候选在进入 counterbank 前都必须通过：

- 完整 719 回合执行检查；
- 多 farmer/hand 数一致性检查；
- 双座位和独立 seed 检查；
- 对当前全局池的不退化门槛；
- 对本类别困难路线的覆盖下界。

## 7. 在线选择与切换

对可执行候选 `a`，使用后验风险调整分数：

```text
score(a)
  = sum_c P(c | prefix) * U_LCB(a,c)
  - lambda * tail_risk(a)
  - mu * switch_cost(a,current_state)
```

只有当最佳候选相对 `KEEP` 的预期增益超过验证集确定的门槛，而且候选满足 continuation
contract 时才切换。后验熵高并不必然禁止切换；如果同一候选对整个后验支持集都稳健，
仍可以切换。

v0 保持当前执行层“共同开局 + 最多一次切换”，避免同时改变识别、候选生成和多阶段
执行三个变量。若 v0 成功，再扩展为每日 belief 更新和多阶段 block router。

## 8. 与模型化 agent 的关系

贝叶斯后验本身就是一个紧凑的对手 belief embedding。后续 selector 不再只输入 147
维当前状态，而可以输入：

```text
[当前状态向量, 对手类别后验, 候选路线 embedding, continuation contract]
```

这使新增路线不必每次扩充固定输出头：候选成为模型输入，selector 学习的是
`state × belief × candidate -> value/rank`。首版仍用显式 payoff 查表和风险门控；当积累
足够 counterfactual 数据后，再替换为 candidate-conditioned ranker、GRU 或小型
Transformer。神经网络不是 v0 的必要条件。

## 9. 成功标准

`BAYESIAN-PREFIX-COUNTERBANK-v0` 首先是可证伪实验，不直接替换生产 agent。

必要条件：

- 贝叶斯后验混合在封闭测试上优于当前全局路线混合；
- 贝叶斯方法优于或等于前 `n` 天硬分类；
- 整体收益提升不能以明显降低最低单对手胜率为代价；
- OOD 回退相对当前 agent 不发生显著退化；
- 活跃路线库、模型大小和每回合计算成本在部署预算内；
- 最终集成仍满足总体胜率至少 90%、单对手至少 80% 的现有验收线。

辅助判断：贝叶斯方法应回收全局策略与“知道真实路线”oracle 之间有意义的一部分差距。
具体比例由开发集预注册，不能看过封闭测试后再修改。

## 10. 主要风险与控制

| 风险 | 控制方法 |
|---|---|
| 同一前缀对应多个后续路线 | 保持混合后验，以类别集合做稳健反制 |
| 市场导致计划未执行 | 市场只作条件变量；同一路线覆盖多市场轨迹 |
| 同提交 replay 重复造成先验偏置 | episode 去重、按提交限权、Dirichlet 平滑 |
| 类别数和路线数爆炸 | 观察类别与反制类别分离，路线跨类共享 |
| GA 对少量 seed 过拟合 | 分折训练、独立 seed、双座位、LCB/CVaR |
| 新对手不属于任何已知类 | UNKNOWN/OOD + KEEP + 增量 replay 回灌 |
| selector 学会错误置信 | 校准曲线、Brier/NLL、硬分类消融 |

## 11. 建议执行顺序

1. 实现前缀数据契约和离线提取器。
2. 用现有路线库构造小规模 payoff signature，验证反制类别是否明显少于行为类别。
3. 运行不生成新路线的贝叶斯路由实验，先证明“识别和路由”有增益。
4. 只对已证明存在 oracle gap 的类别启动 GA counterbank。
5. 通过完整全池不退化门槛后，才接入生产 selector。
6. v0 成功后再研究 candidate-conditioned 神经 selector 和多次 block 调整。

实施细节见 [实验规格](BAYESIAN_PREFIX_COUNTERBANK_V0_EXPERIMENT.md) 和
[数据/接口契约](OPPONENT_PREFIX_BELIEF_DATA_CONTRACT_V0.md)。
