## 3. 实际改了什么

这次没有重写 A06 R12 的底层执行器，也没有加入固定动作回放。最终性能变化来自**规则参数与已有时序模块的启用组合**；代码级额外改动是彻底移除旧学习排序器并拒绝其入口。完整差异见 `CHANGES.patch`。

### 3.1 现金紧张时，更看重较早兑现的收益

`discount: 0.005 → 0.12`。保留原版的现金相关折扣形式：

```text
折现系数 = 1 / [1 + discount × max(0, 1 - 当前现金/20000)]^(回款日 - 当前日)
```

这不是将未来产出直接当现金；仍由原规划器给出候选、滚动执行和尾部估值。改动提高早期资金紧张时对远期收益的折扣，现金达到 20,000 后这一折扣自动消失。它是人工规则参数，不是拟合出的价值模型。

### 3.2 启用基于本局公开成交的时段统计

编译开关 `R2_SALE_CLOCK_MODE: 0 → 2`。保留已有公开交易账本，使用本局可推断的己方/对方卖货时段，把对手预测供给分配到更合理的时间，替代固定早、晚各一半的假设。

仅处理可保守推断的非购买商品；跳过午夜边界和可能隐藏 1 元成交的区间。自己的和对手的同一商品都至少观察到两个卖货日后才使用相对时刻信息，统计最多保留最近三个有成交的日子；证据不足时回退到旧先验。没有读取对手仓库、未来动作、种子或未来商店。

### 3.3 缩减经济候选集合，而非关闭动态规划

`portfolio_passes: 6 → 4`，`candidate_extra: 1 → 0`。保留基准、偏早回款、偏作物、偏动物四类经济候选，并继续比较既有两种执行模式。去重前的组合上限由 18 降为 8，删除了本面板中不稳定的额外扩张/极端竞争候选。

每日候选比较、原作物/动物动态规划、现金与物料约束、日内修正、R11 恢复和 R12 收获交付链仍保留。所有对手、种子、座位使用同一份配置，没有按文件名或对手 ID 切换配置。

### 3.4 无 ML／RL

最终 `learned_value.hpp` 不含原来的已拟合排序器数据；`available=false`。负数 `scenario` 入口被拒绝。160 盘末尾调试记录全部显示 `learned_value_active=false`、`learned_value_available=false`。未训练或使用分类器、回归模型、价值网络、策略网络或 RL。描述性的局内成交频数不是训练出的策略。

## 4. 测试口径与限制

使用附件冻结的十个公开源码，而不是重新声称它们是实时天梯前十。附件原说明指出它们来自冻结的 `QUALIFIED_TOP20.json` 前十项。`01_prvsiyan` 与 `06_tetsutani` 源码 SHA-256 相同；其他多位也有共同代码血缘，因此这不是十个完全独立的策略家族。

验收种子固定为 `26092401` 至 `26092408`，每个种子交换座位各打一盘，共每对手 16 盘。两边都实时执行代理源码，互相响应当前局面，不播放已保存的对手动作。每盘执行默认规则的 **719 次状态转移**，按最终现金严格判胜。

原版和最终版的这 320 盘全部完成，没有代理异常或进程失败。这里的“没有错误”不是声称对全部可能状态做过形式化证明，也不等于检查到了每种静默 no-op。

**本次做过面板调优，不是封存的独立留出集。** 早期筛选用了另外三个开发种子；后期也用了上述验收种子的子集挑选候选，然后对固定最终版完整跑 160 盘。必须把 69.38% 理解为这个已参与调优的冻结面板成绩，不能外推为天梯胜率或新种子的保证。

同一初始种子不意味着策略改变后仍经历完全相同的商店序列：规则的每日随机数消费受空地数量影响，空地随双方行为改变；交换座位也可能改变随机数分配。我们保留了这种真实规则，不把商店路径另行冻结。最终版对 `01_prvsiyan`、种子 `26092404`，座位 0 以 127,991 对 122,188 获胜，而座位 1 以 111,285 对 120,377 失败。这是不能把单座位 7/8 直接外推成 14/16 的具体例子。

## 7. 使用与复现

提交压缩包解压后保持 `main.py` 和 `policy/` 相对路径不变，入口为 `main.py:agent(observation, configuration)`。附带已验证的 Linux x86-64 `a06.so`，不必先重编译。需要本地重编译时，在 `agent/` 下运行：

```bash
python3 build.py --unit
```

完整证据包根目录下，重跑相同 160 盘：

```bash
python3 inputs/verify_package.py
python3 evaluation/bench.py --agent agent --workers 4 --out evaluation/results/local_r13.jsonl
python3 evaluation/bench.py --variant baseline --workers 4 --out evaluation/results/local_r12.jsonl
python3 evaluation/summarize.py evaluation/results/local_r13.jsonl --baseline evaluation/results/local_r12.jsonl --out evaluation/results/local_comparison
```

每条命令默认即为 8 个固定种子、两个座位、十个对手。便携评测器只适配了路径、输出隔离和来源校验；实际 719 步对局循环与已执行版本的 AST 一致，见 `evaluation/PORTABILITY.json`。预编译模拟器不可用时运行 `python3 evaluation/build_sim.py --input inputs`。

重查四局规则差分：

```bash
python3 evaluation/check_sim.py evaluation/results/entry_full/*.json.gz
```

完整包中的 `inputs/` 和探索 `variants/` 保留历史原版，可能包含原版未启用的学习排序器；它们只用于复现对照，不属于提交依赖。**提交包只有本次禁用模型后的 `agent/` 文件。**

原始 160 盘记录在 `evaluation/results/baseline.jsonl` 与 `evaluation/results/r13_final.jsonl`；逐日记录、四局完整状态流、验证凭据、实验明细和 CSV 汇总一并提供。
