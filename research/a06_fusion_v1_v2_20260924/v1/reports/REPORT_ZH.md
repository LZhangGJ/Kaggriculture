## 3. 最终仅保留的改动

原模型把单个田间项目的正向产出计在产出日。R14将这些正向流量按“50%当日、50%次日”的确定性预期分配，以降低对当天全部变现的乐观程度。该比例是本轮实验采用的启发式近似，**不是对未来真实回仓时间的精确预测，也不是训练所得模型**。

- 负向投入流、投资成本和劳动仍保留在原来的物理日期，不推迟成本。
- 使用原始流量快照统一迁移，避免同一批货在循环中重复顺延。
- 最后一天的流量不再顺延出游戏边界；原有终局执行器保持不变。这不等于证明所有田间资产都可终局变现。
- 当前仓库、背包库存由原组合代码单独加入，不进入这个单项目延迟函数。

A06的产业选择、任务生成、现实状态校验和执行器保留；R13的公开成熟商品出售层保留。运行配置为 `delivery_calendar=0.5`。本轮试过的肥料删减开关在候选中为 `r14_fert_floor=0`，不启用。新开局、重排班、原生出售插队、长周期推演等失败实验不在最终执行配置中启用。

`learned_value.hpp`中 `available=false`，负数scenario被拒绝。没有模型权重、RL策略、对手程序调用或逐步动作回放。测试种子只交给裁判，清除后才向Agent提供配置。

## 6. 败局审计与解释边界

审计局：R13，对手5，种子2026092401，座位0，终局109,033对118,443，分差−9,410；与上轮同局动作哈希一致。该局非日末地块动作检查未发现己方“地块状态完全不变”的操作；这只是一个有限检查，不是全体动作合法性证明。

按冻结裁判逐步重放并对DROP/日末自动入仓做库存守恒检查，该局己方发现3单位MILK溢出，对手发现多类溢出。这个单局观察不足以把所有败局归因于仓容；也不能证明执行器没有其他问题。审计脚本、完整观察/动作轨迹和库存损失日志均在完整实验包。

另一个与种子差异有关的机制：冻结官方规则中，日末先用同一个日随机数生成器遍历空地生成杂草，再抽取新商店。空地数量/位置变化会改变随机数的消耗。因此**相同种子不保证不同策略面对完全相同的后续商店序列**。具体例子：上述对手5/种子/座位，R13第3天首店为BRUNCH_SPOT，R14为YARN_STORE。配对结果仍是合法对战结果，但不能把分差变化全部解释成“面对完全相同市场时纯收益提升”。见冻结规则 `_end_of_day`、`_spawn_weeds` 以及两份日记。

目前最明确的实验结论是：增加推演长度或排班复杂度，并未自动带来多种子稳健收益；本轮尚未把经济价值预测、实际经营和市场响应之间的误差可靠解决。

## 8. 复跑

完整实验包解压进入根目录后：

```bash
python evaluation/benchmark.py \
  --candidate A06_R14_CASHFLOW/main.py \
  --variant R14_REPRO --panel acceptance --workers 4 \
  --out repro/r14 --diary
```

该命令运行固定十对手160盘，不包含平台超时认证。重编译候选：

```bash
cd A06_R14_CASHFLOW
python build.py --cxx g++-14 --unit
```

重编译会产生新库，仍需重复轨迹一致性检查。`RELEASE_MANIFEST.json`记录交付文件及配置；原始编译凭据记录编译时输入。运行配置在加载时读取，不在库中固化。
