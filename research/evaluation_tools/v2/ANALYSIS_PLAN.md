# Evaluation tools v2: fixed analysis

This version leaves the original six-candidate evaluation and its published bundle unchanged. It is an opt-in runner for new experiments. Freeze all inputs before running its preflight. Every runtime, seed manifest, opponent list, reference feature file, threshold, analysis file and relevant audit file contributes to that freeze. Run and resume checks also bind the exact job list, environment, timeout and preflight receipts. Analysis checks those same records before using results.

Preflight selects the first two representative seeds in manifest order and the stress seeds with the minimum and maximum `ref_milk_minus_wool`; numerical seed order breaks ties. These stress labels remain conditional on PASS/PASS. Cross all four seeds with every frozen candidate, every opponent and both seats. Require all 719 transitions, 1,440 observation comparisons per parity game, matching actions and terminal outcomes across native/official execution, and package/adapter agreement where applicable. Preflight games never enter strength estimates.

Keep the original 16 opponents as the primary pool. Add the five existing AFS R2 stress profiles as a separate diagnostic pool: crop producer, livestock producer, cash maximizer, delayed seller and aggressive expander. These are related parameter variants, not five independent strategy families. Never add diagnostic wins to the primary score. Report each opponent, each seat, source groups and a descriptive mean giving each source group equal weight. Unclassified opponents have separate report groups; their ancestry remains unverified. This suite does not establish performance against Majkel's private policy or unseen leaderboard opponents.

Report representative, stress and any newly released holdout separately. Strict wins divided by scheduled games remain primary. Report draws and losses, plus `(wins + 0.5*draws)/games` as a labeled secondary point estimate. Missing, duplicate, invalid or unexpected cases block analysis. Preserve errors and use a documented new version for repairs.

Use 4,000 common seed-cluster bootstrap resamples per panel, with key `kaggriculture-seed-contract-v2-bootstrap`. Keep all opponent/seat cases for each seed together. Preserve percentile intervals and paired differences against frozen reference candidates. For overall primary rates, also report approximate simultaneous intervals for every candidate pair within that panel: center each bootstrap pairwise difference at its observed difference, take the maximum absolute error across pairs for each resample, and use its 95th percentile as the common half-width. This adjustment covers the declared pairwise family within one panel; it does not cover all opponent/condition slices or repeated development runs. Do not automatically promote the highest score. Stress intervals describe the selected stress panel.

Preserve the existing reference-condition definitions and 180 pre-action market samples. Condition comparisons and realized-market summaries use the primary pool. Actual market groups remain descriptive and action-dependent. Additional diagnostics remain separate from these summaries. Flag fewer than 20 distinct seeds and empty groups.

The original holdout remains reserved for the original frozen roster. A v2 holdout release requires its completed original comparison receipt, the exact retired original seed manifest, a new 256-seed manifest, and a fresh campaign audit after the v2 freeze, including NPZ and remote registry checks. Reject overlaps with the retired holdout, all development sets, the entire stress pool and audited history. Bind the release to one freeze and claim one output run; resume may continue that same run. Retire the new holdout after feedback. This is procedural separation, not cryptographic secrecy. Complete historical exclusion coverage remains the custodian's responsibility.

The 180-second per-game CPU timeout is not a hosted action-time certificate. Test the packaged candidate under the competition's runtime limits before submission. V2 preflight measures the same policy latency field as the original runner and labels it as local diagnostic evidence.
