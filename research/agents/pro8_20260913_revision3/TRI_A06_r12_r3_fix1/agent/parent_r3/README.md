# TRI_A06_r12_r3 — approved recurring-crop maintenance supply

**Full engineering candidate, not an accepted >85% agent.** This package actually
builds and runs the A06 calendar-r12 lineage. The only parent is the centrally
tested r2 native `638626de9398f0aed45e98394742ee22df875dd805f2647dee6d5666eb1c7755`.
The other same-named r2 (`bd0c7dd…`) in the conversation was neither substituted
nor borrowed. `parent/` is a byte-identical, read-only copy of all 51 supplied
parent files. `IDENTITY.json` binds both original input archives and the parent.

The submission is **root `main.py:agent`**, loading **`policy/a06.so`**. Nothing
under `parent/`, `research/`, `feedback/`, or `logs/` is loaded by production.
The production configuration and compiler flags are unchanged. Rebuild offline
with `python -B build.py`; build and run the three supplied source-test suites
with `python -B build.py --unit`. See `BUILD.md` for actual commands and ABI.

## One structural change

At R2 case `1827852203`, day20/step480, the exact parent selected 22 fertilizer
requirements with only 13 units in the shed. The preparation path's `day < 15`
purchase condition omitted the nine-unit shortfall. `reserve()` then degraded
selected FERTILIZE+WATER jobs, while watering remained. This is **not** a claim
that all fertilizer purchasing after day15 was prohibited: existing recovery
can still purchase and collect inputs. The source instrumentation reproduces all
2,876 supplied parent actions and exposes selection, raw jobs and reservation.
See `provenance/maintenance_evidence.json` and `logs/audit_*.json`.

R3 supplies only an already-selected, due, incumbent strawberry/tomato service
lost to actual fertilizer reservation, on days15–28. It does not turn every
missing bonus into an obligation or force economically rejected maintenance.
Existing service valuation, wages, item-price limits, cash/stock reservation,
capacity, route assignment, public supply assumptions and calendar DP remain.
The earlier end-season wheat/carrot planting fix and r2 survival wage ordering
remain intact and are explicitly tested.

Before keeping additional procurement, the controller compares copied,
current-day execution of parent preparation and supplied preparation. Existing
collection/recovery that already fulfils all selected maintenance suppresses
the extra purchase. Otherwise, supplied preparation must actually achieve at
least one additional selected FERTILIZE+WATER service, without losing any selected
service the parent preparation achieves. Buying fertilizer alone is insufficient:
pickup, travel, valid use and watering must finish in the remaining day. The
comparison is a **conditional feasibility screen**, not income, a perfect
opponent model or actual future state. It uses an idle synthetic counterpart
and no external private inventory or saved future. Exceptions fail closed to
parent preparation. Live investment and recovery remain enabled.

## Limitations and acceptance

The central parent progress file contains an **incomplete** snapshot:917 games,
647 wins,270 nonwins; its best possible final count is1266/1536. It is not a
completed parent win rate. No later full-panel supplement was received here.
All917 rows and every exposed/used development seed are retained. Earlier rounds
use different seeds; historical rate differences are not an ablation.

The candidate has **zero completed games against the central fixed12-opponent
panel**. The actual mini-panel did not show improvement. The preparation screen
is deliberately narrow and does not repair rejected service valuations, forecast
market absorption, all portfolio effects or every public loss. The horizon-local
screen can have downstream investment/sales effects, and both narrow wins remain
at risk. Acceptance still requires the central new shared64-seed,12-opponent,
both-seat panel: **at least1,306 strict wins out of1,536**; draws do not count.
This package is delivered for that independent test, not labelled a success.
