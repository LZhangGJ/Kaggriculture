# 联合训练与独立种子对局验收

目标：完整固定对手池的纯胜率 ≥65%，胜率 = 胜局 / 全部对局，平局不算胜。完整验收为 15 个对手 × 2 个座位 × 每座位 16 局 = 480 局，需要至少 312 胜、零运行错误。这里要求对手池平均胜率，不是每个对手分别达到 65%。

## 模型与训练

从 `local_teacher_bc_20260917/runs/bc_joint_exact_001/best.pt` 冻结初始化。历史结果只用于选择初始化，不能替代本轮新种子验收。

使用共享 Transformer 编码器（宽度 128、3 层、4 个注意力头），同时训练单位动作类型/数量，以及市场动作序列骨架/数量。输入是当前可见棋盘、单位、公共与自己的私有资源、精确整数特征、自己上一轮实际动作。市场模块不接收教师给出的当前单位动作。模型在对局中不调用教师策略。

全部参数联合微调 1,500 步，批量 64，峰值学习率 1e-5；保存第 500、1,500 步作为候选。在约 20% 的训练样本中用模型预测替代上一轮动作历史，降低对完美历史的依赖。当前观测和训练标签仍来自原教师数据；这属于历史扰动训练，不是重新采样并标注的 on-policy DAgger。

训练自检覆盖：预测不依赖当前目标标签、历史动作编码一致、共享编码器和两类动作头均有有限非零梯度。验证损失用于安排候选顺序；最终好坏由完整对局结果判断。

## 种子与选择

`PLAN.json` 在训练开始前固定全部比赛。`SEED_AUDIT.json` 记录 180 份历史协议/数据清单的路径和哈希，保守排除了其中 12,289 个正整数。720 个新对局种子全部唯一，且与排除集合无交集。

- 两组候选开发测试各 120 局：每个对手每个座位 4 个独立种子。两个候选也不共用种子。
- 最终测试 480 局：每个对手每个座位 16 个独立种子，与开发测试、历史训练和已登记对局种子均无重叠。
- 从验证损失较低的已微调候选开始测试；首个开发纯胜率达到 65% 的候选冻结为 `selected.pt`，随后才运行最终测试。
- 最终种子用 `FINAL_RESERVATION.json` 绑定模型哈希，不能再用同一批最终种子尝试另一个模型。若未达标，需要继续训练并登记新的最终测试种子。
- 每场比赛的环境种子仅供裁判初始化，不进入模型观测；双方只能获得各自可见观测。

## 运行与限制

`pipeline.py` 依次调用 `train.py`、候选开发比赛、最终比赛。`PIPELINE.json` 记录整体进度，`run/STATUS.json` 记录训练进度，`evaluation/*/SUMMARY.json` 是胜率结果的权威来源。不另做赛后回放扫描来重新计算胜率。

实际运行目录：`F:/Kaggriculture/experiments/joint_win65_20260918`。`main.py` 是独立学生入口，加载本目录 `selected.pt`，使用本地 CUDA FP32 单样本推理，与本轮对局后端保持一致。历史动作中的原子播种取消仅用于和训练数据一致的历史编码，不修改实际提交动作。

对局使用固定官方规则解释器和 15 个冻结对手、两个独立裁判进程；本地运行器不实施比赛平台的超时或沙箱限制。本轮胜率不等同于通过平台 CPU/时限验收。

CPU 使用 Windows Job 原生硬限额约束本进程及子进程，并按全机负载动态限速：目标 55%，达到 60% 暂停新训练/推理，低于 55% 恢复。为用户的 70% 要求预留余量。其他程序仍可能使全机瞬时占用超过 70%，本实验不会停止无关应用。
